Research brief · November 2026

Agent Data Retrieval Brief

Latest findings, results and to-dos for an open-source toolkit that compiles unstructured documents and tools into an agent-retrievable data lake, with graph and schema engineering.

garytang32/agent-data-retrievalBranch claude/magical-lamport-n94rs3Research complete · no code yetStatus as of November 2026

Key points
  • Compile once, serve every agent exactly. The toolkit should be an open agent context compiler: three stores (raw evidence, a typed snapshot-pinned database, searchable knowledge units plus tool records) on one spine of stable IDs, source spans, ACLs and validity fields, reached through tiered tools over MCP.
  • Structure moved outcomes more than models did. A 4 KB semantic document added 17–23 points; typed field definitions mattered more than the model family; parameterized tools scored 0.939 vs 0.666 for raw SQL on 3B–8B models.
  • Mainstream agents rent an index and read. Independent audits find only 39–77% of their cited claims supported and citation overlap below 0.02 Jaccard across identical runs, so the toolkit should be the exact, citable backend they call, not a rival search loop.
  • Theorems certify the store, not the ranker. Keeping raw evidence, pinning snapshots and version-keyed calibration rest on published results; fusion weights, chunk sizes and loop budgets must be tuned on each team's golden set. Nine earlier defaults were corrected.
  • Status. Five reports, a combined summary and two methods catalogs are done; about 2,567 distinct sources are catalogued. No toolkit code exists and all seven roadmap phases are not started.

Recommendation: start with Phase 0 (golden set, flat hybrid baseline, repeated-run harness), then write record spec v0.1, and aim the first public result at the unpublished experiment: one research agent over raw documents vs the compiled lake (Part 3).

Key terms
Agent context compiler
The proposed toolkit: it turns documents, data and tool catalogs into stores agents query, instead of being a parser, vector database or chat app.
Spine
The fields every store shares: stable IDs, source spans, access-control lists (ACLs) and validity/version fields.
Snapshot pinning
Publishing the database as immutable, tagged snapshots (Iceberg or DuckLake) so the same query returns identical rows.
Knowledge unit
A typed searchable record: concept, topic page, rule card, procedure, article/FAQ or table record, inside one shared envelope.
Rule card
A unit holding a rule's modality, conditions, thresholds, exceptions and dates, plus optional executable bindings (Cedar, Rego, DMN or ASP).
Span grounding
Storing each extracted value with the document span it came from, and re-slicing that span in code to check the quote.
MCP
Model Context Protocol, the tool interface agents use; the 2026-07-28 spec is stateless-first with explicit handles.
BM25F
Lexical ranking that weights fields (title, breadcrumb, identifiers, body) before term saturation.
RRF
Reciprocal rank fusion, a common way to merge ranked lists; the theory report finds no optimality result for its k=60 default.
Conformal risk control
A statistical method to set auto-accept thresholds with a stated error guarantee; valid only for the extractor version it was calibrated on.
Golden set
A vetted set of questions, documents and expected answers used to tune and gate every change.
pass^k
The share of tasks an agent passes on all k repeated attempts; a reliability measure.
Data processing inequality
The theorem that no processing step (chunker, extractor, summarizer) can add information about the source.
[P] / [S] / [I]
Theory labels: published theorem, the theory report's own sketch, and inferred mapping from a theorem to a toolkit method.

1.1The bottom line

What to build
An open, Apache-2.0 agent context compiler: not a parser, vector database, graph database or chat app.
Shape
Three stores on one spine: immutable raw evidence; a typed, snapshot-pinned database filled once by an LLM at ingestion; and searchable typed knowledge units with tool records beside them.
Access
Tiered: parameterized tools and a semantic layer first, guarded read-only SQL/Cypher second, hybrid lexical-plus-dense search third, labelled raw-text fallback last. Gating rules run outside the agent.
Why
Models cannot supply determinism (accuracy varies up to 15% across "deterministic" runs); materialized extraction beat chunk RAG 50.9 vs 6.0 recall on intersections; stale or conflicting content, not weak retrieval, causes most policy failures.
Positioning
The exact, citable, permission-aware backend that Codex, Claude Code, Cursor and deep research products call, not a competitor to their search loop.
Open ground
Engine-neutral record format · versioned grounded extraction · cost-bounded incremental graphs · tools stored as data · end-to-end ACL sync · neutral evaluation harness.
Bottom line
The durable asset is the versioned contract, not the model: extractors, embedders and vendors will be swapped within about two years.

1.2Architecture and what goes where

Each earlier report designed one part. Together they divide the work by question type: exact questions go to the typed database, open questions to knowledge units, provenance to raw evidence.

Store 1Raw evidence

Immutable, content-addressed: doc_id = sha256(bytes), a DoclingDocument-compatible tree with page, bbox, char span, parser revision and confidence. Theory makes it non-negotiable.

Store 2Typed database

FieldValue rows with (doc_id, page, char_start, char_end, spec_id), validation status and extractor fingerprint; entities, aliases, bitemporal statements; published as Iceberg or DuckLake snapshots.

Store 3Knowledge units

One envelope (identity, provenance, applicability, governance, access, hashes) around concepts, topic pages, rule cards, procedures, articles and table records.

Beside themTool records

JSON schema, expanded description, examples, side effects, auth scope and "writes entity Y" edges under the same ACLs. No surveyed project stores tools next to documents.

1.4What the theory proves, bounds and corrects

Rows about what to store and how to gate it rest mostly on published theorems the toolkit can make true by construction. Rows about how to rank and how much to read rest on bounds and empirical laws.

TheoremsCertify the store

Keep raw evidence (data processing inequality); external typed store for long-tail facts (monofact and B-bit bounds); normalized schema; frozen extractions and total ordering; provenance polynomials; SHA-256 and MinHash; conformal review; certain answers for conflicts; filter, never down-rank, superseded content.

Bounds and empirical lawsGuide the access layer

Keep the lexical channel; BM25F; summaries as navigation only; query-time compression; short loops with verifiers first; small index plus read(range); structure-led chunking; Zipf and Heaps refitted per corpus.

NothingTune or measure

RRF with k=60; 256–512-token chunk size; MMR; one-level progressive disclosure; SECI-style tacit-knowledge capture. Empirical defaults only.

Open gaps the toolkit can own

Engine-neutral record format

Every engine keeps its own state; proprietary intermediate schemas are where lock-in sits.

Versioned, grounded extraction

No surveyed library treats an extraction run as a versioned, diffable entity.

Cost-bounded incremental graphs

Community restructuring drives update cost; LightRAG builds reach 757M tokens.

Tools as data

Tool registries (SCOUT, MCP gateways) sit apart from documents and entities.

End-to-end ACL sync

No permissive open implementation for Confluence, SharePoint, Drive and Slack.

Neutral evaluation harness

Every vendor benchmark ranks its author first.

Two uncertainties shape the bet: demand for an open agent data format is inferred, not measured; hyperscalers bundling "good enough" pipelines are the main adoption risk, so exporters into their platforms are a survival feature.

3.4Consolidated defaults and defaults to avoid

Default
  • Truth: raw bytes and the canonical tree; chunks, records, pages, embeddings and file trees are regenerable views
  • Parsing: Docling text-layer path for born-digital; PaddleOCR-VL for scans; images for invoices and receipts; frontier models only for multi-page tables and validation failures
  • Extraction: native structure → synthesized code → encoders → constrained LLM with evidence-first fields; explicit null reasons
  • Validation: deterministic checks first; span re-slice; disagreement as routing; version-keyed conformal risk control; humans on rejected fields only
  • Identity and versioning: SHA-256 content IDs; Merkle-root snapshot IDs; full extractor fingerprint on every row; no floating model aliases; write-audit-publish branches
  • Chunking and enrichment: heading-first, atomic tables/steps/FAQ pairs, size tuned, no overlap; breadcrumb prefix always; LLM context only if it wins
  • Retrieval: BM25F + dense + domain-validated reranker; tuned linear fusion; hard pre-filters on ACL, status and validity; greedy coverage for final context
  • Access and loop: small stable tool surface; parameterized tools first; inline paginated results; decompose first; rate-based stopping with a hard cap; abstain with a gap report
  • Governance: filter superseded content; authority tiers; signed sources; quarantine and spotlight external text; immutable retrieval log
Avoid
  • Markdown as stored truth; semantic, LLM or late chunking by default; chunk overlapLoses boxes and provenance; independent studies favour structure
  • Query-time LLM operators as the system of record; "temperature 0 is deterministic"Variance and cost on every query (SemBench)
  • Free text-to-SQL or text-to-Cypher as the primary interface; raw SQL MCP serversBEAVER 10.8%; injection risk
  • RAPTOR or GraphRAG as the backbone; open-predicate graphs for exact queriesIndependent losses; untyped edges
  • Propositions as the primary index; vector-only retrievalLIMIT and keyword-query failures

  • Same-model self-consistency votes; one conformal threshold across versions; Bloom filters as dedupCorrections 4, 5 and 9
  • Dozens of per-source tools; multi-level skill hierarchies; large always-loaded instruction files; results as files0.913 → 0.640; 90.1% stale obedience; 93.1 → 55.2

Conclusion

The research moved the problem from models to contracts. A 4 KB semantic document mattered more than switching frontier models, typed field definitions more than the extractor, validity filters more than better rankers, and the harness as much as the retriever. Guarantees attach to what the toolkit can fix by construction: retained sources, pinned snapshots, fixed hashes and version-keyed calibration. Ranking and reading parameters must be earned on a golden set.

The toolkit wins by being the layer everyone else lacks: exact typed answers, re-sliceable citations, permission columns, currency metadata and a neutral way to prove them. Research is complete and no code exists yet. The next move is Phase 0, and the first public result should be the unpublished experiment: one agent, one corpus, raw documents vs a compiled lake. If the lake wins on completeness, faithfulness and stability at comparable cost, the thesis holds; if not, the phase gates say which layer to cut.
