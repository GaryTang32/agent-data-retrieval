# Phase 4: Knowledge Units and Enforcement — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Typed knowledge units (concepts, rule cards with citation closure, procedures with
SKILL.md and Mermaid renderings, FAQ/KCS articles, table records) served by four new read tools
and measured on new rule and procedure gold (4A); executable rule bindings checked by tests,
Z3 and a recorded review, enforced by an out-of-process gate with a hash-chained log, and
measured on a simulated drawbridge desk with and without the gate and a procedure runtime (4B).

**Architecture:** Units are write-once canonical JSONL overlay files per content snapshot,
listed in a hashed build manifest (the units id) that `units/HEAD` names and only the units
merge gate moves, exactly the Phase 3 table pattern. Each unit is built from one source
document and inherits its ACL and Phase 2 envelope; a separate per-view BM25F + dense unit
index serves `define`, `rule_lookup`, `procedure_lookup` and `unit_search` inside
`adr_store.tools.Tools`. Bindings are data in a typed three-valued DSL compiled by code from
grounded enrichment parameters; one decision function serves the gate process (allow tokens,
hash-chained log) and the advisory `check_rules` tool. The simulation runs three processes:
the agent loop (model calls), the environment (world, scripted user, procedure runtime, store
reads) and the gate.

**Tech Stack:** Python 3.12, standard library (`json`, `hmac`, `socket`, `sqlite3`), pydantic
2.14.3, the existing `adr_store`/`adr_eval` packages, `mcp==2.3.0` (`[mcp]` extra), pytest 9.2,
ruff 0.17. One new optional dependency: `z3-solver==5.3.3.0` as the `[analysis]` extra,
build-time only.

**Spec:** `docs/superpowers/specs/2026-11-21-phase4-design.md` (commit 9e9dd0f, rulings P1–P36;
P31–P36 made after the builder check). Section numbers (§) and rulings (P) below refer to it.
Read it first.

## Review Focus

1. **A rule id written another way.** An agent asks `rule_lookup(rule_id="§117.1081(a)(2)")`, `"33 CFR 117.1081 (a)(2)"`, `"117.1081(a)(2)"` or `"33 CFR 117.1081"`. Expected: the first three return the same card as `"33 CFR 117.1081(a)(2)"`, and the section form returns every card at or under the section. A malformed id gets the fixed unknown-rule message. Test in Task 8.
2. **A window boundary and clock words.** A request at 9:00 against "7 a.m. to 9 a.m.". Expected: allowed, because windows are half-open `[start, end)`. "Noon", "12 noon", "midnight", "12 midnight" and "12:01 a.m." parse to 720, 720, 0 or 1440, 0 or 1440 and 1. "11 p.m. to 6 a.m." crosses midnight. Test in Task 14.
3. **A federal holiday observed on another day, across a year end.** 2028-01-01 is a Saturday, so the holiday is observed on Friday 2027-12-31, and 2026-07-04 (a Saturday) is observed on Friday 2026-07-03. Expected: "Monday through Friday, except federal holidays" does not close on those Fridays. Test in Task 14.
4. **A handle saved before Phase 4** (no `units` key), or units built for an older content snapshot. Expected: the eight earlier tools work as before. The four unit tools refuse the handle with `NO_HANDLE_UNITS`, refuse stale units with `NO_UNITS`, and never fall back to HEAD. Test in Task 8.
5. **An agent tool call with malformed arguments**: `draw` as the string `"2"`, an `open_at` with a `Z` offset or no seconds, an unknown request id, or an extra argument. Expected: the environment refuses the call as malformed before the gate sees it. The refusal is logged under `adr.gate.fail-closed@1`, nothing executes and the trial goes on. Test in Task 19.

Layout (§5.2): `<store>/units/<snapshot>/<type>-v<version>-<id[:16]>.jsonl` (one canonical JSON
`Unit` per line, sorted by `unit_id`), `<…>.report.json` beside it (unhashed: counts, rejections
with problems, null reasons by field, grounding rates), `<store>/units/<snapshot>/units-<id[:16]>.json`
(the manifest; its SHA-256 is the units id) and `<store>/units/HEAD`.

Envelope values (§5.1): `status` is `superseded` when the document's Phase 2 envelope has
`superseded_by`, else `validated`. `effective_from` and `effective_to` are the envelope's
`valid_from` and `valid_to`. `chain` is `chain_id`. `jurisdiction` is the envelope's value
(`applicability.JURISDICTION`, "US-federal") for gov, and `governance.json`'s value for bench
("Redwood Inference"). `owner` is the issuer (eCFR agency, "Internal Revenue Service") or the
bench source system. `authority_tier` is 1 for the eCFR and the IRM, 2 for bench Confluence and
Drive, 3 for research markdown, and 4 for PDFs and bench chat, mail and tickets. `hashes.text`
is the SHA-256 of the normalised text. `hashes.meta` is the SHA-256 of the canonical JSON of
the envelope fields.

Rules (§6.1, §8; the ones the signatures leave open are the planner's calls, builder notes 5–7):
- **Marker paths:** level 1 `(a)`, level 2 `(1)`, level 3 roman `(i)`, level 4 `(A)`. A paragraph starting with several markers ("(a)(1)") takes them all. An ambiguous `i`/`v`/`x` is roman when the current path is at level 2 or deeper, unless it is the letter right after the current level-1 letter. A paragraph without a marker takes the last path plus `("p<n>",)`, with n counting unmarked paragraphs under that path from 1. The provision id is `"<title> CFR <section>" + "".join(f"({m})" for m in path)`.
- **Modality:** the leftmost match of any lexicon phrase (case-insensitive, word-bounded), longest at equal start. `modal_spans` hold every match. A paragraph with no match is a non-modal provision, not a card (P4).
- **Spans:** each `P` is located in the canonical text after the end of the previous one, as `ecfr_sections` locates sections, and re-sliced. A miss rejects the unit.
- **Cross-references:** the five forms of §8.3, plus a trailing paragraph path ("§ 117.31(b)"). "§§ A and B" gives two references. A target in the same part resolves when the version holds that section; otherwise it is `dangling`. Another part is `external`.
- **Closure, in this order:** `cites` gives the provisions at or under the target, up to `CITES_PER_REF`. A card gives its `unit_id`; a non-modal provision gives `unit_id` None and its span. `defines` is added by Task 3. `exception_of` follows `closure.json`: `{"part": "33 CFR 117", "subpart": "B", "targets": ["33 CFR 117.5", "33 CFR 117.31(b)"]}`. `context` gives the same section's non-modal provisions sharing a `draw_keys` key (33 CFR 117), or the section's nearest non-modal provisions up to `CONTEXT_MAX` (other parts). Entries are deduped, keeping the first.

## Builder notes: spec points resolved in this plan (planner's calls)

1. **"The Phase 3 validator is extended" (§5.2) without touching Phase 3's models.** `contract_sha256` hashes `Contract.model_dump()`, and every tables id includes it, so a new field on `Column` would move every tables id and break constraint 1 and X1. Unit contracts therefore get their own `UnitContract`/`UnitField`, which delegate scalar checks to the Phase 3 validator through a public alias. A test pins the 15 committed table contract hashes.
2. **`define` takes `include_superseded`.** §7 lists it and §11.2's table omits it. Both are honoured; the default is false.
3. **Non-modal provisions as closure targets (§6.1, §8.3).** They are not one of the five unit types (P4). A closure entry therefore carries `unit_id` None plus the provision's ref and span, and `rule_lookup` returns its text by re-slicing. It is always in the card's own document, so it shares the card's visibility.
4. **One Phase 4 seed.** The spec fixes no Phase 4 seed beyond the bootstrap and `assign_split` (20261108). `SEED4 = 20261121` is used for every other draw.
5. **Modality "first match"** is read as the leftmost match in the paragraph, longest at equal start. Table order alone would let "need not" outrank an earlier "shall", and leftmost-longest also puts "shall not" ahead of "shall".
6. **Marker paths and unmarked paragraphs.** An unmarked paragraph gets the last path plus `p<n>`. A `rule_id` naming a section or a paragraph returns every card at or under it, so "33 CFR 117.5" finds "33 CFR 117.5(p1)".
7. **Closure caps.** A section-level citation can reach many provisions; it is capped at 5 per reference, in document order. The `context` relation outside 33 CFR 117 (where no mile key exists) takes the section's nearest non-modal provisions, at most 3.
8. **First promotion.** §6.6 makes every promotion go through the gate, but the rule and procedure gold only exist after Task 13. Task 6 lets the first promotion of a store (no HEAD) run with no cases; with a HEAD, cases are required. Task 12 wires the gold kinds.
9. **The gate's I/O deadline is a clock input.** Constraint 3 names the ACL freshness check as the only clock input. A gate that does not answer must still fail closed (P15), which needs a deadline. It is 30 s, it can only deny, and a run in which it fired is reported and not used for T2.
10. **BM25F is field repetition** with integer weights from {1, 2, 3}, as Phase 1's breadcrumb weighting. No new BM25 code is written.
11. **The 2,000-token cut (P20).** Pieces are taken in rank order (a hit, then its closure). The piece that crosses the budget keeps its longest fitting prefix, and its span shrinks to match. Pieces are verbatim spans, so a prefix maps to a span exactly.
12. **`p2-default-scoped`** restricts `p2-default`'s ranking at depth `DEPTH` = `CHANNEL_K` (100) to in-scope chunks (preflight C12: `Tools.search` refuses a depth above `CHANNEL_K`, and no code path ranks 1,000 chunks). `run_p4` calls `system.searcher.search(q, top=CHANNEL_K, filters=system.filters_for(as_of), dedup=system.spec.dedup)` for `p2-default` and `p2-default-scoped`; `p4-units` asks `rule_lookup`/`procedure_lookup` for as many hits as the tools allow (100), enough to reach the 2,000-token budget; Recall@10, MRR and Hit@k read the first ranks. Corpus-wide BM25 statistics stay. A procedure-candidate scope is below document level, so a store restricted by document cannot express it.
13. **§ 117.5's basis can be vacuous.** "Basis for every draw with no specific rule covering the time" is `¬(p1 ∨ …)`, which can never fire when the specific periods cover all times, and §12.4 rejects vacuous bindings. It is emitted only when `covers_all` finds a gap. That check evaluates the windows at their critical points (every boundary minute and the minute before it, each weekday, holiday true and false, every date-range boundary day and the day before), where `in_window` is piecewise constant, so it is exact without Z3. A draw that is permanently "closed to navigation" compiles to an always-firing forbid, which §12.4 rejects as vacuous; such draws get no bindings and the gate escalates their calls.
14. **The B1 grid for draws without a notice threshold** uses notice in {none, 0, 48 h}. The spec's set needs an N.
15. **Holidays.** Both the legal date and the observed date (Saturday → Friday, Sunday → Monday) count as `federal_holiday`. Inauguration Day (5 U.S.C. 6103(c)) is excluded, because it applies only in the Washington area. The fact module is shared by the gate and the reference evaluator; it holds no rule parameter, so the reference stays independent of the bindings.
16. **"At most 32" review calls against 53 enriched sections.** Bindings come only from the 30 pool sections and from §§ 117.5 and 117.31 (§12.2). § 117.40 and the other subpart A sections enrich cards but compile no binding, so review needs at most 30 + 2 = 32 calls. **Amended after Task 17 (controller ruling):** the § 117.5 and § 117.31(b) bindings are not reviewed in calls of their own. Each draw's general-duty and emergency bindings go in the call of the section the draw belongs to, beside its other bindings, and every section message quotes the § 117.5 and § 117.31(b) cards verbatim. A single § 117.31 call would carry 40–60 emergency bindings, and its truncation at `max_tokens` 2000 would reject every draw under P48. Calls are therefore at most the number of pool sections with bindings, at most 30. A reply still unparseable after the retry at repeat 1 rejects the section's draws with reason `review_unparseable`, and the report counts them (sections, draws, bindings, and replies whose output reached `max_tokens`).
17. **`bindings/HEAD`.** The spec gives bindings a manifest and id but no promotion rule. `adr bindings promote` moves `bindings/HEAD` only when every binding verifies and is signed off (B3). No flip gate applies: the simulation is the measure.
18. **An unparseable agent reply** is a turn with no action, and it uses one of the three calls. No repeat-index retry is made inside a trial, so a replay stays exact and the budget stays bounded.
19. **Runtime arm against `config/runtime.json`.** A4 requires a disabled profile to run without the runtime, but the gate-runtime arm must measure the runtime in order to set the flag. The arm forces the runtime on for measurement; every other use reads the flag. The discipline check writes the flag from the two arms' pass^1.
20. **The HMAC key** is generated in the environment process (`secrets.token_bytes(32)`) and handed to the gate over an inherited pipe. Neither tokens nor the key are logged. Transcripts and logs therefore replay byte-identically (T2) even though the key differs per run.
21. **Jurisdiction values.** gov units carry the Phase 2 envelope's "US-federal", so the jurisdiction filter means the same on units and chunks. Bench units carry "Redwood Inference" from `config/units/governance.json`.
22. **One compile command over several stores.** §16 gives `units compile --procedures` and `golden procedures --gen` one share each across gov and bench, so both commands take a repeatable `--store` under one budget.
23. **Table records** are made for the FR, drawbridge and manifest tables. They are not made for entity tables, whose rows span documents, so a record over them would need several documents' access (P31).
24. **Canary arithmetic.** Each canary runs with a small `--max-calls` (3 calls plus 3 retries, 12 for the three-arm simulation canary, 4 for review and the runtime canary). The full run gets the share minus the units the canary used, so each command's total stays within its share.
25. **The 150 fail-closed probes are staged.** §15.4 counts five tools, but `check_rules` only exists from Task 18, and it is 4B code. Task 9 runs the 120 probes over the four read tools. Task 22 runs the full 150 once `check_rules` and `bindings/HEAD` exist.
26. **P36 without touching the Phase 2 runner.** `runner._takes_as_of` passes `as_of` only on `policy_asof` items, and changing it would change Phase 2 runs (constraint 2). The Phase 4 harness (`phase4.run_p4`) calls `P2System.retrieve(q, as_of=item.as_of)` itself for every rule item. A test pins `_takes_as_of` as it is.
