# Phase 3: The Typed Deterministic Database — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Typed tables loaded from corpus metadata (3A) and extracted from 33 CFR 117 with
verbatim, code-checked quotes (3B), queried through `describe_tables`, `query_table` and
guarded `sql` under the Phase 2 ACL, applicability filters and handles, and measured (Q1, Q2,
E1, E2, T1–T6, S1–S3, D1, X1).

**Architecture:** Tables are write-once canonical JSONL overlay files per content snapshot,
listed in a hashed build manifest (the tables id) that `tables/HEAD` names and only the merge
gate moves. Each call loads the caller's visible, applicability-admitted rows into an
in-memory SQLite database (cached per tables id and admitted documents) and compiles
`query_table` arguments to one parameterised statement with `golden/records.py` semantics;
`sql` runs one guarded `SELECT` on the same database. 3B extraction runs once per distinct
section text through the existing `.cache/llm` cache, so rebuilds make no call.

**Tech Stack:** Python 3.12, standard-library `sqlite3` (3.53 here) and `json`, pydantic
2.14.3, the existing `adr_store`/`adr_eval` packages, `mcp==2.3.0` (the `[mcp]` extra),
pytest 9.2, ruff 0.17. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-20-phase3-design.md` (commit 457da3b). Section
numbers (§) below refer to it. Read it first.

## Global Constraints

- No model call outside §11: part 3A, every probe, every test and every rebuild make none; `--max-calls 0` proves it (constraints 4–5).
- **Task 11 runs only after the user approves the §11 budget.** Shares per command: extract 560, second pass 560, `golden tables` 140, query generation 125, baseline answers 100; total cap 1,485 of 1,500.
- Models: Sonnet `claude-sonnet-5-5` extracts and generates, Opus `claude-opus-5-5` runs the second pass, both through the Claude Code adapter; every call records the served model.
- The canonical text, Phase 1 records and Phase 2 overlays never change; no snapshot id, doc record, chunk id, index fingerprint or overlay id moves (constraint 1).
- The five Phase 2 tools return identical hits, counts and messages; their results gain only the handle key `tables` (constraint 2, §9.3).
- Determinism: same snapshot, contracts and cache → byte-identical table files and tables id; total orders everywhere; no wall-clock input except the Phase 2 ACL freshness check (constraint 3).
- A value is stored as grounded only if its quote re-slices from the stored text at the recorded offsets (constraint 6).
- All Phase 3 builds and measurements use `.cache/store-p2/<corpus>`; `.cache/store/` and `.cache/index/` are read-only; use `--store`, never `--corpus`, in real-data checks.
- Tests never write the repo's `.cache/`, `data/` or `runs/`; every new default path is redirected in `tests/conftest.py::_isolate_writable_state` by the task that adds it.
- `pytest -q -W error` and `ruff check .` pass after every task.
- Committed: contracts, configs, schemas, summaries, counts, `golden/gov-tables/v0.1/` (public-domain gov text). Local only: run rows, probe outputs, research text and anything from bench.
- Limits: semantic layer ≤ 8 KB; categorical values listed only up to 25; `sql` results capped at 1,000 rows and flagged truncated.
- Thresholds fixed now (§12): Q1 ≥ 0.90 per corpus and gov above `baseline-linear` with McNemar p < 0.05; Q2 ≥ 0.80 and paired 95% lower bound > +0.02; E1 ≥ 95%; E2 ≥ 0.85 on `waterway`, `bridge`, `notice_hours`, `opens_on_signal`; T1–T6, S1–S3, D1, X1 as §12.
- Seeds: probes, the gov-tables drawer and entity samples `20261120`; `assign_split` and bootstrap `20261108`.

## Review Focus

1. **A filter value of the wrong type** (`{"year": "2020"}` from an agent): records semantics say it never matches, so a count of 0 looks like an answer. Expected: the count stays 0, and the result names the clause in `never_matches`. Test in Task 4.
2. **A `sql` statement ending in `;` or a `-- comment`**: wrapping it as `SELECT * FROM (<stmt>) ORDER BY …` breaks it, or the comment swallows the closing parenthesis. Expected: it runs. Test in Task 5.
3. **A handle saved before Phase 3** (no `tables` key) given to a table tool. Expected: it validates and works for the five Phase 2 tools; table tools refuse it explicitly and never fall back to HEAD. Test in Task 6.
4. **A caller who sees no rows** (`user:outsider`). Expected: `describe_tables` still lists every table, counts are 0, `list` is `[]`, `count_by` is `[]`, and `sql` aggregates run over empty tables. No error. Test in Task 6.
5. **Tables built for an older content snapshot** after a new ingest moves HEAD. Expected: table tools refuse with `NO_TABLES` naming `adr tables build` and never serve stale rows. Test in Task 6.

Layout (§5.2): `<store>/tables/<snapshot>/<table>-v<version>-<id[:16]>.jsonl` (id = SHA-256
of the file; one canonical JSON `RowRecord` per line, rows sorted by `sort_key` over
`c.order`), `<table>-v<version>-<id[:16]>.report.json` beside it (unhashed: counts,
rejections with reasons, null reasons by column), `<store>/tables/<snapshot>/tables-<id[:16]>.json`
(the manifest; its SHA-256 is the tables id) and `<store>/tables/HEAD` (the full tables id).
`manifest_path` globs `tables/*/tables-<id[:16]>.json` and checks the hash. `sort_key` is
SQLite's order so Python and SQL sort alike: NULL < numbers (bool as 0/1) < text (code-point
order = UTF-8 byte order); list columns compare by their stored canonical JSON text.

`build_tables` builds every contract of `corpus` whose loader is `metadata` (plus `entities`
from Task 3, and `extraction` when `with_extraction`, Task 9), including tables with zero rows.
It writes the table files and the manifest and never moves HEAD. It records the applicability

Rules (planner's calls, from the survey of `docket_ids`):
- **Dockets:** split each string on commas. A part matching `^(?:([A-Z]{2,3}) )?Docket (?:Nos?\.|Numbers?) ?\[?(.+)$` gives numbers (the rest, split on ` and `), each prefixed by the group's letters when present ("MB 17-317"). A following part with no "Docket" word that is a bare `\d{2}-\d+` keeps the previous prefix. Every other part goes to `other_ids` as written.
- **Authors:** split on `,`, strip each part, drop empty parts; a part equal to `et al` or `et al.` (case-insensitive) sets `et_al` and is not an author. `name_key` = the authors normalisation key (Task 3; until then `casefold`).
- **Missing fields:** null with reason `absent`. A CFR `part` that is not all digits leaves `part` null with reason `unparseable`, and `cfr_part` keeps the label. `status` comes from the applicability overlay, or is null `absent` without one.

**Semantics** (§5.4, reproducing `records.py`; the contract's column type decides
compatibility at compile time, and an incompatible clause compiles to `0` and is named in
`never`):

| Clause | Compiles to |
|---|---|
| `col` = v | `col = ?` for text/date ↔ str, int/real ↔ int/float (not bool), bool ↔ bool, list ↔ list (canonical JSON). Text equality is exact |
| `col__in` [..] | OR of the compatible elements' equalities; a non-list value never matches |
| `col__gte`/`__lte` | `col >= ?` / `<= ?` for numbers, text/date ↔ str and bools; NULL never matches; list columns never match |
| `col__contains` v | text/date: `instr(casefold(col), ?) > 0` with `str(v).casefold()`; lists: `EXISTS (SELECT 1 FROM json_each(col) WHERE casefold(value) = ?)`; other types never match |
| `col__ne` v | non-NULL, compatible and `col != ?` |
| `col__isnull` b | `col IS NULL` / `IS NOT NULL`; a non-bool value is a `QueryError` |
| `col__contains_any` [..] | OR of `__contains`; a non-list value is a `QueryError` |

An unknown table, column or operator, or an op outside `OPS`, is a `QueryError` naming it.
Exact copy: `unknown column 'yeer' in table fr_documents`, `unknown operator 'between' in
'year__between'`. Results by op:
- `count`: the number of rows;
- `list`: `sorted({str(v)})` of `list_column`;
- `lookup`: `rows` (`{"doc_id", "row", "prov"}`) in `order` (a `-` prefix descends), then contract order, at most `limit`, with `truncated` set when more match. `value` is `fields[0]` of the single matching row, else None (the records rule);
- `count_by`: needs one field; groups `[{"value", "count"}]` sorted by value, NULL first; a list column groups by element.

`from_gold_query` maps the corpus's `DEFAULT_TABLE`, drops `_`-prefixed keys, and turns
`_field` into `fields`. `gate` evaluates on a full-view database under default applicability,
on the candidate and on HEAD (no HEAD: every case wrong). It counts as a flip every case that
is right on HEAD and wrong on the candidate. It calls `_set_head(candidate)` only when
`len(flips) <= max_flips`. A count case is right when `count == int(expected)`; a list case
when the id sets are equal.

## Builder notes: spec points resolved in this plan (planner's calls)

1. **Gate in Task 4, not 3B.** The tools resolve tables through `tables/HEAD`, and HEAD moves only through the gate. 3A builds are promoted by gating on the v0.1 count_filter gold, where 0 flips are possible from no HEAD.
2. **Task 10 split from the gated run.** The golden generator and the tables-mode harness are stub-tested before approval; Task 11 only runs commands.
3. **`applicability=` argument.** `query_table` and `sql` take the Phase 2 filters as `applicability` (a `Filters` dict), because `filters` is the row predicate of §8.
4. **Types decide at compile time.** The contract's column type decides each clause; every type pair v0.1 uses reproduces `records.py`. Where Python alone would compare (bool vs int, list ordering), `query_table` never matches. `never_matches` names clauses whose value type cannot match, without changing any count.
5. **New operators:** `__ne` matches non-null, comparable and unequal values; `__isnull` takes a bool; `__contains_any` takes a list. Bad values for the last two are errors; for v0.1 operators, bad values never match (records semantics).
6. **`lookup` and `count_by`.** `lookup` returns rows with provenance plus `value` under the records rule. `count_by` sorts by value with NULL first; a list column groups per element. Contracts name a `list_column` for `list`.
7. **Total row order.** Rows are sorted in SQLite's order (NULL < numbers < text; lists by stored JSON), so Python and SQL sort alike.
8. **SQL order (§8.2).** A statement without a top-level `ORDER BY` is wrapped and ordered by every output column. One with an `ORDER BY` runs as written; its ties fall in engine order, which depends only on the per-view database (rows inserted in contract order), so it is deterministic and equal to a view-only store's. Parsing the `ORDER BY` terms to append tie-breakers was not attempted.
9. **The "too many rows" class** is a result over 2 MB after the 1,000-row cap; more than 1,000 rows is a truncation flag. Unknown tables and columns are the syntax class.
10. **Function whitelist.** Date and time functions are excluded because `'now'` reads the clock. Recursive CTEs are allowed and bounded by the VM-step budget, which implements "beyond a depth".
11. **`count_distinct`** in the semantic layer is given as an `sql` template; §8 lists no such `query_table` op.
12. **Entity tables.** Rows are per (entity, raw form, source table/column, document), so they filter per view. `display_name` is filled when the per-view database is built.
13. **Normalisation keys** per type, and override semantics: `merge` maps to the smallest key; `split` makes `<key>#n`.
14. **No link table.** A row drawn from two documents would need two documents' access. `fr_documents.title_state`/`title_waterway_keys` and `drawbridge_*.waterway_key` allow joins in `sql`, and the link report is committed.
15. **Docket and author parsing** rules are in Task 2. A bare "USCG-…" goes to `other_ids`.
16. **`drawbridge_bridges` repeats** the section's `state`, `waterway` and `waterway_key`, with the same provenance, so one `query_table` call can filter draws. `query_table` has no joins, and §10.3's own example question needs this.
17. **Nine model columns, one group.** §7.5 says "8 model columns"; §5.5 lists nine (`bridge` included). All nine go in one group.
18. **Failure caching** is opt-in per call, under `Cache.key("failure", key)`, so Phase 0/1 cache entries and behaviour are untouched.
19. **`adr tables build` never calls a model** (default `--max-calls 0`); `adr tables extract` does. Build needs `--corpus` and writes every contract of the corpus, even with zero rows, so view stores have the same table set.
20. **Yes/no lookups** are answer kind `id` (`"yes"`/`"no"`, variants `"true"`/`"false"`), since `AnswerKind` has no bool.
21. **`p3-typed` on v0.1** runs the generated op and filters whatever `store` says (as `exec_match` does), ignores the generated `as_of`, and uses default applicability, which admits every FR and manifest row.
22. **Seeds:** 20261120 for the Phase 3 probes, the drawer and the entity samples.
23. **Real-data tests** use a new `realdata` marker and skip when local data is absent.
24. **`Handle.tables` is optional.** `REQUIRED` keeps the bad-handle message byte-identical. The one Phase 2 test edit beyond key sets is the MCP tool count (5 → 8).
25. **Applicability probes** on the drawbridge tables need 3B, so they run in Task 11; Task 7 covers `fr_documents`.
26. **`sql` log lines** carry the statement's SHA-256 in `args`, never its text.
27. **`p3-typed` dev split.** The Q2 query share (125) also covers a dev-split `p3-typed` run (about 24 calls) for information.
