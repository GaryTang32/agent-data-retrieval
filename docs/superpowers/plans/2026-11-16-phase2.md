# Phase 2: Applicability, Permissions, Tools as Data and an MCP Server — Implementation Plan

Spec: `docs/superpowers/specs/2026-11-16-phase2-design.md` (commit 27511b0). Read it first;
section numbers below (§) refer to it. Work test-first. `pytest -q -W error` and `ruff check .`
must pass after every task. No model calls anywhere in Phase 2 (ruling R1). Tasks follow the
build order of §16: 2A (Tasks 1–5), 2B (Tasks 6–8), 2C (Tasks 9–11), 2D (Task 12), write-up
(Task 13). Each part ends with its criteria measured and written up before the next begins; a
failed criterion is reported as failed, with the component that caused it.

## Shared rules for every task

- **Phase 1 stays reproducible.** No Phase 1 snapshot id, doc record, chunk id or index
  fingerprint changes (constraint 1). The Phase 1 systems and commands keep their behaviour.
  The only permitted edits to Phase 1 tests are the expected *key sets* of tool results and
  logged `args` (e.g. `tests/store/test_tools.py` lines asserting `set(d) == {...}` and
  `idx["args"] == {...}`), extended by the new field names a task adds; no expected value
  changes. Each task lists those edits in its review notes. The Phase 0/1 recorded-rankings
  test (`tests/test_systems.py`, `baseline_rankings_mini.json`) is never edited.
- **Real stores are read-only.** `.cache/store/<corpus>` and `.cache/index/*` are only read
  (loading an index takes a shared `flock` on its existing lock file; that is all). Every
  real-data check runs on scratch copies under `.cache/store-p2/<corpus>`, made with
  `cp -a .cache/store/<c> .cache/store-p2/<c>` (Task 1) and checked by `HEAD` (gov
  `f002821f2cb3…`, research `97c415b1aa71…`, bench `7d8d1f8adda6…`). Never use `adr --corpus`
  in a real-data check: it targets `.cache/store/<c>`; pass `--store .cache/store-p2/<c>`.
  Clones of a p2 store for destructive probes (Task 8) are plain `cp -a` copies too: the
  retrieval log is appended in place, so hard links are not safe.
- **Tests never write the repo's `.cache/`, `data/` or `runs/`.** Every new default path
  (`p2_store_dir`, the tool store, probe output roots, `data/tools`) is redirected in
  `tests/conftest.py::_isolate_writable_state` in the task that adds it. Server subprocesses
  in tests get explicit `--store`/`--emb-cache` under `tmp_path` (conftest monkeypatching does
  not reach subprocesses). Tests use fake embedders, lexical-only indexes or fixtures; nothing
  reads `data/` or `.cache/` except tests marked `slow`.
- **Determinism** (constraint 3): sorted iteration, ties by id, no wall-clock input into any
  ranking, record or overlay id; the seeds are those of the spec (MinHash 20261116, probes
  20261116, bootstrap 20261108). The ACL freshness check (F3) is the only clock-dependent
  decision; it takes an injectable `clock`.
- **Overlays are write-once** like Phase 1 records: canonical JSON (sorted keys, compact,
  UTF-8, one trailing newline, as `records.canonical_json`), written with `store.write_atomic`;
  an existing file with other content under the same name is refused (`StoreError`).
- **Schemas.** Every new pydantic model whose JSON is stored (envelope overlay, dedup overlay,
  ACL directory, policy, snapshot, tool record, tool snapshot) gets a schema file in
  `src/adr_store/schema/`, produced by extending `records.schemas()` (lazy imports), so the
  existing stale-schema test covers them.
- **Module boundaries.** Toolkit code goes in `src/adr_store/`. The Phase 0/1 harness modules
  keep reaching `adr_store` only through `adr_eval.systems`; the new Phase 2 harness modules
  (`adr_eval/phase2.py`, `adr_eval/probes/`, `adr_eval/tools_eval.py`) may import `adr_store`
  directly (planner's call, see the builder notes).
- **Committed vs local results.** Run rows, probe sets, ToolRet data and anything quoting
  research or bench text stay local (`runs/`, `data/`), as in Phase 1. `results/phase2/`
  commits configs, summaries and counts only. Never edit the pinned research corpus files
  (`reports/*.md`, `research_notes/`, `papers/manifest.csv`; `tests/test_pinned_files.py`).
  `reports/agent-data-retrieval-status.html` is not pinned and may be updated in Task 13.

- Family by URI: eCFR `…/api/versioner/v1/full/<date>/title-<t>.xml?part=<p>` → chain
  `ecfr:<t>:<p>`; IRM `https://www.irs.gov/irm/part<N>/irm_<a>-<b>-<c>r` → chain
  `irm:<a>.<b>.<c>` (leading zeros dropped: `irm:5.19.1`); Federal Register
  `https://www.federalregister.gov/api/v1/documents/` → no chain, fields read from
  `json.loads(store.text(doc_id))`; anything else → every field `unknown`/null (research,
  bench, mini, loose files).
- eCFR: versions of a chain ordered by `source_version`; `valid_to` = the next version's date;
  `supersedes`/`superseded_by` the neighbours. `issuer` from the gov config's `parts[i].agency`
  through a fixed slug→name table (`coast-guard` → "Coast Guard",
  `federal-communications-commission` → "Federal Communications Commission"); IRM issuer
  "Internal Revenue Service"; FR issuer the most specific agency's `name`, chosen as
  `GovAdapter.records` chooses it.
- FR status rule, in order (planner's call, reproduces §4.1's counts): `type == "Proposed
  Rule"` → `proposed_rule` (tier 4); `action` matching `(?i)\b(notice|notification) of

  rule, `dates` matching `(?is)\beffective\b.*?\bfrom\b(.+?)\bthrough\b(.+?)(?:\.(?:\s|$)|;)`

  of `valid_to` recorded in `provenance` as `fr.dates` with the matched range); a failure
  leaves `valid_to` null and is listed in the report.
- The report (`<store>/applicability/<snapshot>/envelope-1.report.json`, not part of the
  overlay id; also printed): counts by family, status, basis and tier; chains and links; the FR
  `dates` parse failures by doc id; the two caveats of §4.3 as text.
- `adr applicability derive [--store S] [--gov-config F]` (default `corpora/gov/config.json`)
  writes the overlay for HEAD; deriving again is a no-op; a differing file is refused.
- Layout: `<store>/applicability/<snapshot_id>/envelope-1.json`.

**Files:** `src/adr_store/dedup.py`, `src/adr_store/tools.py`, `src/adr_store/cli.py` (`adr

Build (§4.5):

```python
PARAMS = {"exact": "sha256(text)", "tokens": r"\w+", "lower": True, "shingle": 5,
          "num_perm": 128, "prime": 4294967311, "seed": 20261116,
          "a_range": [1, 2**32], "b_range": [0, 2**32], "bands": 16, "rows": 8,
          "threshold": 0.90}
def shingles(text: str) -> frozenset[str]   # " ".join of 5 consecutive tokens; < 5 tokens:
                                            # one shingle of all tokens ("" for none)
def minhash(sh: frozenset[str]) -> np.ndarray   # uint64[128]
def jaccard(a: frozenset[str], b: frozenset[str]) -> float

class Cluster(BaseModel):
    cluster_id: str                # SHA-256 of the sorted member ids joined by "\n"
    members: list[str]             # chunk ids, sorted
    kind: Literal["exact", "near"] # exact iff every member has the same text SHA-256
    min_jaccard: float             # minimum over the cluster's edges, 6 decimals
    edges: list[tuple[int, int, float]]   # member indices and Jaccard of every qualifying pair:
                                          # exact pairs (1.0) and verified near pairs (>= 0.90)
class DedupOverlay(BaseModel):
    format_version: Literal["0.1"]; snapshot: str; chunker: dict
    chunk_content_sha256: str      # of the chunks it was built over; checked on load
    params: dict; clusters: list[Cluster]; stats: dict

def build(chunks: list[StoreChunk], snapshot: str, chunker: dict) -> DedupOverlay
def overlay_key(chunker: dict, params: dict) -> str   # SHA-256(canonical {chunker, params})[:16]
def write_overlay(store_path, overlay) -> tuple[str, Path]    # id = SHA-256 of the file
def load_overlay(store_path, snapshot, chunker, chunk_content_sha256,
                 overlay_id=None) -> Dedup | None
class Dedup:
    overlay_id: str
    def components(self, cluster_id: str, admitted: Callable[[str], bool]) -> list[list[str]]
        # connected components of the cluster's edges restricted to admitted members
def canonical(members: list[str], chunks, applicability, as_of) -> str   # §4.5 rules 1-4
def collapse(ranked: Hits, dedup, admitted, chunks, applicability, as_of, top) -> list[Slot]
```

- Hash family (planner's call): for `i` in 0..127, `a_i = rng.randrange(1, 2**32)` then
  `b_i = rng.randrange(0, 2**32)`, `rng = random.Random(20261116)`; `h` = the first 4 bytes of
  the SHA-256 of the shingle's UTF-8, big-endian. With `a, h, b < 2**32`, `a*h + b < 2**64`,
  so `uint64` numpy arithmetic is exact. LSH: 16 bands of 8 rows, a band's key is its 8 values'
  bytes; candidate pairs are verified by exact Jaccard. Clusters are the connected components
  of exact-equality edges plus verified near edges.
- Collapse: fused candidates up to 200 (`StoreIndex.retrieve(…, top=200)`); walk in rank
  order; the first member of each component (restricted to the members the caller's view and
  filters admit) takes the slot; the slot shows the component's canonical member with the
  best-ranked member's score (`scored_by`); `alternates` lists the other admitted members
  (`chunk_id`, `doc_id`, `exact|near`, Jaccard to the shown member, computed from shingles);
  stop at `top`. With a reranked index, collapse runs over the reranked top 50.
- `Tools.search(…, dedup: bool | None = None)`: `None` means on when a dedup overlay exists for
  the active index's chunks, off otherwise; `True` without an overlay is refused ("no dedup
  overlay; run `adr dedup build`"). `Hit` gains `scored_by` and `alternates`;
  `SearchResult` gains `dedup` (overlay id or null). Log lines gain `dedup`.
- `adr dedup build [--store S]` uses the active index's chunks; prints the cluster table of
  §4.5. Layout: `<store>/dedup/<snapshot_id>/<overlay_key>.json`.

Tests (§12 Dedup, all six bullets): exact clusters equal the SHA-256 groups; fixed signatures
for three fixture texts (computed once by a pure-Python reference loop, pinned in the test);
every candidate pair is verified (a forced LSH collision below the threshold is not linked);
canonical selection follows each tie-break in order (one fixture per rule); collapse never shows
two members of one admitted component and never shows or lists an invisible or filtered member
(admitted predicate excludes members; a hidden bridge member B between A~B~C does not join A
and C); `dedup=False` gives the Phase 1 ranking; byte-identical rebuild.

Real-data check: build on the three copies twice (byte-identical); compare with the §4.5
table — gov all versions: 1,958 exact clusters over 5,430 chunks, 3,472 redundant (51.2%), 366
verified near pairs, redundancy at 0.90 54.0%; gov in-force view: 0 exact; research: 1 exact
cluster of 3; bench: 1 of 3. Report differences and build time.

```python
# adr_eval.phase2
def item_subsets(items, groups, applicability) -> dict[str, list[str]]
    # "asof": policy_asof with evidence; "in_force": non-as-of with evidence, every group has a
    # member in a document with superseded_by null; "superseded_only": the other non-as-of
    # evidence items; "scored": all with metrics
def slot_stats(rows, chunks, applicability, dedup, items, groups) -> dict
    # per subset: superseded slots; wrong-version slots (as_of items: doc not admitted by
    # Filters(as_of=item.as_of)); duplicate slots (a slot sharing an admitted component with a
    # slot above it; also against unrestricted clusters); distinct evidence groups touched in
    # the top 10; tokens@10
```

## Builder notes: spec points resolved in this plan (planner's calls)

1. **ACL off vs fail closed.** F1/F4 deny a store without `acl/HEAD` or a call without a caller,
   but constraint 2 and §12 Regression keep Phase 1 tools working. `Tools(acl=False)` is the
   Phase 1 behaviour (log `acl_decision: "off"`); `acl=True` enforces F1–F5. `adr --as`, the
   probes, the Phase 2 harness after 2B and the MCP server (always) enforce.
2. **Phase 1 tests "unchanged".** Every result gains fields (§4.4, §4.5, §9.2: "every result
   carries a handle") and log `args` gain arguments, but Phase 1 tests pin exact key sets. Only
   those key sets are extended; no expected value changes.
3. **A5's "recorded" runs** have no committed per-item rows and none are local. They are
   re-run with the unchanged Phase 1 code and must reproduce the committed config and summary
   exactly; A5 compares `p2-identity` to those rows (Task 5).
4. **Build order vs. B criteria.** B1/B3/B4 name `search_tools`, `load_tool` and an
   already-running MCP server, which exist only after 2C and 2D. 2B measures them for the three
   content tools; Task 11 adds the tool tools; Task 13 adds the MCP legs. Likewise 2A runs
   before ACLs exist: the 2A runs have no ACL layer, and Task 8 re-runs them as `user:auditor`
   and requires identical rows.
5. **Dedup clusters across hidden members.** Connected components over all chunks can join two
   visible chunks only through a hidden or filtered bridge, which is both a weak leak and a B2
   mismatch against a subset store. The overlay stores edges, and collapse uses components
   restricted to the members the caller's view and filters admit.
6. **FR status wording.** "Notice if `action` names an enforcement notice or notification" is
   read as `(notice|notification) of enforcement`; "Notification of expired temporary rules"
   and "Notification of temporary deviation" are temporary rules. This reproduces §4.1's
   47/54/59/7.
7. **MinHash details** the spec leaves open: the `a`, `b` ranges (`[1, 2³²)`, `[0, 2³²)`,
   drawn as pairs), the shingle string (words joined by one space), big-endian `h`, the empty
   shingle, cluster `kind` and `min_jaccard`, and the dedup overlay id (SHA-256 of the file;
   the file also records `chunk_content_sha256`, checked on load).
8. **ACL salts and user ids** for tenant, second tenant and group are fixed in Task 6; §5.2's
   per-view shares came from a prototype whose salts are not recorded, so only the bucket counts
   must match exactly.
9. **Caller grammar.** A caller is a `user:` principal; F5 covers a malformed caller and
   off-grammar principals in a snapshot. F4 and F5 are decided per call, also in the MCP server.
10. **Read under filters.** §4.4 applies filters to `read`; a visible but filtered document is
    refused with a filter message (filters are not secret), an invisible one is "not found".
11. **Handle has a sixth key, `tool_index`.** §9.2's handle names the tool snapshot but not the
    tool index, so a replay of `search_tools` could change after a re-tune. Adding it keeps
    replays exact.
12. **Per-call HEAD.** `Tools` resolves HEAD, the active index and `acl/HEAD` per call (Phase 1
    read HEAD at construction), which F2 and revocation in long-running servers require.
13. **Harness module boundary.** The Phase 1 rule ("the harness imports `adr_store` only
    through the system registry") is kept for Phase 0/1 modules; the new probe, comparison and
    tool-evaluation modules import `adr_store` directly.
14. **Mini fixture applicability.** The deriver recognises only the spec's families by URI, so
    mini's dated regulation files are `unknown` (no invented dates); applicability tests use
    gov-shaped fixtures instead.
15. **Tool tuning metric.** nDCG@10 on dev (as Phase 1); Completeness@10 decides only the dev
    choice of system and C3.
16. **Probe callers for fail-closed** (Task 8) and the "no entry" construction (an attribute
    rule with `[]`) are fixed here; the spec gives only the counts.
17. **OpenAPI fixtures** come as JSON from the `gh-pages` branch to avoid a YAML dependency; the
    MCP reference-server snapshots are captured once in a throwaway venv and committed (MIT).
