# Knowledge Base Quality and Lifecycle for Agent Knowledge Bases (Freshness, Deduplication, Conflicts, Authority, Versioning, Permissions, Evaluation)

Scope: how to keep a *searchable* agent knowledge base (documents, rules, policies, SOPs, domain notes that agents retrieve by search) correct, current, consistent, governed and measurable over time. Indexing/chunking, SOP modeling, taxonomies, agent access patterns and product surveys are covered by other tracks. Research state as of November 2026; year of each source is given. "Author-reported" means the result comes from the paper or vendor that built the method. "Independent" means a third party measured it. Vendor docs are flagged as vendor (bias: they describe intended behavior, not measured behavior).

Cross-reference: the earlier study's `Deterministic retrieval data conversion/09_quality_versioning_provenance.md` covers quality, versioning and provenance for *typed/tabular* data (data contracts, lakehouse time travel, lineage). This file covers the *text knowledge base* side. Its problems are mostly different: temporal validity of passages, near-duplicate prose, contradictory documents, poisoning, permission-aware ANN search, and LLM-judged evaluation.

## 1. Freshness and incremental updates: change detection, incremental re-indexing, embedding refresh, stale-content detection, time-aware retrieval, expiry and review dates

### Takeaway
Incremental *ingestion* is a solved engineering problem: content hashing plus a record manager means only added, changed and deleted documents get re-parsed and re-embedded. *Temporal validity* is not solved. Benchmarks from 2025 and 2026 show that outdated passages left in the corpus are more harmful than irrelevant ones: they cost about 10–35 points of accuracy and can flip correct answers 17–91% of the time. Current dense retrievers and rerankers cannot tell "relevant" from "still valid". Recency decay helps only when temporal metadata is reliable, and it trades away recall. A KB therefore needs explicit validity metadata (effective_from, superseded_by, review_due, expires_at) that is used at both retrieval and generation time. It also needs an explicit lifecycle for retiring superseded content, not just "add new docs".

### Cited Findings

**Change detection and incremental re-indexing (engineering mechanisms)**
- LangChain indexing API (`index()` with a `RecordManager`, langchain-core). It hashes each document and its metadata, records what is in the vector store, and skips unchanged documents. Cleanup modes: `None` (never delete); `incremental` (delete stale versions of source IDs seen in this run, continuously, which "helps limit the chance that users see duplicated content"); `full` (after the run, delete everything the loader did not return, so the loader must return the entire dataset or it will wrongly delete content); `scoped_full` (full, limited to source IDs seen; added in 0.3.25). `force_update=True` re-indexes even unchanged docs, "useful when re-indexing with updated embeddings". The default `key_encoder` is SHA-1, and the docs warn that "SHA-1 is not collision-resistant", so an attacker could craft colliding texts. Changing the encoder requires re-indexing to avoid duplicates — [LangChain reference: indexing.api.index (vendor/OSS docs, 2025–2026)](https://reference.langchain.com/python/langchain-core/indexing/api/index)
- LlamaIndex `IngestionPipeline` with a docstore keeps a `doc_id → content hash` map. With a vector store attached, a repeated `doc_id` with a changed hash is re-processed and upserted, and an unchanged hash is skipped. Without a vector store it can only drop duplicate inputs. Each (node, transformation) pair is also hashed and cached (local, Redis, MongoDB or Firestore), so reruns reuse earlier transformation and embedding outputs — [LlamaIndex Ingestion Pipeline docs (OSS docs)](https://developers.llamaindex.ai/python/framework/module_guides/loading/ingestion_pipeline/)
- Amazon Bedrock Knowledge Bases (managed, vendor doc): "Syncing is incremental, so Amazon Bedrock processes only the documents that were added, modified, or deleted since the last sync." Changed content or metadata leads to full re-parse, re-chunk, re-embed and re-index. Deletes remove vectors. A metadata-only optimization merges new metadata into existing vectors without calling the embedding model, but only when only `.metadata.json` changed, the file is not CSV, and no custom transformation Lambda is used. Newly synced vectors can take "a few minutes" to become queryable for non-Aurora stores — [AWS Bedrock user guide: sync data (vendor, 2026)](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-data-source-sync-ingest.html)
- Implication for ACL metadata: Azure AI Search says permission changes in the source "are only reflected in search results after that metadata is synchronized to the index". For SharePoint, item-level unique-permission changes are picked up incrementally on each indexer run (2026-05-01-preview API), but changes *inherited* from site, library or folder scope "require an explicit refresh". Freshness of ACLs is therefore a separate SLA from freshness of content — [Microsoft Learn: Document-level access control in Azure AI Search (vendor, updated Sept 2026)](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview)

**Embedding-model refresh**
- Drift-Adapter (Vejendla, arXiv 2025) learns a small mapping (Orthogonal Procrustes, low-rank affine or residual MLP) from new-model query embeddings into the legacy embedding space, so the existing ANN index keeps serving after an embedding-model upgrade. Author-reported results on MTEB text corpora and a 1M-item CLIP upgrade: it recovers 95–99% of full re-embedding Recall@10/MRR, adds under 10 µs of query latency, and costs "over 100 times" less to recompute than full re-indexing or dual-index serving. Failure mode: the gain shrinks under larger model drift, and it only *defers* re-embedding — [Drift-Adapter, arXiv:2509.23471](https://arxiv.org/abs/2509.23471)
- Inference: on a full re-embed, LangChain's `force_update` (above) or a blue/green index rebuild is the conventional route. Drift-Adapter is the cheap bridge while that rebuild runs.

**Why stale content matters: evidence from temporal benchmarks**
- TimeQA (Chen, Wang & Wang; NeurIPS 2021 Datasets track; arXiv 2021) mined time-evolving facts from Wikidata aligned to Wikipedia and wrote time-sensitive questions. The best model then, FiD, reached 46% vs 87% for humans. This established that QA systems lack consistent temporal reasoning — [TimeQA, arXiv:2108.06314](https://arxiv.org/abs/2108.06314)
- StreamingQA (Liška et al., DeepMind, ICML 2022): questions asked on a given date over 14 years of time-stamped news, evaluated quarterly. Adding new articles to the retrieval index allows "rapid adaptation", but semi-parametric models with an outdated LM under-perform those with a retrained LM — [StreamingQA, arXiv:2205.11388](https://arxiv.org/abs/2205.11388)
- RealTime QA (Kasai et al., 2022; weekly questions): GPT-3 updates answers from newly retrieved documents but "tends to return outdated answers when retrieved documents do not provide sufficient information", which is an unanswerable-case detection problem — [RealTime QA, arXiv:2207.13332](https://arxiv.org/abs/2207.13332)
- FreshLLMs / FreshQA (Vu et al., Google, 2023): every model struggles with fast-changing and false-premise questions. Evidence count and *order* in the prompt materially change correctness. The benchmark is refreshed periodically — [FreshLLMs, arXiv:2310.03214](https://arxiv.org/abs/2310.03214)
- CRAG (Meta; KDD Cup 2024): 4,409 QA pairs labeled by dynamism (real-time = seconds, fast-changing = up to daily, slow-changing = up to yearly, static). It scores perfect / acceptable / missing / incorrect as +1 / 0.5 / 0 / −1, so hallucination costs more than abstaining. Straightforward RAG with GPT-4 Turbo reached only 43.6% accuracy with 30.1% hallucination. The best industry systems answered at most 63% "perfect" without hallucination (Copilot Pro 62.6% perfect, 17.9% hallucination). Real-time and fast-changing questions remained among the hardest slices — [CRAG, arXiv:2406.04744](https://arxiv.org/abs/2406.04744)
- HoH (Ouyang et al., ACL 2025; arXiv 2025) is the first benchmark aimed at *outdated information coexisting* in the corpus: 96,124 QA pairs and 219,463 documents built from monthly Wikipedia diffs (Myers diff plus a fine-tuned Qwen2.5-0.5B factual-change classifier at 96.8% accuracy). Llama-3.1-70B falls from 89.12 to 72.95 score when one outdated passage is added, with 10.05% "harmful" answers. Llama-3.1-8B falls from 85.70 to 50.93 and Qwen-2.5-7B from 76.31 to 33.93. Without temporal weighting, outdated passages are retrieved slightly *more* often than current ones (top-5 hit 0.8837 vs 0.8707). Gaussian time decay cuts outdated hits to 0.4950 but lowers relevant hits to 0.7023. Temporal retrievers trade recall for validity: MRAG gets outdated hits to about 0.05 but relevant hits fall to about 0.29, while TempRALM gets 0.45 relevant / 0.23 outdated. "Outdated passages hurt RAG more than irrelevant ones." Caveat (from the authors): the outdated docs are near-copies, which is less varied than real corpora — [HoH, arXiv:2503.04800](https://arxiv.org/abs/2503.04800)
- Stale-Document Poisoning (Ahmed, Galke Poech & Röttger, arXiv Sept 2026): 317 verified "knowledge reversals" in medicine, law, software and platform policy, grounded in dated official sources. Outdated retrieved evidence flips 30% (Llama) and 37% (Qwen) of answers that were correct without retrieval. With an explicit "follow the document" instruction, that rises to 66% and 75%. Across models and domains the flip rate ranges 17–91%, while up-to-date evidence is followed in 97–100% of trials. Dates alone give only modest adaptation. When models are told *when the old evidence stops applying*, larger models switch almost perfectly. A recency-aware hybrid reranker cut poisoning by 4.6–10.0 points, but only when dates were accurate — [Stale-Document Poisoning, arXiv:2609.31342](https://arxiv.org/abs/2609.31342)
- TREK (Hu et al., arXiv Oct 2026): over rapidly evolving knowledge, "the main bottleneck is post-retrieval reasoning rather than retrieval". Frontier models are misled by conflicting evidence even after retrieving everything needed. Benchmarks dominated by outdated distractors "substantially underestimate task difficulty" — [TREK, arXiv:2610.25323](https://arxiv.org/abs/2610.25323)
- Healthcare RAG (Javadi et al., 2025): using Australian TGA consumer medicine documents and PubMed abstracts stratified by publication year, contradictions between highly similar abstracts degraded accuracy and consistency. The authors conclude "retrieval similarity alone is insufficient" and call for contradiction-aware filtering — [Contradictions in Context, arXiv:2511.06668](https://arxiv.org/abs/2511.06668)

**Time-aware retrieval methods**
- TempRALM (Gade & Jetcheva, 2024) adds a temporal relevance term to semantic similarity, scoring documents relative to the query's time. It reports up to 74% improvement over a baseline RALM "without requiring ... recalculating or replacing the RALM document index" (author-reported; small-scale Wimbledon-style queries) — [It's About Time, arXiv:2401.13222](https://arxiv.org/abs/2401.13222)
- TempRetriever (Abdallah et al., 2025) embeds query date and document timestamp into DPR and uses time-based negative sampling. Author-reported gains: +6.63% Top-1 and +3.79% NDCG@10 on ArchivalQA, and +9.56% Top-1 on ChroniclingAmericaQA. It needs training data with timestamps — [TempRetriever, arXiv:2502.21024](https://arxiv.org/abs/2502.21024)
- MRAG (Zhang et al., 2024; TempRAGEval) is training-free. It splits the question into main content plus a temporal constraint, summarizes retrieved evidence, then ranks with a semantic-temporal hybrid. In HoH's independent test it strongly suppressed outdated docs but lost recall (see above) — [MRAG, arXiv:2412.15540](https://arxiv.org/abs/2412.15540)
- ChronoQA (Chen et al., 2025): 5,176 Chinese questions over 300k news articles (2019–2024), covering absolute, aggregate and relative temporal types, for evaluating temporal RAG — [ChronoQA, arXiv:2508.12282](https://arxiv.org/abs/2508.12282)
- Fact-duration prediction (Zhang & Choi, EMNLP Findings 2023) predicts how long a fact stays true, then discards volatile facts or routes them to fresh sources. This improves calibration under temporal misalignment. It is the conceptual basis for setting per-item review intervals by volatility — [Mitigating Temporal Misalignment, arXiv:2305.14824](https://arxiv.org/abs/2305.14824)
- Bi-temporal memory: Zep/Graphiti (Zep AI, Jan 2025) keeps a temporally aware knowledge graph whose edges carry validity metadata. When new information contradicts a fact, the affected edges are *invalidated* rather than deleted, which preserves history. Updates are incremental per "episode", not batch recomputation as in GraphRAG. Author-reported: 94.8% vs 93.4% (MemGPT) on DMR, and up to 18.5% accuracy gain with 90% lower latency on LongMemEval — [Zep, arXiv:2501.13956](https://arxiv.org/abs/2501.13956); [Graphiti overview (vendor docs)](https://help.getzep.com/graphiti/getting-started/overview)
- Mem0 (2025) extracts, consolidates and updates (ADD/UPDATE/DELETE/NOOP) memories from conversations. Author-reported on LOCOMO: 26% relative improvement over OpenAI memory on LLM-as-judge, 91% lower p95 latency, and over 90% token savings vs full context. These are vendor-authored claims about memory consolidation, a cousin of KB dedup and update — [Mem0, arXiv:2504.19413](https://arxiv.org/abs/2504.19413)

**Review dates and expiry in human-curated KBs**
- Guru (vendor) "verification": each card has a verifier and a verification interval. Guru's blog gives the default as 1 month, and the vendor recommends review at least yearly. On expiry the card becomes *Unverified* and goes to the verifier's queue, but it "remains searchable and visible", with the status shown to users. The verifier checklist says to lengthen the interval if nothing changed and shorten it if a lot changed — [Guru verification feature page (vendor)](https://www.getguru.com/features/verification); [Guru blog: introducing verification (vendor)](https://www.getguru.com/blog/introducing-verification); [Guru Verification Checklist card (vendor)](https://app.getguru.com/card/T9GMGbyc/Verification-Checklist)
- KCS v6 (Consortium for Service Innovation) argues *against* archiving as the main freshness fix: "Archiving old articles treats the symptoms of findability, not the cause". With relevance-driven search, old content can stay if it stays out of irrelevant results. Archiving strategy is an output of Knowledge Domain Analysis — [KCS v6 Technique 5.5 Archiving Old Articles](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/044); [KCS v6 Technique 5.9 Knowledge Domain Analysis](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/060)

### Inferences
- The KCS "don't archive, rank" stance predates LLM RAG. HoH and Stale-Document Poisoning show that for LLM consumers, a superseded passage in top-k is *actively harmful*, not merely noise. For agent KBs, superseded content should be excluded from default retrieval by a hard validity filter, with history kept only for explicit "as-of" queries. This is the bi-temporal pattern Graphiti uses. It is a deliberate departure from human-KB practice.
- The most cost-effective freshness signal is *explicit applicability metadata surfaced to the generator* ("superseded on 2026-03-01 by doc X"). Stale-Document Poisoning found that telling the model when old evidence stops applying nearly fixed the problem for larger models, while recency decay alone gave only 4.6–10 points. Ingestion should extract or require effective/superseded dates for policies and SOPs.
- Review intervals should scale with volatility (fact-duration idea; Guru checklist heuristic; CRAG dynamism classes). Example: static reference content 12 months, policies on their own review cycle, fast-changing operational facts days to weeks or served live rather than indexed.
- Track content freshness and ACL freshness as two separate SLAs (Azure inherited-permission caveat).

### Gaps
- No independent benchmark compares recency-decay functions (Gaussian vs exponential vs step) across enterprise policy corpora. HoH is Wikipedia-based, and its outdated docs are near-duplicates.
- No published measurements of how fast "staleness" accumulates in real enterprise KBs (e.g., % of articles past review date) were found. Vendor claims exist but no audited data.
- No independent evaluation of Drift-Adapter was found. It is a single-author 2025 preprint.

## 2. Duplicates, near-duplicates, versions of the same document, and canonical source selection

### Takeaway
Exact duplicates are caught by content hashes. Near-duplicates (boilerplate, re-exports, copies across SharePoint, Confluence and email) need MinHash/LSH (Jaccard over shingles) or SimHash (Hamming over 64-bit fingerprints), both mature since 1997–2007. *Semantic* duplicates (paraphrases, translations) need embedding clustering (SemDeDup-style). Dedup in a KB is not just a storage saving. Duplicates crowd top-k and amplify one source's "vote" in conflict resolution. But *versions* of the same document must not be collapsed blindly: version-aware retrieval (VersionRAG) lifts versioned-QA accuracy from 58% to 90%. Canonical selection is a governance decision: authoritative system of record > latest effective version > most-reused or validated. Generic dedup does not stop adversarial poisoning, because poisoned texts are deliberately non-identical.

### Cited Findings

**Classical near-duplicate detection**
- MinHash / resemblance (Broder, SEQUENCES 1997; DEC SRC). It defines *resemblance* and *containment* of documents, reduces both to set intersection over shingles, and estimates them with small random-permutation sketches. This is the basis of MinHash-LSH dedup used today. Cost: linear-time sketching, and LSH banding gives sublinear candidate lookup — [Broder 1997, On the resemblance and containment of documents (PDF)](https://www.cs.princeton.edu/courses/archive/spring13/cos598C/broder97resemblance.pdf)
- SimHash (Charikar, STOC 2002) gives locality-sensitive hashing schemes from rounding algorithms. Random-hyperplane hashing makes Hamming distance between fingerprints approximate cosine similarity — [Charikar 2002, Similarity estimation techniques from rounding algorithms (PDF)](https://www.cs.princeton.edu/courses/archive/spr04/cos598B/bib/CharikarEstim.pdf)
- Google web-scale near-duplicate detection (Manku, Jain & Das Sarma, WWW 2007): "for a repository of 8B webpages, 64-bit simhash fingerprints and k = 3 are reasonable". At k=3, precision and recall were both "near 0.75". The 8B fingerprints occupy 64GB, and permuted-table lookups find fingerprints within k bits fast enough for crawl-time decisions. Lesson: SimHash at k=3 still misses or mislabels about a quarter of pairs, so tune on your own labeled pairs — [Manku et al., Detecting Near-Duplicates for Web Crawling (PDF)](https://static.googleusercontent.com/media/research.google.com/en//pubs/archive/33026.pdf)
- Lee et al. (Google, ACL 2022; arXiv 2021) built exact-substring (suffix array) and near-duplicate (MinHash) dedup for LM training data. C4 contained one 61-word sentence repeated over 60,000 times, and train-test overlap affected over 4% of validation sets. Dedup cut memorized emissions 10× and reduced the training steps needed. This is independent evidence that duplicated text distorts downstream behavior and evaluation — [Deduplicating Training Data, arXiv:2107.06499](https://arxiv.org/abs/2107.06499)
- SemDeDup (Abbas et al., Meta AI, 2023) clusters pretrained-model embeddings (k-means) and removes pairs above a cosine threshold within clusters. It removed 50% of a LAION subset with minimal performance loss and also helped on C4. This is the semantic-dedup template — [SemDeDup, arXiv:2303.09540](https://arxiv.org/abs/2303.09540)

**Redundancy pruning specific to RAG corpora**
- Chunk filtering (Berdyugina et al., 2026): entity-based filtering cut vector index size by about 25–36% while keeping retrieval quality close to baseline (token-level precision, recall and IoU), across several corpora — [Reducing Redundancy in RAG through Chunk Filtering, arXiv:2604.24334](https://arxiv.org/abs/2604.24334)
- Zero-RAG (Luo et al., Frontiers of CS 2026) uses a "Mastery-Score" to prune corpus knowledge the LLM already knows. It pruned Wikipedia by 30% and sped retrieval by 22% "without compromising RAG's performance" (author-reported). Caution: for enterprise KBs, pruning by "the model knows it" removes the authoritative citation, which governance usually needs — [Zero-RAG, arXiv:2511.00505](https://arxiv.org/abs/2511.00505)
- Maximal Marginal Relevance (Carbonell & Goldstein, SIGIR 1998) is the standard query-time diversity rerank against redundant hits. But a 2026 poisoning stress test found MMR "leaves exposure unchanged" for query-anchored poisons. MMR handles benign redundancy, not attacks — [MMR, SIGIR 1998 (DOI)](https://doi.org/10.1145/290941.291025); [Reliability Stress Testing under Query-Relevant Corpus Poisoning, arXiv:2611.04264](https://arxiv.org/abs/2611.04264)
- Dedup does not stop poisoning: in PoisonedRAG, duplicate-text filtering left attack success "unchanged in every case" (e.g., NQ black-box stayed at 0.97), because each malicious text's generated part differs — [PoisonedRAG (USENIX Security 2025), arXiv:2402.07867](https://arxiv.org/abs/2402.07867)

**Versions of the same document**
- VersionRAG (Huwiler, Stockinger & Fürst, ZHAW, 2025) models document evolution as a hierarchical graph of version sequences, content boundaries and changes between versions. It routes queries by intent (version-specific vs change-tracking). On VersionQA (100 manual questions over 34 versioned technical docs) it reaches 90% accuracy vs 58% for naive RAG and 64% for GraphRAG. Implicit change detection reaches 60% vs 0–10% for baselines, and indexing uses 97% fewer tokens than GraphRAG. Small benchmark, author-reported — [VersionRAG, arXiv:2510.08109](https://arxiv.org/abs/2510.08109)
- KCS content standard check #1 is "Unique: no duplicate article created earlier with the same content". The Consortium says many duplicates in sampling signal a need for search training ("search early, search often"). Duplicates are weighted as more severe than wordiness — [KCS v6 Technique 5.10 Content Health Indicators](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/065)
- KCS Knowledge Domain Analysis lists "Content overlaps: consolidating duplicate articles" as a named output owned by Knowledge Domain Experts — [KCS v6 Technique 5.9](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/060)

### Inferences
- Recommended layered dedup at ingestion:
  1. Normalized exact hash (SHA-256, not SHA-1, given the LangChain warning) at document and chunk level.
  2. MinHash-LSH on 5-gram word shingles at a Jaccard threshold of about 0.8, or SimHash with k≈3 on 64 bits, for near-duplicates.
  3. Embedding-cluster semantic duplicates flagged for *review*, not auto-deleted, because paraphrased policies may differ in one critical clause.
- Treat "same logical document, different version" as a *version chain* (doc_id, version, effective dates, supersedes), not a duplicate. Retrieval defaults to the current effective version. The others stay addressable for as-of and diff queries (VersionRAG, Graphiti).
- Canonical source selection should be rule-based and auditable. Precedence: (a) designated system of record or owner, (b) approval/validated state, (c) latest effective date, (d) reuse signal. Non-canonical copies keep a `canonical_ref` pointer so that citations resolve to the authoritative copy.

### Gaps
- No benchmark measures the effect of near-duplicate *chunks* on RAG answer quality in enterprise corpora (as opposed to LM training). Expected harms (top-k crowding, inflated agreement) are inferred, not measured.
- No published best-practice thresholds for MinHash or SimHash on short policy/SOP chunks (vs web pages) were found.

## 3. Conflicting knowledge, source authority and trust ranking, and misinformation/poisoned documents with defenses

### Takeaway
LLMs are poor at handling conflicting context. With two contradictory passages they rarely surface the conflict (WikiContradict). They adopt wrong retrieved content over a correct prior more than 60% of the time (ClashEval). Misleading real-world retrievals make RAG *worse than no retrieval* (RAGuard). Conflict must therefore be handled *before* generation and in the KB itself:
- detect contradictions at ingestion and in periodic audits (LLM or NLI pair checks on near-neighbor chunks; a two-stage cheap-classifier-then-LLM cascade cuts cost about 62%);
- attach authority and provenance metadata and rank or filter by it (reliability-aware RAG, credibility-aware generation);
- distinguish *evolution* (newer supersedes older) from *disagreement* and from *attack* (EvoTrustRAG).

Poisoning is practical: 5 crafted passages per target in a corpus of millions give about 90–99% attack success, and a single document can work as a backdoor. Published query-time detectors look much weaker once benchmark shortcuts are removed. Ingestion-time filters provably cannot stop coordinated poisoning. The strongest controls are *who can write* (provenance, signed sources, review gates) plus retrieval-time demand monitoring and isolate-then-aggregate generation for high-stakes answers.

### Cited Findings

**Taxonomy and benchmarks of knowledge conflicts**
- The survey by Xu et al. (EMNLP 2024; arXiv 2024) defines three classes: *context-memory* (retrieved vs parametric), *inter-context* (between retrieved passages) and *intra-memory*. It reviews causes (misinformation, outdated info, ambiguity), model behaviors and solutions — [Knowledge Conflicts for LLMs: A Survey, arXiv:2403.08319](https://arxiv.org/abs/2403.08319)
- Liu & Roth (2025) survey conflicts in natural text (including conflicting sources), annotation conflicts and generated-output conflicts, arguing conflicts must be "explained and dealt with", not discarded — [Conflicts in Texts, arXiv:2504.19472](https://arxiv.org/abs/2504.19472)
- ConflictBank (Su et al., NeurIPS 2024 D&B; arXiv 2024): 7,453,853 claim-evidence pairs and 553,117 QA pairs covering conflicts from misinformation, temporal discrepancies and semantic divergence, tested on 12 LLMs from 4 families — [ConflictBank, arXiv:2408.12076](https://arxiv.org/abs/2408.12076)
- WikiContradict (Hou et al., IBM Research, NeurIPS 2024 D&B; arXiv 2024): 253 human-annotated real Wikipedia contradictions between *equally trustworthy* passages. Given two contradictory passages, "all models struggle to generate answers that accurately reflect the conflicting nature of the context, especially for implicit conflicts". An automated judge reaches F=0.8 against human evaluation (3,500+ judgments) — [WikiContradict, arXiv:2406.13805](https://arxiv.org/abs/2406.13805)
- ClashEval (Wu, Wu & Zou, Stanford, NeurIPS 2024 D&B; arXiv 2024): 1,200+ questions in six domains (drug dosages, records, etc.) with perturbed context. Models adopt incorrect retrieved content, "overriding their own correct prior knowledge over 60% of the time". Less realistic perturbations and higher model confidence (token probabilities) reduce adoption — [ClashEval, arXiv:2404.10198](https://arxiv.org/abs/2404.10198)
- WhoQA (Pham et al., 2024): 5K questions about same-name entities with up to 8 valid answers. The authors recommend models "transparently inform users about the conflicts" rather than choose silently, and find conflicts significantly degrade RAG performance — [Who's Who, arXiv:2410.15737](https://arxiv.org/abs/2410.15737)
- RAGuard (Zeng et al., 2025) uses naturally occurring misinformation (Reddit) as the retrieval corpus. With misleading retrievals, "all tested LLM-powered RAG systems perform worse than their zero-shot baselines", while humans do better — [RAGuard, arXiv:2502.16101](https://arxiv.org/abs/2502.16101)
- RGB (Chen et al., AAAI 2024; arXiv 2023) tests noise robustness, negative rejection, information integration and counterfactual robustness. LLMs "struggle significantly" with negative rejection and false information — [RGB, arXiv:2309.01431](https://arxiv.org/abs/2309.01431)
- Context compliance (Chen et al., 2026): under a worst-case TruthfulQA misconception-injection probe, standard RAG reaches only 15.0% accuracy. Explicit decomposition (contextual vs prior answer) improves controlled-conflict robustness (Entity Swap 88.0% vs 79.3%). The authors frame conflict handling as an *observability* problem — [Does RAG Know When Retrieval Is Wrong?, arXiv:2605.14473](https://arxiv.org/abs/2605.14473)

**Contradiction detection across documents (KB-side auditing)**
- LLMs as context validators (Gokul et al., Amazon, 2025): a synthetic contradiction-generation framework shows that detecting contradictions in a retrieved set "remains a challenging task even for state-of-the-art LLMs". Performance varies by contradiction type, and chain-of-thought helps some models and hurts others — [Contradiction Detection in RAG Systems, arXiv:2504.00180](https://arxiv.org/abs/2504.00180)
- ConflictRAG (Wang et al., 2026) detects conflicts in two stages: an embedding-based MLP classifier, with LLM refinement only for uncertain cases. This reduced API cost by 62% at 90.8% detection accuracy. It adds Entropy-TOPSIS source-credibility scoring (+7.1% selection accuracy over manual heuristics) and reports 88.7% conflict-detection F1 (author-reported) — [ConflictRAG, arXiv:2605.17301](https://arxiv.org/abs/2605.17301)
- SparseCL (Xu et al., 2024) trains sentence embeddings that preserve contradiction cues and combines cosine with a sparsity score, so contradiction *retrieval* scales as vector search. It reports over 30% accuracy gains on MSMARCO/HotpotQA synthetic contradictions and is used to clean corrupted corpora — [SparseCL, arXiv:2406.10746](https://arxiv.org/abs/2406.10746)
- Caution on dense retrievers: CoverageBench-Negate (Abrishamchian et al., Oct 2026) builds about 63,000 original vs negated near-twin evidence pairs. BM25 separates them "substantially better" than dense retrievers (Qwen3, Jina), which "stay near chance". Embedding similarity alone will not flag negation-type contradictions — [Coverage Under Contradiction, arXiv:2610.37162](https://arxiv.org/abs/2610.37162)
- EvoTrustRAG (Nie et al., Aug 2026) introduces *conflict origin attribution*: is a conflict legitimate evolution, malicious intervention, or unresolved uncertainty? It builds a conflict evidence graph and keeps earlier and later states as temporal knowledge, separates intervention candidates, or leaves unresolved conflicts visible. Author-reported: attribution macro-F1 rises from 72.2% to 79.1%, and error under the strongest coordinated attack falls from 31.2% to 16.0% — [EvoTrustRAG, arXiv:2608.07933](https://arxiv.org/abs/2608.07933)

**Source authority and trust ranking**
- RA-RAG (Hwang et al., ICML 2025; arXiv 2024) estimates per-source reliability by cross-checking information across sources (truth-discovery style). It retrieves from the top-κ reliable and relevant sources and aggregates by weighted majority vote, and it scales as the number of sources grows (author-reported) — [RA-RAG, arXiv:2410.22954](https://arxiv.org/abs/2410.22954)
- Classical antecedent: SLiMFast (Joglekar, Rekatsinas & Garcia-Molina, 2015/SIGMOD 2017) does data fusion with source-reliability estimation and guarantees. This is the truth-discovery line that RA-RAG revisits — [SLiMFast, arXiv:1512.06474](https://arxiv.org/abs/1512.06474)
- Credibility-aware generation (Pan et al., 2024) trains LLMs to weigh contexts by provided credibility scores — [Not All Contexts Are Equal, arXiv:2404.06809](https://arxiv.org/abs/2404.06809)
- CrAM (Deng et al., AAAI 2025; arXiv 2024) is plug-and-play. It finds influential attention heads and scales their attention to each document by its credibility score, giving over 20% improvement against misinformation pollution on NQ/TriviaQA with Llama2-13B, Llama3-8B and Qwen1.5-7B. It needs white-box model access — [CrAM, arXiv:2406.11497](https://arxiv.org/abs/2406.11497)
- Astute RAG (Wang et al., Google Cloud AI Research, 2024) elicits the LLM's internal knowledge, consolidates it with retrieved passages "with source-awareness", and finalizes by reliability. It is the only method to match or beat no-RAG in the worst case (Gemini, Claude; author-reported) — [Astute RAG, arXiv:2410.07176](https://arxiv.org/abs/2410.07176)
- MADAM-RAG (Wang, Prasad, Stengel-Eskin & Bansal, UNC, 2025) has one agent per document debate, with an aggregator that keeps all valid disambiguated answers and discards misinformation. It gains up to 11.40% on AmbigDocs and up to 15.80% on FaithEval (Llama3.3-70B). On RAMDocs the baseline reaches only 32.60 EM. The gap stays large when supporting evidence is imbalanced — [RAG with Conflicting Evidence, arXiv:2504.13079](https://arxiv.org/abs/2504.13079)
- Wikipedia source reliability (D'Ignazi et al., ACM TWeb 2025) models the reliability of cited domains across languages. It is an example of deriving authority priors from editorial behavior — [Language-Agnostic Modeling of Source Reliability on Wikipedia, arXiv:2410.18803](https://arxiv.org/abs/2410.18803)

**Poisoning attacks on the corpus**
- Zhong et al. (Princeton, EMNLP 2023) use HotFlip-style token perturbations to make adversarial passages that dense retrievers return for *unseen* queries. 50 passages optimized on NQ misled over 94% of questions on financial and forum corpora, and every retriever tested fell to 500 or fewer passages in a corpus of millions — [Poisoning Retrieval Corpora, arXiv:2310.19156](https://arxiv.org/abs/2310.19156)
- PoisonedRAG (Zou, Geng, Wang & Jia; USENIX Security 2025, pp. 3827–3844): 5 malicious texts per target question in corpora of 2.68M (NQ), 5.23M (HotpotQA) and 8.84M (MS-MARCO) give ASR of 0.97/0.97, 0.99/0.94 and 0.91/0.90 (black-box/white-box). Tested defenses: paraphrasing reduced ASR only to about 0.79–0.93; perplexity detection had a high false-positive rate at useful recall; duplicate filtering had no effect; retrieving k=50 still left about 41–43% ASR on HotpotQA while inflating context cost — [PoisonedRAG, arXiv:2402.07867](https://arxiv.org/abs/2402.07867); [USENIX Security 2025 PDF](https://usenix.org/system/files/usenixsecurity25-zou-poisonedrag.pdf)
- Phantom (Chaudhari et al., 2024) uses *one* malicious document that is retrieved only when a natural trigger phrase appears. It can induce refusal, reputation damage, privacy violation or harmful output, transfers to GPT-3.5/4, and was demonstrated end-to-end on NVIDIA "Chat with RTX" — [Phantom, arXiv:2405.20485](https://arxiv.org/abs/2405.20485)
- A policy-KB case (Solanki et al., 2026): one injected *rule* (1.6% poisoning rate) corrupted 85% of LLM contexts in a policy-aware RAG for mission control. This is directly relevant to rule/SOP KBs — [KB Poisoning for Policy-Aware LLM-RAG, arXiv:2607.04379](https://arxiv.org/abs/2607.04379)

**Defenses and their measured limits**
- RobustRAG (Xiang et al., Princeton, 2024) isolates passages into groups, generates per group, then securely aggregates by keyword or decoding. It offers *certifiable* robustness for a bounded number of injected passages. Cost: multiple LLM calls per query and some clean-accuracy loss — [Certifiably Robust RAG, arXiv:2405.15556](https://arxiv.org/abs/2405.15556)
- TrustRAG (Zhou et al., 2025) first filters by clusters (poisoned passages cluster tightly), then lets the LLM self-assess and resolve inconsistencies. It is training-free and plug-in — [TrustRAG, arXiv:2501.00879](https://arxiv.org/abs/2501.00879)
- RAGPart and RAGMask (Pathmanathan et al., 2025) are retriever-side defenses using document partitioning and token-masking similarity shifts. They reduce ASR across 4 attacks and 4 retrievers while keeping benign utility, and the authors also stress-test with an interpretable attack — [RAGPart & RAGMask, arXiv:2512.24268](https://arxiv.org/abs/2512.24268)
- An attention-variance filter (Choudhary et al., 2025) flags passages with anomalous normalized attention. It gives up to about 20% higher accuracy than baselines, but adaptive attacks still reach up to 35% success — [Through the Stealth Lens, arXiv:2506.04390](https://arxiv.org/abs/2506.04390)
- ProGRank (Yin et al., 2026) is a training-free retriever-side rerank using probe-gradient instability signals, including under adaptive attacks (author-reported) — [ProGRank, arXiv:2603.22934](https://arxiv.org/abs/2603.22934)
- Independent critique 1, "Ranking Is Not Deciding" (Kumar & Sahaym, Oct 2026). PoisonedRAG's released code prepends the target question to every poison. Of 21 published defense evaluations surveyed, 8 verifiably used poison built that way, 5 used a length cue, and 12 report no false-positive rate at the deployed threshold. Deleting only the prefix took a re-implemented content filter from AUROC 0.953 to 0.758 and its miss rate from 0.191 to 0.763. Length-padding took TrustRAG's set-level stage from a 0.000 to a 0.827 miss rate. Conclusion: report the poison set's construction profile and the operating-point FPR — [Ranking Is Not Deciding, arXiv:2610.33849](https://arxiv.org/abs/2610.33849)
- Independent critique 2, "Coverage Is Not Containment" (Pathak & Sharma, Aug 2026). A coordinated set of m=10 individually unremarkable documents seizes 10/10 top-k slots for a target (9.9/10 on a live HNSW index) and makes the generator emit the planted claim 88% of the time. The authors *prove* that any ingestion-time statistic cannot separate this from legitimate niche uploads: the best trained classifier catches 4.2% at 1% FPR. A retrieval-time detector that observes *query demand* caught 100% at the same FPR — [Coverage Is Not Containment, arXiv:2608.16044](https://arxiv.org/abs/2608.16044)
- Retrieval-layer stress test (Sung et al., Nov 2026): five query-targeted documents per query cut classical-retriever nDCG@10 by 40.2–61.5%. Overlap-based admission filtering removes full-query poisons but "may sharply reduce clean retrieval utility", and MMR does not reduce exposure — [Reliability Stress Testing, arXiv:2611.04264](https://arxiv.org/abs/2611.04264)
- OWASP Top 10 for LLM Apps 2025, LLM08 "Vector and Embedding Weaknesses", lists data poisoning, cross-context leaks, knowledge conflicts and embedding inversion. Mitigations: "accept data only from trusted sources", audit the KB for hidden content, tag and classify data, and keep "detailed, immutable logs of retrieval activity". Example: a résumé with hidden text that steers a RAG screener — [OWASP LLM08:2025](https://genai.owasp.org/llmrisk/llm082025-vector-and-embedding-weaknesses/)
- Security survey (Mu et al., 2026) gives an end-to-end taxonomy of RAG threats (poisoning, adversarial, membership inference) and input/output-side defenses with benchmarks — [Towards Secure RAG, arXiv:2603.21654](https://arxiv.org/abs/2603.21654)

### Inferences
- For an agent KB, *conflict handling belongs in the data layer*. Each chunk carries `source_system`, `owner`, `authority_tier`, `approval_state`, `effective_from/to` and `supersedes`. Retrieval passes these to the generator. Conflicting top-k sets get a "conflict present" flag so the agent can disclose or escalate, as WhoQA and WikiContradict recommend.
- Offline contradiction audits are affordable with a cascade: candidate pairs from near-neighbor search plus BM25 (dense alone misses negations), a cheap classifier, then an LLM judge for uncertain pairs (about 62% cost cut in ConflictRAG). A human owner resolves the result: supersede, merge, or mark as legitimately scoped (e.g., region-specific policy).
- Poisoning defense should start with *write-path governance*. Given the impossibility result for admission filters and the shortcut critique of query-time detectors, controls that do not depend on content statistics are the most robust: provenance, allow-listed sources, signed and owner-approved policy documents, and quarantine for user-contributed or external content. Add retrieval-time demand anomaly monitoring and, for high-stakes rule answers, isolate-then-aggregate (RobustRAG).
- Treat hidden text (white-on-white, zero-size fonts, alt text) as an ingestion QA check, per OWASP's résumé scenario.

### Gaps
- No standard benchmark covers *enterprise policy* contradictions (e.g., regional variants, superseded procedures). WikiContradict and ConflictBank are Wikipedia or synthetic.
- Authority-tier ranking (system-of-record priority) is common in practice, but no controlled study of its effect was found.
- Defense results are mostly author-reported. The 2026 critiques suggest many are overstated, and no independent leaderboard with standardized poison construction exists.

## 4. Permissions and governance: document-level ACLs, permission-aware retrieval, PII redaction, data residency, leakage (membership inference), and auditing what the agent read

### Takeaway
The consensus, from vendors and from a Microsoft Research position paper, is *deterministic* enforcement. Every retrieved chunk must be authorized for every principal in the interaction, enforced inside the retrieval engine (pre-filter on ACL metadata synced from the source), never by prompting the LLM to withhold content. Key operational risks:
- ACL sync lag (inherited-permission changes may need explicit refresh);
- chunk-level ACL propagation;
- multi-user and agent contexts (participant-aware rules);
- recall loss from filtered ANN.

RAG adds leakage channels beyond the ACL: membership inference (about 30 natural queries, under $0.02 per document), extraction of the datastore, and embedding inversion (92% exact reconstruction of 32-token inputs). PII should be redacted or classified before indexing (Presidio-class tools, with no completeness guarantee). Retrieval should be logged immutably (OWASP), including citations, so that "what did the agent read" can be answered.

### Cited Findings

**Permission-aware retrieval**
- Azure AI Search (vendor, Sept 2026) offers four approaches:
  - security filters (GA; string group IDs in a `Collection(Edm.String)` field queried with `search.in`, which gives "subsecond response times" vs slow OR-chains; the principal "is just a string" with no authentication);
  - POSIX-like ACL/RBAC scopes from ADLS Gen2 and Blob (preview);
  - Microsoft Purview sensitivity labels (preview; single-tenant, RBAC only);
  - SharePoint ACLs (preview).

  Query-time enforcement takes the user's Entra token in `x-ms-query-source-authorization` and compares its claims with indexed permission metadata. If documents are chunked, ACL and label fields must be *projected to each chunk*: "Without this projection, chunk-level references aren't filtered." Label metadata is also returned to agents via the MCP `knowledge_base_retrieve` tool — [Azure AI Search document-level access overview](https://learn.microsoft.com/en-us/azure/search/search-document-level-access-overview); [Azure security filter pattern](https://learn.microsoft.com/en-us/azure/search/search-security-trimming-for-azure-search)
- Microsoft 365 Copilot (vendor): "only surfaces organizational data to which individual users have at least view permissions", and the "Semantic Index honors the user identity-based access boundary". Purview-encrypted content honors usage rights. The vendor stresses that customers must fix their own permission models, so oversharing in the source becomes oversharing in the agent — [Microsoft Learn: Data, Privacy, and Security for Microsoft Copilot (updated Nov 2026)](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-privacy)
- Glean (vendor) connectors sync source ACLs and enforce them at query time. SharePoint uses webhooks and `/delta` permission scans for "near real-time" permission changes. Some connectors (e.g., Salesforce, OneDrive real-time layer) query the source live per user instead of relying only on the index — [Glean: connectors power Glean (vendor docs)](https://docs.glean.com/connectors/connectors-power-glean); [Glean SharePoint connector (vendor docs)](https://docs.glean.com/connectors/native/sharepoint/about)
- "Enterprise AI Must Enforce Participant-Aware Access Control" (Bhatt et al., Microsoft Research, 2025) demonstrates exfiltration through fine-tuning and RAG when access control is absent. It argues prompt sanitization, output filtering and similar defenses "are fundamentally probabilistic". The principle: content used in training, retrieval or generation must be "explicitly authorized for all users involved in the interaction". The authors state it is deployed in Microsoft Copilot Tuning — [arXiv:2509.14608](https://arxiv.org/abs/2509.14608)
- Policy-aware vector search (Yalamarthi & Pappachan, 2026) formalizes fine-grained access control for vector DBs. It names the tension between correct policy enforcement, ANN recall and latency (pre-filter vs post-filter vs partitioned indexes), and lists open challenges — [Policy-aware Vector Search, arXiv:2606.19803](https://arxiv.org/abs/2606.19803)
- SD-RAG (Al Masoud et al., 2026) applies sanitization and disclosure controls *at retrieval time*, using human-readable policies over a graph data model, instead of trusting the generator. It reports up to 58% privacy-score improvement and resilience to prompt injection (author-reported) — [SD-RAG, arXiv:2601.11199](https://arxiv.org/abs/2601.11199)

**Leakage and inference attacks**
- Zeng et al. (ACL Findings 2024; arXiv 2024) give empirical evidence that RAG leaks its private retrieval database through targeted prompts, while RAG can *reduce* leakage of LLM training data — [The Good and The Bad, arXiv:2402.16893](https://arxiv.org/abs/2402.16893)
- Membership inference on RAG (Anderson, Amit & Goldsteen, IBM; ICISSP 2025) works with prompts in black- and gray-box settings. An instruction-based defense in the RAG template was effective for some datasets and models — [Is My Data in Your Retrieval Database?, arXiv:2405.20446](https://arxiv.org/abs/2405.20446)
- Interrogation Attack (Naseh et al., 2025) uses natural questions answerable only if the target document is present. It succeeds with about 30 queries, costs "less than $0.02 per document inference", doubles TPR@1%FPR over prior attacks, and is about 76× less detectable than earlier adversarial prompts — [Riddle Me This!, arXiv:2502.00306](https://arxiv.org/abs/2502.00306)
- MIA detection (Choi et al., EMNLP Findings 2025): MIA queries are highly similar to exactly one document, so a "detect-and-hide" similarity defense obfuscates attackers while keeping utility — [Is This Query Too Close to Home?, arXiv:2505.22061](https://arxiv.org/abs/2505.22061)
- Differentially private RAG (Koga, Wu, Zhang & Chaudhuri, UCSD, 2024) spends privacy budget only on tokens needing sensitive info. It beats non-RAG at ε≈10, which is a weak guarantee in practice — [DP RAG, arXiv:2412.04697](https://arxiv.org/abs/2412.04697)
- Embedding inversion (Vec2Text; Morris et al., EMNLP 2023) iteratively recovers 92% of 32-token inputs exactly and recovers full names from clinical notes. An independent reproduction (Seputis et al., RecSys 2025) confirmed the results under ideal conditions, found sensitivity to sequence length, and showed quantization and Gaussian noise mitigate it. Embeddings are therefore sensitive data — [Text Embeddings Reveal (Almost) As Much As Text, arXiv:2310.06816](https://arxiv.org/abs/2310.06816); [Reproducibility study, arXiv:2507.07700](https://arxiv.org/abs/2507.07700)
- SoK on RAG privacy (Bodea et al., TUM, 2026) offers a systematic review, a taxonomy of RAG privacy risks, and a process diagram mapping mitigations and their maturity — [SoK: Privacy Risks and Mitigations in RAG, arXiv:2601.03979](https://arxiv.org/abs/2601.03979)
- Unlearning via the KB (Wang et al., 2024): modifying the RAG knowledge base can simulate "forgetting" for closed models. Conversely, deleting a document from the KB (and its vectors and caches) is the main lever for erasure requests in RAG — [When Machine Unlearning Meets RAG, arXiv:2410.15267](https://arxiv.org/abs/2410.15267)

**PII redaction, residency, auditing**
- Presidio (originally Microsoft, now community-owned under the Data Privacy Stack) has an Analyzer (NER + regex + rule logic + checksums + context), an Anonymizer (operators incl. replace, redact, encrypt, pseudonymize), an image redactor and a structured-data module. Explicit caveat: "there is no guarantee that Presidio will find all sensitive information" — [Presidio docs](https://presidio.dataprivacystack.org/)
- Data residency example (vendor): M365 Copilot became a covered workload in Microsoft's data-residency commitments on March 1, 2024. EU traffic stays inside the EU Data Boundary, but "Models provided by Anthropic as a subprocessor are currently excluded from the EU Data Boundary". Residency therefore depends on *which model* serves a request, not only where the index lives — [Microsoft Learn: Copilot privacy](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-privacy)
- Auditing (vendor): Copilot stores each prompt and response "including citations to any information used to ground Copilot's response". Admins can search it with Purview/eDiscovery and set retention. OWASP LLM08 recommends "detailed, immutable logs of retrieval activity" to detect suspicious behavior — [Microsoft Learn: Copilot privacy](https://learn.microsoft.com/en-us/copilot/microsoft-365/microsoft-365-copilot-privacy); [OWASP LLM08:2025](https://genai.owasp.org/llmrisk/llm082025-vector-and-embedding-weaknesses/)

### Inferences
- Required design for the toolkit:
  1. Carry source ACLs (principals, inheritance resolved) and sensitivity labels to *every chunk*.
  2. Enforce as a pre-filter in the retrieval engine using the caller's identity, never in the prompt.
  3. For multi-agent or multi-user sessions, intersect the permissions of all participants.
  4. Expose an ACL-staleness metric (time since last permission sync per source).
  5. Fail closed when ACL metadata is missing.
- Retrieval audit log record: query, principal(s), retrieved chunk IDs with version hashes, ACL decision, which chunks were cited, and the model used (for residency). This answers "what did the agent read" and supports MIA and poisoning forensics (demand anomalies, per §3).
- PII handling: classify and redact at ingestion for low-sensitivity indexes. Keep raw PII only in ACL-restricted partitions. Treat vectors as equally sensitive as the text (Vec2Text). Deletion must cascade from source to chunks, vectors, caches and eval sets.

### Gaps
- No independent benchmark of permission-aware ANN (recall/latency under selective filters) across vector DBs was found. The 2026 vision paper says the area is still open.
- No measured data on ACL-sync lag in production systems. Vendors document mechanisms, not SLAs.
- Little evidence on how well PII redaction holds up for RAG chunks (vs whole documents), or on re-identification across chunks.

## 5. Evaluation of knowledge bases and retrieval for agents: RAGAS, ARES, RAGChecker, TruLens, CRAG, synthetic test sets, LLM-as-judge reliability, knowledge-gap detection, coverage, and human curation (KCS)

### Takeaway
Use a layered evaluation stack:
- (a) component metrics on a versioned golden set: context precision/recall, faithfulness/groundedness, answer correctness;
- (b) claim- or nugget-level diagnostics (RAGChecker, AutoNuggetizer) that separate retrieval misses from generator errors;
- (c) statistically calibrated LLM judges (ARES with prediction-powered inference on about 150–300 human labels);
- (d) production signals: unanswered or abstained queries, low-groundedness answers, reuse and link accuracy as in KCS.

LLM judges agree with humans at the system level, but they are biased in known ways: query-term stuffing fools relevance labels, self-preference, position bias. TREC's own leadership warns against replacing human judgments. Synthetic test sets are cheap but low-diversity unless persona and question-type distributions are controlled (DataMorgana). "Sufficient context" classification turns failures into an actionable split: KB gap vs model failure.

### Cited Findings

**Frameworks**
- RAGAS (Es, James, Espinosa-Anke & Schockaert; EACL 2024 demo; arXiv 2023) is a reference-free suite: faithfulness, answer relevance, context relevance (later context precision/recall), with LLM-computed metrics needing no human labels — [Ragas, arXiv:2309.15217](https://arxiv.org/abs/2309.15217)
- Ragas testset generation (OSS docs) builds a knowledge graph over chunks (splitters, LLM or rule extractors such as entities and keyphrases, relationship builders using e.g. entity Jaccard). It then synthesizes single-hop/multi-hop × specific/abstract queries from scenarios (nodes, length, style, persona). The docs do not describe how generated-query quality is validated — [Ragas test data generation docs](https://docs.ragas.io/en/stable/concepts/test_data_generation/rag/)
- ARES (Saad-Falcon, Khattab, Potts & Zaharia, Stanford; NAACL 2024) works as follows. FLAN-T5 XXL generates synthetic queries and answers, kept only if the retriever returns the source passage. Three DeBERTa-v3-Large judges score context relevance, answer faithfulness and answer relevance. Prediction-powered inference (PPI) over human labels gives 95% CIs: at least about 150 labels are needed, 300 were used, and average CI width was 6–7 points. Kendall τ beat RAGAS by 0.16 (context relevance) and 0.15 (answer relevance) on real systems, with 78% fewer annotations than sampling alone. Cost: about 32GB GPU and several hours of fine-tuning — [ARES, arXiv:2311.09476](https://arxiv.org/abs/2311.09476); PPI theory: [Angelopoulos et al., Prediction-Powered Inference, Science 2023, arXiv:2301.09633](https://arxiv.org/abs/2301.09633)
- RAGChecker (Ru et al., Amazon; NeurIPS 2024 D&B; arXiv 2024) extracts claims and checks entailment (Llama3-70B via RefChecker). Overall claim precision, recall and F1. Retriever: claim recall and context precision. Generator: faithfulness, relevant/irrelevant noise sensitivity, hallucination, self-knowledge and context utilization. Meta-evaluation on 280 pairwise instances from 8 systems in 10 domains (inter-annotator agreement 90.95%), Pearson with human overall preference: RAGChecker 61.93, RAGAS answer similarity 48.31, TruLens answer relevance 35.15, ARES answer relevance 17.81, human upper bound 70.09. These are author-run comparisons. Limitations: English text only; the checker does not separate "neutral" from "contradiction" — [RAGChecker, arXiv:2408.08067](https://arxiv.org/abs/2408.08067)
- TruLens "RAG triad" (OSS; Snowflake/TruEra): context relevance (query↔chunk), groundedness (response claims supported by context), answer relevance (response↔query). The docs say passing all three means the app is hallucination-free "up to the limits of its knowledge base". The triad does *not* check that the KB itself is correct or current — [TruLens RAG triad](https://www.trulens.org/getting_started/core_concepts/rag_triad/)
- eRAG (Salemi & Zamani, SIGIR 2024) labels each retrieved document by the downstream task score the LLM gets using that document alone. Kendall τ with end-to-end RAG quality improves by 0.168–0.494 over relevance-label metrics, using up to 50× less GPU memory. Query-document relevance labels correlate weakly with RAG outcomes — [eRAG, arXiv:2404.13781](https://arxiv.org/abs/2404.13781)
- AutoNuggetizer (Pradeep et al., Waterloo/Microsoft, TREC 2024 RAG Track): LLMs create "nuggets" (atomic facts a good answer must contain) and assign them to answers. Run-level scores show strong agreement with manual nugget evaluation (21 topics, 45 runs initially, then community-wide). Per-topic agreement is weaker, so the authors say further work is needed to diagnose individual failures — [Initial Nugget Evaluation Results, arXiv:2411.09607](https://arxiv.org/abs/2411.09607); [The Great Nugget Recall, arXiv:2504.15068](https://arxiv.org/abs/2504.15068)
- FActScore (Min et al., EMNLP 2023) gives the share of atomic facts supported by a knowledge source. Its estimator has under 2% error, and evaluating 6,500 generations by humans would have cost $26K — [FActScore, arXiv:2305.14251](https://arxiv.org/abs/2305.14251)
- RAGTruth (Niu et al., ACL 2024) has about 18,000 RAG responses with word-level hallucination annotations. A fine-tuned small model is competitive with GPT-4 prompting for detection — [RAGTruth, arXiv:2401.00396](https://arxiv.org/abs/2401.00396)
- Lynx (Patronus AI, 2024) is an open hallucination (faithfulness) judge plus HaluBench (15k samples). It outperforms GPT-4o and Claude-3-Sonnet judges on HaluBench (vendor-authored benchmark) — [Lynx, arXiv:2407.08488](https://arxiv.org/abs/2407.08488)
- Trust-Score / Trust-Align (Song et al., ICLR 2025; arXiv 2024) jointly measures grounded answers, citation quality and *correct refusal* when context is insufficient — [Trust-Score, arXiv:2409.11242](https://arxiv.org/abs/2409.11242)
- Surveys of RAG evaluation (Yu et al., 2024; Gan et al., 2025) catalog datasets, metrics and frameworks, with a meta-analysis of evaluation practice — [Evaluation of RAG: A Survey, arXiv:2405.07437](https://arxiv.org/abs/2405.07437); [RAG Evaluation in the Era of LLMs, arXiv:2504.14891](https://arxiv.org/abs/2504.14891)
- InspectorRAGet (IBM, 2024) is an introspection platform for aggregate and instance-level RAG evaluation with human and algorithmic metrics — [InspectorRAGet, arXiv:2404.17347](https://arxiv.org/abs/2404.17347)

**Benchmarks and synthetic test sets**
- CRAG (above, §1) uses a truthfulness score that penalizes hallucination more than missing answers. Its LLM auto-evaluators reach 94.7–98.9% average F1 against human labels — [CRAG, arXiv:2406.04744](https://arxiv.org/abs/2406.04744)
- DataMorgana (Filice et al., TII, 2025) generates synthetic Q&A with configurable user and question categories and distributions. It produces more lexically, syntactically and semantically diverse question sets than existing tools, and was used for the SIGIR 2025 LiveRAG challenge — [DataMorgana, arXiv:2501.12789](https://arxiv.org/abs/2501.12789)
- LiveRAG (SIGIR 2025): 70 teams, 500 unseen questions, fixed corpus (FineWeb-10BT) and LLM. Evaluation used LLM-as-judge correctness and faithfulness first, then *manual review of top submissions*. This is a hybrid human/LLM protocol — [LiveRAG Challenge Report, arXiv:2507.04942](https://arxiv.org/abs/2507.04942)
- RAGProbe (Sivasothy et al., 2024) generates evaluation scenarios automatically to probe RAG pipelines for failures — [RAGProbe, arXiv:2409.19019](https://arxiv.org/abs/2409.19019)
- Seven failure points (Barnett et al., ICSE-CAIN 2024; three case studies) include missing content (the KB does not contain the answer), missed top-ranked documents, not in context, not extracted, wrong format, wrong specificity and incomplete. Key lesson: "validation of a RAG system is only feasible during operation" — [Seven Failure Points, arXiv:2401.05856](https://arxiv.org/abs/2401.05856)

**LLM-as-judge reliability**
- Thomas et al. (Microsoft Bing, SIGIR 2024; arXiv 2023): LLM relevance labels prompted to match careful first-party user feedback were as accurate as human labellers "for a fraction of the cost". But "simple paraphrases" of prompts change accuracy — [LLMs can accurately predict searcher preferences, arXiv:2309.10621](https://arxiv.org/abs/2309.10621)
- UMBRELA (Upadhyay et al., Waterloo/Microsoft, 2024) is an open reproduction with GPT-4o. LLM labels correlate highly with system rankings on TREC DL 2019–2023, and it was used in TREC 2024 RAG — [UMBRELA, arXiv:2406.06519](https://arxiv.org/abs/2406.06519)
- Counterpoint: Soboroff (NIST; IRRJ 2025) says "don't use LLMs to create relevance judgments for TREC-style evaluations". A TREC track normally takes about six trained contractors for 2–4 weeks — [Don't Use LLMs to Make Relevance Judgments, arXiv:2409.15133](https://arxiv.org/abs/2409.15133)
- Alaofi et al. (SIGIR-AP 2024) find that LLMs label relevant more often than humans. Injecting query words into irrelevant passages fools them, and instructions such as "this paper is perfectly relevant" manipulate some models. "Non-relevance" labels are more reliable than "relevant" labels — [LLMs can be Fooled, arXiv:2501.17969](https://arxiv.org/abs/2501.17969)
- Position bias (Wang et al., ACL 2024): changing answer order let Vicuna-13B "beat" ChatGPT on 66 of 80 queries. Mitigations: multiple-evidence calibration, balanced position swapping, and human-in-the-loop for uncertain cases — [LLMs are not Fair Evaluators, arXiv:2305.17926](https://arxiv.org/abs/2305.17926)
- Self-preference (Wataoka et al., 2024): GPT-4 prefers lower-perplexity, familiar text, regardless of whether it wrote it — [Self-Preference Bias, arXiv:2410.21819](https://arxiv.org/abs/2410.21819)
- MT-Bench / Chatbot Arena (Zheng et al., NeurIPS 2023 D&B): strong LLM judges reach over 80% agreement with humans, about human-human level, but position, verbosity and self-enhancement biases are documented — [Judging LLM-as-a-Judge, arXiv:2306.05685](https://arxiv.org/abs/2306.05685)
- LLM-as-a-Judge survey (Gu et al., 2024) covers reliability strategies (consistency, bias mitigation) and meta-evaluation — [A Survey on LLM-as-a-Judge, arXiv:2411.15594](https://arxiv.org/abs/2411.15594)

**Knowledge-gap detection and coverage**
- Sufficient context (Joren et al., Google, ICLR 2025; arXiv 2024): an autorater classifies whether retrieved context is enough to answer. Large models answer well with sufficient context but "often output incorrect answers instead of abstaining" when it is insufficient. Guided abstention using the sufficiency signal improves correct-when-answering by 2–10%. Applied to production logs, "insufficient context" queries form the KB content-gap backlog — [Sufficient Context, arXiv:2411.06037](https://arxiv.org/abs/2411.06037)
- CRAG's scoring and RealTime QA both stress that systems should *detect unanswerable cases* rather than answer from stale or insufficient context — [CRAG, arXiv:2406.04744](https://arxiv.org/abs/2406.04744); [RealTime QA, arXiv:2207.13332](https://arxiv.org/abs/2207.13332)
- KCS Knowledge Domain Analysis outputs "Content gaps: knowledge people are looking for that does not exist", alongside content overlaps (duplicates), archiving strategy and pervasive issues. Success is measured by findability, self-service success and incident reduction — [KCS v6 Technique 5.9](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/060)

**Human curation workflow: KCS (Consortium for Service Innovation)**
- KCS v6 structure: the *Solve Loop* (Capture, Structure, Reuse, Improve; "Search Early Search Often", "Reuse is Review", "Flag It or Fix It", "License to Modify") and the *Evolve Loop* (Content Health, Process Integration, Performance Assessment, Leadership & Communication). "The Solve Loop and Evolve Loop are interdependent" — [KCS v6 Evolve Loop](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040)
- Content Standard Checklist (formerly Article Quality Index) has six yes/no checks: Unique, Complete, Clear, Title relates, Links valid, Metadata correct. Errors are weighted 2×. Below 90% triggers coaching, and consistently below 80% puts the KCS license at risk. Random sampling by coaches is weekly during rollout and monthly when mature ("only a few hours per reviewer each month"). Targets: link rate above 60%, link accuracy above 90%, and "Reuse accuracy is more important than reuse rate". Content types: experience-based (high variability tolerance) vs compliance-based (no tolerance for interpretation). A Consortium survey found articles need to be "sufficient to solve"; technical accuracy and findability are "very important", editorial items less so — [KCS v6 Technique 5.10 Content Health Indicators](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/065)
- Article structure: Issue (in the requestor's words), Environment, Resolution, Cause. System-managed metadata covers dates, versions, reuse counts and editors. Explicit "audience, quality, and governance attributes" plus the licensing model control who sees and edits — [KCS v6 Practice 5 Content Health](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010); [KCS v6 Technique 5.1 Article Structure](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/020)

### Inferences
- For agent KBs, map KCS signals to automated equivalents:
  - "reuse" → a chunk cited in an answer that was accepted, not escalated;
  - "link accuracy" → groundedness plus correctness of answers citing the chunk (sampled human audit);
  - "flag it or fix it" → agent and user feedback creating review tickets on the chunk's owner;
  - "content gap" → queries with insufficient context, abstentions, or zero results above threshold.
- Evaluation cadence: (1) a per-change regression suite on the golden set at every KB or index change (cheap LLM-judge metrics); (2) weekly ARES-style PPI with about 150–300 fresh human labels to keep judge drift honest; (3) a monthly KCS-style human sample of KB articles for content-standard adherence.
- Use claim/nugget diagnostics to route failures. Low claim recall plus insufficient context means a KB gap: create content. Context present but unused means a generator or prompt problem. Wrong claims sourced from a chunk mean bad content: fix or supersede the chunk.
- Never let a judge model grade its own family's outputs alone (self-preference). Swap positions. Watch for query-term stuffing in content written to "please" retrievers (Alaofi et al.), which also overlaps with poisoning.

### Gaps
- No benchmark directly evaluates *knowledge base quality* (coverage, consistency, staleness) independent of a QA system. Coverage benchmarks (CoverageBench) are emerging but not KB-maintenance-oriented.
- No public data quantifies KCS-for-RAG outcomes (e.g., agent answer accuracy before and after adopting KCS content health). KCS evidence is practitioner, survey and Consortium-reported.
- Comparisons between frameworks (RAGChecker vs RAGAS vs ARES) are author-run. No neutral 2026 meta-evaluation was found.

## 6. The most effective lifecycle and QA process, with cost

### Takeaway
The evidence supports a *governed, event-driven lifecycle*:
- ingest via hashed incremental sync;
- QA gates at write time (dedup, PII and hidden-text scan, ACL completeness, authority and validity metadata, contradiction check against neighbors);
- serve with validity, ACL and authority filters plus conflict flags;
- monitor with a layered eval stack and production gap signals;
- curate with KCS-style owners, review intervals scaled to volatility, and supersede-not-delete versioning.

Most of the cost is one-time embedding and LLM enrichment plus ongoing human review. The automated QA gates are cheap relative to the cost of errors: stale and conflicting content measurably flips answers.

### Cited Findings (cost and effectiveness anchors)
- Incremental sync cost: only changed docs are re-embedded. A metadata-only change can avoid embedding calls entirely on Bedrock — [AWS Bedrock sync docs (vendor)](https://docs.aws.amazon.com/bedrock/latest/userguide/kb-data-source-sync-ingest.html); [LangChain indexing API](https://reference.langchain.com/python/langchain-core/indexing/api/index)
- Embedding-upgrade cost: an adapter bridge is reportedly over 100× cheaper than full re-embedding and recovers 95–99% of recall (author-reported) — [Drift-Adapter, arXiv:2509.23471](https://arxiv.org/abs/2509.23471)
- Redundancy pruning: 25–36% index reduction (entity-based chunk filtering) and 30% corpus pruning with 22% faster retrieval (Zero-RAG) — [arXiv:2604.24334](https://arxiv.org/abs/2604.24334); [arXiv:2511.00505](https://arxiv.org/abs/2511.00505)
- Contradiction-audit cost: a cascade classifier plus LLM cut API cost 62% at 90.8% detection accuracy (author-reported) — [ConflictRAG, arXiv:2605.17301](https://arxiv.org/abs/2605.17301)
- Evaluation labeling cost: ARES needs about 150–300 human labels per evaluation (78% fewer than sampling) but about 32GB GPU and hours of fine-tuning. FActScore estimates $26K for human evaluation of 6,500 generations vs near-zero automated. A TREC track takes about six contractors for 2–4 weeks. RAGChecker's human meta-eval paid annotators about $255 — [ARES](https://arxiv.org/abs/2311.09476); [FActScore](https://arxiv.org/abs/2305.14251); [Soboroff](https://arxiv.org/abs/2409.15133); [RAGChecker](https://arxiv.org/abs/2408.08067)
- Human curation cost: KCS mature-state sampling takes "a few hours per reviewer each month". Guru-style verification queues route expired items to named owners — [KCS 5.10](https://library.serviceinnovation.org/KCS/KCS_v6/KCS_v6_Practices_Guide/030/040/010/065); [Guru (vendor)](https://www.getguru.com/features/verification)
- Cost of *not* doing it:
  - one outdated passage drops Llama-3.1-70B from 89 to 73 score with about 10% harmful answers (HoH);
  - outdated docs flip 17–91% of correct answers (Stale-Document Poisoning);
  - misleading retrievals put RAG below zero-shot (RAGuard);
  - 5 poisoned passages give about 90–99% ASR (PoisonedRAG);
  - membership inference costs an attacker under $0.02 per document (Interrogation Attack).

  Sources: [HoH](https://arxiv.org/abs/2503.04800); [Stale-Document Poisoning](https://arxiv.org/abs/2609.31342); [RAGuard](https://arxiv.org/abs/2502.16101); [PoisonedRAG](https://arxiv.org/abs/2402.07867); [Riddle Me This](https://arxiv.org/abs/2502.00306)
- RAG robustness "evolves rather than [is] designed in at the start", and validation is only feasible during operation, which supports continuous monitoring over one-off launch QA — [Seven Failure Points, arXiv:2401.05856](https://arxiv.org/abs/2401.05856)

### Inferences: recommended lifecycle and QA design for the toolkit

**Data model (per chunk, inherited from the document):** `doc_id`, `version`, `content_sha256`, `source_system`, `source_uri`, `canonical_ref`, `owner`, `authority_tier` (e.g., 1 = system of record or approved policy … 4 = user-generated or external), `approval_state` (draft / not_validated / validated / superseded / retired, analogous to KCS states), `effective_from`, `effective_to`, `supersedes` / `superseded_by`, `review_due` (from a volatility class), `last_verified_at`, `acl_principals` + `acl_synced_at`, `sensitivity_label`, `pii_flags`, `lineage` (parser/model versions), `embedding_model_version`.

**Lifecycle stages and gates**
1. *Ingest (event-driven)*: connectors emit add/modify/delete plus permission-change events. Content hash and record manager skip unchanged items, and a full-sync reconciliation runs periodically to catch missed deletes (LangChain `full` or `scoped_full` semantics).
2. *Write-time QA gates* (block, or quarantine to `not_validated`):
   - exact or near-duplicate check (SHA-256, then MinHash-LSH or SimHash), linking to the canonical copy;
   - version-chain detection (same `doc_id` or title lineage → new version, set `supersedes`);
   - PII scan and redaction (Presidio-class) plus hidden-text scan;
   - ACL completeness (fail closed);
   - required validity metadata for rules, policies and SOPs;
   - contradiction check of new chunks against top-k neighbors (BM25 + dense candidates, then a classifier, then an LLM judge) routed to the owner;
   - source allow-list and authority tier, with external or user content quarantined (poisoning).
3. *Serve*: pre-filter by ACL (all participants), `approval_state ∈ {validated, not_validated-with-label}` and validity window (default "now", with "as-of" queries allowed). Rank by relevance with authority and recency priors. Pass validity, authority and `superseded_by` text to the generator. Set a conflict flag when top-k disagree. For high-stakes rule answers, use isolate-then-aggregate. Log retrieval and citation events immutably.
4. *Monitor*:
   - per-change regression on a golden set (RAGAS/RAGChecker-style metrics plus conflict and temporal probes modeled on HoH, WikiContradict and RAGuard);
   - weekly PPI-calibrated judge audit (ARES);
   - production dashboards: insufficient-context rate, abstention rate, groundedness, citation-acceptance ("reuse"), queries per chunk (demand anomalies for poisoning), staleness (% past `review_due`) and ACL-sync lag.
5. *Curate (KCS-style)*: owners get queues for expired reviews, contradiction tickets, user and agent flags, and content-gap clusters from insufficient-context queries. Monthly sampled content-standard checks. Supersede rather than delete, keeping history for audit and "as-of" queries. Hard-delete only for erasure or legal requests, cascading to vectors, caches and eval sets.

**Rough cost model (inference from the anchors above; illustrative, not measured):** the dominant costs are (1) initial embedding plus LLM enrichment of the corpus (one-time), (2) re-embedding only changed documents (proportional to churn, often a few percent per month), (3) LLM contradiction checks only on new or changed chunks against about 5–10 neighbors with a cheap-classifier pre-filter, (4) about 150–300 human labels per weekly PPI audit, and (5) a few reviewer-hours per domain per month for KCS sampling plus owner time on review queues. Items 1–3 scale with churn, not corpus size, which is the main argument for hash-based incremental pipelines.

### Gaps
- No end-to-end published study compares lifecycle designs (e.g., "rank old content down" vs "hard-filter superseded content") on enterprise agent KBs with total cost of ownership. The design above is synthesized from component evidence.
- Little public data exists on real enterprise KB churn rates, which drive re-embedding and re-check costs.
- No standard schema exists for KB validity and authority metadata comparable to data contracts for tables. Each vendor (Guru verification, KCS states, Azure labels) uses its own.
