# Reading, synthesis and citation in LLM research agents (what happens after a search result is chosen)

Scope: fetch, extract, read long pages within context limits, compress/take notes, cite, verify, and the read-side security and cost profile. Search backends, the agent loop itself, coding agents and ranking signals are covered by other tracks. Status as of November 2026; older items are marked with their year. "Vendor-reported" = numbers published by the company that sells the system; "independent" = third-party audit or academic study.

Framing finding for the whole track: none of the mainstream systems turn the web into a local vector DB. The pattern is (1) a hosted search index returns URLs + snippets, (2) the agent fetches a small number of chosen pages at query time, (3) the page is converted to text/markdown and is then either read whole, truncated, filtered by code, chunked and scored against the query on the fly, or summarized by a sub-model against a "goal", (4) condensed evidence (quotes, notes, summaries) is kept while raw page text is cleared or compacted, and (5) citations are attached either natively (span-level pointers into the fetched document) or by a separate citation pass. Measured citation accuracy for this pipeline is still well below 100% in every independent audit.

## 1. Fetching and extraction: how agents get page text (HTTP vs headless browser, HTML-to-markdown, PDFs, JS pages, paywalls/robots)

### Takeaway
Vendor "fetch" tools are mostly plain server-side HTTP fetchers with caching that return cleaned text (or the raw PDF), and they explicitly do not render JavaScript; full headless/visual browsers are a separate, heavier tool used when a page needs rendering or interaction. Open-source stacks (Readability, Trafilatura, Jina Reader, Firecrawl, Crawl4AI) do the HTML-to-markdown step, and benchmarks show main-content extraction is good but imperfect (best F1 around 0.92 on the Trafilatura benchmark; no single extractor wins on all page types).

### Cited Findings
**Vendor fetch/read tools (official docs, Nov 2026)**
- Anthropic `web_fetch` is a server tool: "The API retrieves the full text content from the specified URL"; for PDFs it returns base64 data processed like an attached PDF; it "currently does not support websites dynamically rendered with JavaScript" and points users to a separate browser-use tool for pages that need rendering, clicking or forms. Supported content types are only text, HTML and PDF (`unsupported_content_type` otherwise). — [Anthropic web fetch tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)
- Anthropic `web_fetch` controls: `max_uses`, `allowed_domains`/`blocked_domains`, `max_content_tokens` (truncates content beyond the limit; text only, not PDFs), optional citations (off by default), results are cached ("content returned might not always reflect the latest version"), `use_cache: false` bypass in `web_fetch_20260309`+, and `url_not_allowed` covers private addresses and `robots.txt`. URL length limit 250 characters. — [Anthropic web fetch tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)
- Anthropic's token rule of thumb for fetched content: average webpage (10 kB) ~2,500 tokens; large documentation page (100 kB) ~25,000 tokens; research-paper PDF (500 kB) ~125,000 tokens. — [Anthropic web fetch tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)
- Anthropic web search results return only `url`, `title`, `page_age` and an opaque `encrypted_content` blob that must be passed back in multi-turn conversations; citations from search results carry up to 150 characters of `cited_text`. — [Anthropic web search tool docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)
- OpenAI's Responses API `web_search` tool exposes three action types: `search`, `open_page` and `find_in_page` (the latter two "supported in reasoning models"); `external_web_access: false` runs a cache-only (offline) search; the web-search context window is capped at 128k regardless of the model's larger window. — [OpenAI web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)
- Google Gemini URL Context tool first checks "an internal index cache, which is optimized for speed" and falls back to a live fetch for pages not in the index; up to 20 URLs per request, max 34 MB per URL; supports HTML/JSON/text/XML/CSV/RTF, PNG/JPEG/BMP/WebP images and PDF; does not support paywalled content, YouTube, Google Workspace files, video/audio; "The model won't follow nested links." — [Gemini URL context docs](https://aistudio.google.com/docs/url-context)
- OpenAI Codex (the coding agent the user asked about) defaults `web_search` to `"cached"`, which "uses an OpenAI-maintained index without external web access"; other modes are `indexed` (external access only when gated by the search index), `live` (unrestricted; default under `--yolo`/full-access sandboxes) and `disabled`. — [Codex config reference](https://learn.chatgpt.com/docs/config-file/config-reference); the docs add cached mode "lowers—but doesn't remove—prompt injection risk" and to "Treat all web results as untrusted input." — [Codex web search docs](https://learn.chatgpt.com/docs/web-search)
- ChatGPT agent (launched July 17, 2025) has both a visual (GUI) browser and a text-based browser plus a terminal; "The model can choose to open a page using the text browser or visual browser." — [VentureBeat, 2025](https://venturebeat.com/ai/openai-unveils-chatgpt-agent-that-gives-chatgpt-its-own-computer-to-autonomously-use-your-email-and-web-apps-download-and-create-files-for-you)
- A 2025 survey of deep research agents organizes information acquisition into API-based retrieval vs browser-based exploration as the two basic strategies. — [Huang et al., Deep Research Agents: A Systematic Examination And Roadmap, 2025](https://arxiv.org/abs/2506.18096)
- OpenAI deep research (Feb 2025) was trained via RL on browsing tasks to learn "searching, clicking, scrolling, interpreting files" and reads "text, images, and PDFs". — [OpenAI Deep Research System Card, 2025](https://cdn.openai.com/deep-research-system-card.pdf)

**PDF handling**
- Claude converts each PDF page into an image and extracts the text of each page, providing both; text costs ~1,500–3,000 tokens per page plus image tokens; limits 600 pages per request (100 when context window <1M) and 128 MB request size; scanned PDFs without extractable text are not citable. — [Anthropic PDF support docs](https://platform.claude.com/docs/en/build-with-claude/pdf-support); [Anthropic Citations docs](https://platform.claude.com/docs/en/build-with-claude/citations)
- OpenAI's API likewise "extracts both the text and an image of each page" of a PDF and sends both to a vision-capable model; files must be under 50 MB per request. — [OpenAI PDF files guide](https://developers.openai.com/api/docs/guides/pdf-files)
- Open-source PDF converters used in agent stacks include Docling (MIT-licensed, layout analysis via DocLayNet and table structure via TableFormer, 2024). — [Auer et al., Docling Technical Report, 2024](https://arxiv.org/abs/2408.09869)

**HTML-to-text/markdown extractors**
- Mozilla Readability.js (the Firefox Reader View engine) needs a DOM (jsdom in Node), returns `title`, `content`, `textContent`, `excerpt`, `byline`, etc.; its output is not sanitized ("explicitly not something we aim to do"), Apache-2.0. — [mozilla/readability GitHub](https://github.com/mozilla/readability)
- Trafilatura project benchmark (run 2026-10-02, 990 documents): trafilatura 2.3.0 F1 0.926 (P 0.906 / R 0.946) vs readability-lxml 0.853, jusText 0.862, news-please 0.836, goose3 0.810, newspaper4k 0.803, boilerpy3 0.807, html2text 0.663 (html2text keeps boilerplate: precision 0.525). Note: this is the tool author's own benchmark. — [Trafilatura evaluation docs](https://trafilatura.readthedocs.io/en/latest/evaluation.html)
- Independent reproducibility study (SIGIR 2023): Bevendorff et al. reproduced 14 main-content extractors and 5 baselines on 8 combined datasets (3,985 pages); code/data released. A related thesis reports that no single algorithm beats the rest and the best one depends on page complexity (I could not confirm that conclusion is stated in the SIGIR paper itself). — [Bevendorff et al., SIGIR 2023 (dblp)](https://dblp.org/rec/conf/sigir/BevendorffGK023.html)
- Jina Reader (`r.jina.ai/<url>`): default engine is a headless browser so client-side JS runs; `X-Engine: direct` is plain HTTP; removes nav/headers/footers/ads and converts to Markdown (via Turndown); CSS selector controls (`X-Target-Selector`, `X-Wait-For-Selector`); native PDF support; optional image captioning; 5-minute cache; `s.jina.ai` returns top-5 search results with full content. — [Jina Reader page](https://jina.ai/reader/)
- ReaderLM-v2 (Jina, 2025): a 1.5B model that converts raw HTML (up to 512K tokens) into Markdown/JSON; authors report it beats GPT-4o by 15–20% on their curated benchmarks (author-reported). — [Wang et al., ReaderLM-v2, 2025](https://arxiv.org/abs/2503.01151)
- Firecrawl advertises handling "Proxies, anti-bot, JavaScript rendering, and dynamic content", outputs markdown/HTML/JSON/screenshots, plus Map, Crawl, Search, Parse (PDF/DOCX/XLSX) and Interact (click/fill) endpoints. — [Firecrawl docs](https://docs.firecrawl.dev/introduction)
- Crawl4AI produces `raw_markdown` and a "fit markdown" filtered version; `BM25ContentFilter` ranks page chunks against a `user_query` (default `bm25_threshold` 1.0), while `PruningContentFilter(LXML)` is a query-independent heuristic using text density, link density and tag importance. — [Crawl4AI fit markdown docs](https://docs.crawl4ai.com/core/fit-markdown/)

**Paywalls, robots.txt and crawler identity**
- OpenAI separates OAI-SearchBot (search index; respects robots.txt), GPTBot (training; respects robots.txt) and ChatGPT-User (user-initiated page visits; "robots.txt rules may not apply"). — [OpenAI crawlers docs](https://developers.openai.com/api/docs/bots)
- Cloudflare (Aug 4, 2025) reported Perplexity using undeclared crawlers impersonating Chrome on macOS and rotating IPs/ASNs to fetch content from sites that disallowed it (declared Perplexity-User 20–25M daily requests vs 3–6M stealth); by contrast ChatGPT-User fetched robots.txt and stopped when disallowed. — [Cloudflare blog, 2025](https://blog.cloudflare.com/perplexity-is-using-stealth-undeclared-crawlers-to-evade-website-no-crawl-directives/)
- Tow Center (Feb 2025 tests) found ChatGPT, Perplexity and Perplexity Pro answered queries about publishers that blocked their crawlers; Perplexity's free tier correctly identified all ten paywalled National Geographic excerpts despite being blocked; engines often cited syndicated/republished copies (e.g., Yahoo News copy of a USA Today article). — [CJR/Tow Center, March 2025](https://www.cjr.org/tow_center/we-compared-eight-ai-search-engines-theyre-all-bad-at-citing-news.php)

### Inferences
- The "read" step is cheap infrastructure (HTTP fetch + cache + boilerplate removal), not an index. Quality depends heavily on the extractor; even a 0.92 F1 extractor drops or keeps the wrong ~8% of segments, which propagates into citation errors.
- Because vendor fetchers skip JS and paywalls, agents substitute other copies (syndications, aggregators), which is one root cause of misattribution measured in Section 3.
- For a data-lake toolkit, the extraction stage (HTML/PDF to clean, span-addressable text with stable offsets) is where a pre-processed corpus can beat live agents: you can run the expensive extractor once, keep page/char offsets, and avoid JS/paywall failures.

### Gaps
- No vendor documents its exact extraction algorithm (OpenAI `open_page`, Gemini URL context, Anthropic `web_fetch` text cleaning are opaque).
- I found no independent benchmark of vendor fetch tools' failure rates (JS pages, timeouts, paywalls) on a common URL set.

## 2. Reading long pages within context: whole-page reading, just-in-time chunking/filtering, find-in-page, subagent summarization, compaction and memory

### Takeaway
Production systems read pages "just in time": they keep URLs as lightweight references and pull content only when needed, then shrink it before it enters the context through truncation, code-based filtering (Anthropic dynamic filtering), query-time chunk scoring (Jina DeepSearch, Crawl4AI BM25), goal-conditioned page summarization by a sub-model (Tongyi/WebSailor "visit"), or WebGPT-style quote collection. Long contexts degrade measurably (lost-in-the-middle, context rot, NoLiMa, RULER), so agents also clear old tool results, compact history and delegate reading to subagents that return 1–2k-token summaries.

### Cited Findings
**Just-in-time vs pre-indexing (the core contrast for the user's question)**
- Anthropic describes "just in time" context: agents "maintain lightweight identifiers (file paths, stored queries, web links, etc.)" and load data at runtime via tools, "Rather than pre-processing all relevant data up front"; it contrasts this with embedding-based pre-inference retrieval and recommends a hybrid ("retrieving some data up front for speed, and pursuing further autonomous exploration at its discretion"), which Claude Code uses (Sep 29, 2025). — [Anthropic, Effective context engineering for AI agents, 2025](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Jina DeepSearch (Mar 2025) does query-time chunking without a vector DB: fetched pages are split into ~500-token chunks, embedded with jina-embeddings-v3 (late chunking), cosine-scored against the query, and a sliding window picks the best contiguous span; "4–5 URLs are fetched per step, yielding hundreds of chunks", "manageable in memory without a vector database". Rationale: long web docs run ~200k tokens (p50) to ~1M tokens (p99) and dumping them is costly; contiguous snippets are easier to cite and reduce hallucination. — [Jina AI, Snippet selection and URL ranking in DeepSearch/DeepResearch, 2025](https://jina.ai/news/snippet-selection-and-url-ranking-in-deepsearch-deepresearch/)
- Anthropic dynamic filtering (Feb 17, 2026): `web_search_20260209`/`web_fetch_20260209` let Claude write and run code to filter fetched pages before they enter context, "rather than reasoning over raw HTML in context". Vendor-reported: across BrowseComp and DeepSearchQA ~11% average improvement with 24% fewer input tokens; BrowseComp Sonnet 4.6 33.3%→46.6%, Opus 4.6 45.3%→61.6%; DeepSearchQA F1 Sonnet 52.6→59.4, Opus 69.8→77.3; price-weighted tokens rose for Opus 4.6 because it writes more filtering code. — [Claude blog, Improved web search with dynamic filtering, 2026](https://claude.com/blog/improved-web-search-with-dynamic-filtering); [Anthropic web fetch docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)
- Crawl4AI's BM25ContentFilter is the open-source equivalent of query-time page filtering (keep only chunks relevant to `user_query`). — [Crawl4AI fit markdown docs](https://docs.crawl4ai.com/core/fit-markdown/)
- WebSailor (Alibaba Tongyi, 2025) "visit" tool: input is URLs plus a per-page "goal"; Jina retrieves full page content, then a summary model (Qwen-2.5-72B) "extracts relevant information based on the goal" — the agent only sees the goal-conditioned summary. — [Li et al., WebSailor, 2025](https://arxiv.org/abs/2507.02592)
- Search-o1 (2025) adds a separate "Reason-in-Documents" module because "of the verbose nature of retrieved documents", to analyze them before injecting into the reasoning chain. — [Li et al., Search-o1, 2025](https://arxiv.org/abs/2501.05366); WebThinker extends this with a "Deep Web Explorer" that navigates pages and an interleaved think-search-draft loop. — [Li et al., WebThinker, 2025](https://arxiv.org/abs/2504.21776)
- OpenAI's browsing models have explicit `open_page` and `find_in_page` actions (find-in-page as a cheap read primitive). — [OpenAI web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)
- WebGPT (2021) is the archetype: a text browser with commands `Search`, `Clicked on link`, `Find in page: <text>`, `Quote: <text>`, `Scrolled down/up`, `Top`, `Back`, `End: Answer`; each step uses a fresh context containing only a summary of state ("the only memory of previous steps is what is recorded in the summary"); quoting records page title, domain and extract as a reference; browsing ends at max actions or "maximum total length of references", and the answer is composed only from collected quotes. — [Nakano et al., WebGPT, 2021](https://arxiv.org/abs/2112.09332)

**Long-context degradation (why whole-page dumping is avoided)**
- Lost in the Middle (2023): performance is highest when relevant info is at the start or end and "significantly degrades" in the middle, even for long-context models. — [Liu et al., 2023](https://arxiv.org/abs/2307.03172)
- Chroma "Context Rot" (July 14, 2025, 18 models incl. GPT-4.1, Claude 4, Gemini 2.5, Qwen3): performance degrades with input length even on simple tasks; distractors compound errors; on LongMemEval all models did significantly better with ~300-token focused prompts than ~113k-token full prompts. Independent (vector-DB vendor, but not selling the LLMs tested). — [Chroma Research, Context Rot, 2025](https://www.trychroma.com/research/context-rot)
- NoLiMa (2025): with minimal lexical overlap between question and needle, at 32K tokens 11 of 13 models fall below 50% of their short-context baseline; GPT-4o drops 99.3%→69.7%. — [Modarressi et al., NoLiMa, 2025](https://arxiv.org/abs/2502.05167)
- RULER (2024): of 17 models claiming ≥32K context, only half maintain satisfactory performance at 32K despite near-perfect vanilla needle-in-a-haystack. — [Hsieh et al., RULER, 2024](https://arxiv.org/abs/2404.06654)
- Google's own long-context guide promotes "providing all relevant information upfront" with Gemini's large window and cites up to 99% single-needle recall, but concedes that with multiple needles "the model does not perform with the same accuracy" and recommends context caching (vendor framing). — [Gemini long context docs](https://aistudio.google.com/docs/long-context)

**Interactive reading of long documents (research systems)**
- ReadAgent (2024): paginates a long text into episodes, compresses them into "gist memories", and looks up original passages when needed; extends effective context 3.5–20x and beats retrieval and full-context baselines on QuALITY, NarrativeQA, QMSum. — [Lee et al., ReadAgent, 2024](https://arxiv.org/abs/2402.09727)
- MemWalker (2023): builds a tree of summary nodes over a long text, then navigates it per query; outperforms long-context, recurrence and retrieval baselines on long-text QA. — [Chen et al., MemWalker, 2023](https://arxiv.org/abs/2310.05029)

**Compaction, tool-result clearing, notes and subagents**
- Anthropic context editing (`clear_tool_uses_20250919`): clears oldest tool results once a trigger is crossed (default 100,000 input tokens), keeps the last 3 tool uses by default, can exclude tools; pairs with a client-side memory tool that warns Claude to save important information before results are cleared; server-side compaction (`compact_20260112`) is now the primary strategy for long conversations. — [Anthropic context editing docs](https://platform.claude.com/docs/en/build-with-claude/context-editing)
- Vendor-reported (Sep 29, 2025): memory tool + context editing improved an internal agentic-search eval by 39% over baseline, context editing alone 29%, and cut token consumption 84% in a 100-turn web-search eval. — [Claude blog, Managing context on the Claude Developer Platform, 2025](https://claude.com/blog/context-management)
- OpenAI compaction: server-side compaction via `context_management.compact_threshold` emits an encrypted, opaque compaction item and prunes context; a standalone stateless `/responses/compact` endpoint returns a compacted window. — [OpenAI compaction guide](https://developers.openai.com/api/docs/guides/compaction)
- Anthropic's multi-agent Research system (June 13, 2025): subagents each search and read in their own context window and return "condensed findings"; the lead saves its plan to Memory because context is truncated beyond 200,000 tokens; subagents can write outputs to external storage and pass "lightweight references" back. — [Anthropic, How we built our multi-agent research system, 2025](https://www.anthropic.com/engineering/multi-agent-research-system); sub-agents typically return "a condensed, distilled summary of its work (often 1,000-2,000 tokens)". — [Anthropic context engineering, 2025](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Tongyi DeepResearch (Oct 2025) uses "Markovian state reconstruction": at each step the agent sees only the question, an evolving report acting as compressed memory, and the last action/observation; evaluation caps at 128 tool calls and 128K context. — [Tongyi DeepResearch Technical Report, 2025](https://arxiv.org/abs/2510.24701)
- ReSum (2025): periodically summarizes interaction history with an external tool; +4.5% over ReAct training-free, +8.2% more with ReSum-GRPO. — [Wu et al., ReSum, 2025](https://arxiv.org/abs/2509.13313)
- AgentFold (2025): learned multi-scale "folding" of history; AgentFold-30B-A3B reaches 36.2% on BrowseComp (author-reported). — [Ye et al., AgentFold, 2025](https://arxiv.org/abs/2510.24699)
- ACON (2025): optimized compression of observations and history cuts peak tokens 26–54% while improving task success; up to 46% gains for smaller models. — [Kang et al., ACON, 2025](https://arxiv.org/abs/2510.00615)
- MEM1 (2025): RL-trained constant-memory agent; 3.5x performance and 3.7x lower memory vs Qwen2.5-14B on a 16-objective multi-hop QA task. — [Zhou et al., MEM1, 2025](https://arxiv.org/abs/2506.15841)
- Compression is itself a source of error: in multi-agent deep research, "information passes through agents like a telephone game"; agents that summarize a single document make few errors, but 84.7% of final-report errors in AI-Q originate at the orchestrator. — [Hirsch et al., 2026](https://arxiv.org/abs/2608.24306); stochasticity in DRA output comes from information acquisition, compression and inference, with inference and early-stage randomness contributing most. — [Zhai et al., 2026](https://arxiv.org/abs/2602.23271)

### Inferences
- "Query-time chunking" is real and cheap: a handful of fetched pages yields only hundreds of chunks, which can be scored in memory (embeddings, BM25, or LLM-written filter code) per question. This is why web agents do not need a global vector DB for the read step; the global index is the search engine's.
- The convergent design is hierarchical: search snippets -> selective fetch -> page-level filtering or goal-conditioned summary -> notes/quotes kept -> raw text cleared/compacted -> final writer. Every arrow is a lossy compression where citations can break (see Section 3).
- For the user's toolkit, the differentiator versus live agents is that a pre-built lake can provide stable, span-addressable chunks and page/char offsets ahead of time, so the agent's "filter" step becomes a cheap lookup and citations can point to immutable spans; the agent loop (just-in-time selection) can stay the same.

### Gaps
- No vendor publishes how its own deep-research products chunk or summarize pages internally (OpenAI, Google, Perplexity are black boxes beyond tool names).
- I found no controlled study directly comparing "whole page in context" vs "query-time chunk selection" vs "goal-conditioned summary" for citation accuracy on the same tasks.

## 3. Citation and attribution: how answers get citations, and how accurate they are

### Takeaway
Citations are produced in three ways: (a) the model collects quotes while reading and writes only from them (WebGPT, GopherCite), (b) the API gives the model chunked documents and returns span-level pointers (Anthropic Citations `char_location`/`page_location`, OpenAI and Gemini `url_citation` start/end indices), or (c) a post-hoc pass attaches/repairs citations (Anthropic CitationAgent, RARR, CiteFix). Independent audits consistently find that a large share of cited statements are not supported by the cited source: ~25% of citations wrong and ~half of sentences not fully supported in 2023 generative search; 40–80% citation accuracy for 2025 deep research systems; 39–77% factual accuracy of citations from frontier models in 2026; and 3–13% of citation URLs fabricated outright.

### Cited Findings
**Mechanisms**
- WebGPT (2021): answers must cite quotes collected during browsing so labelers can judge factual accuracy; the best model is preferred to human demonstrators 56% of the time and to top Reddit answers 69%. — [Nakano et al., WebGPT, 2021](https://arxiv.org/abs/2112.09332)
- GopherCite (2022): RLHP-trained 280B model that cites verbatim quotes; high-quality 80% on NaturalQuestions subset and 67% on ELI5, rising to 90%/80% when abstaining on the third of questions it is least sure of; "not all claims supported by evidence are true" (TruthfulQA analysis). — [Menick et al., GopherCite, 2022](https://arxiv.org/abs/2203.11147)
- WebGLM (2023) targets WebGPT's efficiency limitations with an LLM-augmented retriever, a bootstrapped generator and a human-preference-aware scorer; its 10B model is reported comparable to 175B WebGPT in human evaluation (author-reported). — [Liu et al., WebGLM, 2023](https://arxiv.org/abs/2306.07906)
- Anthropic Citations API: documents are chunked into sentences (plain text, PDFs) or caller-defined blocks (custom content); responses carry `char_location`, `page_location` or `content_block_location` with `cited_text`, which does not count toward output tokens; citations are "guaranteed to contain valid pointers to the provided documents" and Anthropic says its evaluations show it is "significantly more likely to cite the most relevant quotes" than prompt-based quoting (vendor claim); incompatible with structured outputs. — [Anthropic Citations docs](https://platform.claude.com/docs/en/build-with-claude/citations)
- Anthropic web search citations are always on (`web_search_result_location`, ≤150-char `cited_text`); web fetch citations are opt-in and return `char_location` spans into the fetched document. — [Anthropic web search docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool); [Anthropic web fetch docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)
- Anthropic Research uses a dedicated CitationAgent that, after research is finished, processes the documents and the report to "identify specific locations for citations" — i.e., citations are attached post hoc. — [Anthropic multi-agent research system, 2025](https://www.anthropic.com/engineering/multi-agent-research-system)
- OpenAI `url_citation` annotations carry `url`, `title`, `start_index`, `end_index`; `web_search_call.action.sources` lists every URL consulted (usually longer than the citation list); UIs must show inline citations as clickable links. — [OpenAI web search guide](https://developers.openai.com/api/docs/guides/tools-web-search)
- Gemini grounding with Google Search now returns `url_citation` annotations (url, title, start/end index) plus `search_suggestions` HTML that must be displayed; billing is per executed search query for Gemini 3+ ($14 per 1,000 after 5,000 free/month). URL Context returns the same annotation type and a per-URL `url_context_result` status (including "unsafe"). — [Gemini Google Search grounding docs](https://aistudio.google.com/docs/google-search); [Gemini URL context docs](https://aistudio.google.com/docs/url-context)
- Perplexity Sonar returns a `citations` URL array and `search_results` (title, URL, date, last-updated, snippet); answer text cites with bracketed numbers. — [Perplexity docs](https://docs.perplexity.ai/guides/search-context-size-guide)
- Post-hoc attribution: RARR retrofits attribution by searching for evidence for any model's output and minimally editing unsupported content. — [Gao et al., RARR, 2022](https://arxiv.org/abs/2210.08726); CiteFix cross-checks generated citations against retrieved articles (keyword+semantic, BERTScore, light LLM) for a 15.46% relative accuracy gain, letting a 12x cheaper model match the larger one (author-reported, industry RAG product). — [Maheshwari et al., CiteFix, 2025](https://arxiv.org/abs/2504.15629)
- Training for fine-grained citation: LongCite trains 8B/9B models on LongCite-45k for sentence-level citations in long-context QA and reports beating GPT-4o on LongBench-Cite (author-reported). — [Zhang et al., LongCite, 2024](https://arxiv.org/abs/2409.02897)
- Writer design matters: CLAIMWRITER (extract source facts -> map to outline -> write from source-linked claims) cuts hallucination 2.6–4.5x and raises necessary-fact recall 1.2–1.7x when swapped into three DR frameworks. — [Hayashi et al., 2026](https://arxiv.org/abs/2608.28643)

**Evaluation frameworks**
- AIS (Attributable to Identified Sources) defines the human-annotation standard for whether output is supported by its sources. — [Rashkin et al., 2021](https://arxiv.org/abs/2112.12870)
- Attributed QA benchmark and automatic metric correlated with human judgment. — [Bohnet et al., 2022](https://arxiv.org/abs/2212.08037)
- ALCE: automatic citation recall/precision metrics; even the best models lack complete citation support 50% of the time on ELI5. — [Gao et al., ALCE, 2023](https://arxiv.org/abs/2305.14627)
- AttrScore: defines attribution error types and tests LLM/fine-tuned evaluators on New Bing outputs across 12 domains. — [Yue et al., 2023](https://arxiv.org/abs/2305.06311)
- AttributionBench: automatic attribution judging is hard; fine-tuned GPT-3.5 reaches only ~80% macro-F1. — [Li et al., 2024](https://arxiv.org/abs/2402.15089)
- Judges for citation verification (2026): 8 LLM judges on 1,248 human-reviewed rubric decisions; cheaper judges are competitive (GPT-5-mini best source-relevance F1 0.908) and judges are statistically indistinguishable on factual support, but differ in false-positive/negative bias. — [Leung et al., 2026](https://arxiv.org/abs/2607.08700)
- FActScore (2023): atomic-fact precision; ChatGPT 58% on biographies; retrieval-augmented PerplexityAI also evaluated; automated estimator <2% error. — [Min et al., 2023](https://arxiv.org/abs/2305.14251); SAFE uses search to check each fact, agrees with crowd annotators 72% and wins 76% of disagreements, >20x cheaper. — [Wei et al., 2024](https://arxiv.org/abs/2403.18802)

**Measured citation accuracy (independent unless marked)**
- Generative search engines (2023; Bing Chat, NeevaAI, perplexity.ai, YouChat): only 51.5% of sentences fully supported by citations; only 74.5% of citations support their sentence. — [Liu, Zhang & Liang, Evaluating Verifiability in Generative Search Engines, 2023](https://arxiv.org/abs/2304.09848)
- Medical citations (2024, SourceCheckup): 50–90% of LLM responses not fully supported by the sources they provide; even GPT-4 with RAG had ~30% unsupported statements and nearly half of responses not fully supported. — [Wu et al., 2024](https://arxiv.org/abs/2402.02008)
- Tow Center, ChatGPT search (Nov 27, 2024): 153 of 200 quote-attribution answers incorrect or partially incorrect; uncertainty acknowledged only 7 times; cited plagiarized and syndicated copies. OpenAI called it "an atypical test". — [CJR/Tow Center, 2024](https://www.cjr.org/tow_center/how-chatgpt-misrepresents-publisher-content.php)
- Tow Center, eight AI search engines (Mar 6, 2025; 1,600 queries): >60% of queries answered incorrectly overall; Perplexity 37% incorrect, Grok 3 94%; ChatGPT wrong on 134/200 and never declined; Grok 3 154/200 citations led to error pages; >half of Gemini and Grok 3 responses cited fabricated or broken URLs; premium tiers were more confidently wrong. — [CJR/Tow Center, 2025](https://www.cjr.org/tow_center/we-compared-eight-ai-search-engines-theyre-all-bad-at-citing-news.php)
- EBU/BBC News Integrity in AI Assistants (Oct 22, 2025; 22 public service media orgs, 18 countries, 14 languages, >3,000 responses from ChatGPT, Copilot, Gemini, Perplexity): 45% had at least one significant issue; 31% had serious sourcing problems (missing, misleading or incorrect attribution); 20% major accuracy issues; Gemini 76% significant issues, mostly sourcing. — [EBU press release, 2025](https://www.ebu.ch/news/2025/10/ai-s-systemic-distortion-of-news-is-consistent-across-languages-and-territories-international-study-by-public-service-broadcaste)
- DeepResearch Bench (June 2025; citations checked by fetching each cited URL via Jina Reader and an LLM judge): citation accuracy Perplexity Deep Research 90.24% (31.26 effective citations/task), Gemini-2.5-Pro Deep Research 81.44% (111.21 effective citations), OpenAI Deep Research 77.96% (40.79), Grok Deeper Search 83.59% (8.15); Claude-3.7-Sonnet w/Search 93.68% (32.48); Perplexity Sonar-Reasoning-Pro only 39.36%. — [Du et al., DeepResearch Bench, 2025](https://arxiv.org/abs/2506.11763)
- DeepTRACE (Sept 2025; GPT-4.5/5, You.com, Perplexity, Copilot/Bing, Gemini): deep-research modes reduce overconfidence but remain one-sided on debate queries, with large fractions of unsupported statements and citation accuracy 40–80%. — [Venkit et al., DeepTRACE, 2025](https://arxiv.org/abs/2509.04499)
- ReportBench (Aug 2025): commercial deep research agents (OpenAI, Google) produce more reliable reports than search-augmented LLMs, but with substantial room for improvement in cited-literature quality and statement faithfulness. — [Li et al., ReportBench, 2025](https://arxiv.org/abs/2508.15804)
- Cited but Not Verified (May 2026; 14 LLMs, cited content actually retrieved): frontier models keep link validity >94% and relevance >80% but only 39–77% factual accuracy against the cited source. — [Onweller et al., 2026](https://arxiv.org/abs/2605.06635)
- Fabricated URLs (Apr 2026; 10 models/agents, 53,090 DRBench URLs + 168,021 ExpertQA URLs): 3–13% of citation URLs hallucinated (no Wayback record), 5–18% non-resolving; deep research agents cite more per query but hallucinate URLs at higher rates; a URL-liveness tool in the loop cut non-resolving URLs 6–79x to <1%. — [Rao, Wong & Callison-Burch, 2026](https://arxiv.org/abs/2604.03173)
- Smoothing (Oct 2026): across 7 systems and 4 datasets, research agents "consistently produce stronger claims than warranted" by collapsing conflicting sources into one confident narrative. — [Singha Roy, Wadhwa & Durrett, 2026](https://arxiv.org/abs/2610.35793)
- Instability: ten identical runs of one commercial DRA had median pairwise entity Jaccard 0.12 and citation Jaccard <0.02. — [Pykälä & Kaski, 2026](https://arxiv.org/abs/2610.26421); Ai2 Asta showed unstable cited-reference sets across identical queries and poor concordance between retrieved and cited documents. — [Orduña-Malea & Lopezosa, 2026](https://arxiv.org/abs/2606.08301)

**Hallucinated references (no-retrieval or weak-retrieval baselines)**
- 2023: 55% of GPT-3.5 and 18% of GPT-4 citations fabricated (636 references across 84 literature reviews). — [Walters & Wilder, Scientific Reports, 2023](https://www.nature.com/articles/s41598-023-41032-5.pdf)
- 2024: hallucinated reference rates of 39.6% (GPT-3.5), 28.6% (GPT-4), 91.4% (Bard) for systematic-review searches. — [Chelli et al., JMIR, 2024](https://www.jmir.org/2024/1/e53164)
- Hallucinated references can be flagged without external lookup via "consistency checks" (asking the model about the reference's authors): GPT-4 often gives inconsistent author lists for hallucinated references but recalls authors of real ones accurately. — [Agrawal et al., Do Language Models Know When They're Hallucinating References?, 2023](https://arxiv.org/abs/2305.18248)
- In the wild: ~146,932 hallucinated citations estimated in 2025 across 111M references in arXiv/bioRxiv/SSRN/PMC. — [Zhao et al., 2026](https://arxiv.org/abs/2605.07723); ~300 ACL/NAACL/EMNLP 2024–25 papers contain at least one. — [Sakai et al., 2026](https://arxiv.org/abs/2601.18724); ~1 in 20 NeurIPS 2025 and USENIX Security 2025 papers contain ≥2 likely hallucinated references. — [Russinovich et al., 2026](https://arxiv.org/abs/2607.00738)

### Inferences
- Native span-level citation (citing a chunk the system actually holds) eliminates fabricated pointers but not unsupported claims: the pointer is valid while the claim can still overstate the passage. Independent audits measure exactly this gap (39–80% citation accuracy).
- Post-hoc citation (CitationAgent-style) is a design choice that decouples writing from evidence; research localizing errors suggests the orchestrator/writer stage is where most citation errors appear, so "write from claims linked to sources" designs are the mitigation.
- A data lake with immutable span IDs gives a deterministic citation target and makes automatic verification (re-read the span, judge support) cheap; this is something web agents struggle with because pages change, rot or are paywalled.

### Gaps
- No vendor publishes its own citation-precision numbers for current (late-2026) products; most independent numbers are on 2024–2025 versions and may be stale.
- DeepResearch Bench's citation checker itself depends on Jina Reader fetch quality and an LLM judge; judge error rates for that pipeline are not reported in the table.

## 4. Verification and source quality at read time: cross-checking, self-verification, credibility, conflicting sources

### Takeaway
Current agents mostly rely on prompt heuristics and the model's judgment for source quality; measured behavior shows strong deference to whatever plausible document is in context (adopting wrong retrieved content >60% of the time; 66–88 point accuracy drops from one planted document), selective evidence sampling, and over-confident synthesis. Verification techniques that work (CoVe, SAFE-style search-per-claim, URL liveness checks, claim-level writers) are add-on passes rather than default behavior.

### Cited Findings
- Anthropic found early research agents "favored SEO-optimized content farms over authoritative sources such as academic PDFs and personal blogs" and fixed it by adding source-quality heuristics to prompts. — [Anthropic multi-agent research system, 2025](https://www.anthropic.com/engineering/multi-agent-research-system)
- WebGPT "still sometimes quotes from highly unreliable sources" on TruthfulQA; its remaining falsehoods are "typically mistakes when attempting to paraphrase or synthesize information rather than wild hallucinations". — [Nakano et al., WebGPT, 2021](https://arxiv.org/abs/2112.09332)
- OpenAI's deep research system card reports PersonQA accuracy 0.86 and hallucination rate 0.13 vs GPT-4o 0.50/0.30 (vendor-reported; OpenAI notes the test set was partly outdated). — [OpenAI Deep Research System Card, 2025](https://cdn.openai.com/deep-research-system-card.pdf)
- ClashEval (2024): six top LLMs adopt incorrect retrieved content, overriding their own correct prior, over 60% of the time; the more unrealistic the perturbation, the less likely it is adopted. — [Wu, Wu & Zou, ClashEval, 2024](https://arxiv.org/abs/2404.10198)
- LLMs are "highly receptive to external evidence" that is coherent and convincing even when it conflicts with parametric memory, yet show confirmation bias when evidence partially matches memory. — [Xie et al., Adaptive Chameleon or Stubborn Sloth, 2023](https://arxiv.org/abs/2305.13300)
- DRNOISE (2026): seeding one plausible false document causes 66–88 percentage-point accuracy drops for strong agents; "verification inertia" — agents retrieve truthful records yet defer to the answer-like document; generic verification prompts reduce but do not close the gap. — [Nie et al., DRNOISE, 2026](https://arxiv.org/abs/2607.17291)
- Evidence selection bias (2026): early findings redirect later queries and stopping, so the documents an agent reads are a selective sample; a well-cited report can still reach a misleading conclusion. — [Xiao et al., Search Shapes Conclusions, 2026](https://arxiv.org/abs/2609.39026)
- Credibility-aware generation (CAG) trains models to weigh documents by credibility and shows resilience to noisy documents (author-reported). — [Pan et al., 2024](https://arxiv.org/abs/2404.06809)
- Chain-of-Verification: draft, plan verification questions, answer them independently, then revise; reduces hallucination on list, closed-book QA and long-form tasks. — [Dhuliawala et al., CoVe, 2023](https://arxiv.org/abs/2309.11495)
- Search-per-claim verification (SAFE) and atomic-fact scoring (FActScore) are the standard automated checks. — [Wei et al., 2024](https://arxiv.org/abs/2403.18802); [Min et al., 2023](https://arxiv.org/abs/2305.14251)
- Jina DeepSearch down-ranks a maintained list of problematic/gated hostnames and enforces domain diversity (top-k URLs per hostname) and recency estimation before reading. — [Jina AI, 2025](https://jina.ai/news/snippet-selection-and-url-ranking-in-deepsearch-deepresearch/)
- Agents with a URL-health tool self-correct non-resolving citations to under 1%. — [Rao et al., 2026](https://arxiv.org/abs/2604.03173)
- Debate queries: generative search and deep research answers are frequently one-sided and highly confident. — [Venkit et al., DeepTRACE, 2025](https://arxiv.org/abs/2509.04499); claim smoothing across conflicting sources. — [Singha Roy et al., 2026](https://arxiv.org/abs/2610.35793)

### Inferences
- "Reading" is not "verifying": the dominant failure is not inventing facts but trusting the wrong page or overstating a real one. Source credibility is mostly a prompt instruction, not a computed signal at read time.
- A curated data lake can carry provenance/credibility metadata per source and deduplicate syndicated copies, which directly targets the measured failure modes (content farms, syndication, planted UGC).

### Gaps
- I found no public description of computed credibility scoring inside OpenAI, Google or Perplexity deep research products.
- Few studies measure how often agents explicitly cross-check a claim across ≥2 independent sources; most evidence is indirect (DRNOISE, selection bias).

## 5. Prompt injection and poisoning via web content (read-side risk)

### Takeaway
Every page an agent reads is untrusted input that can carry instructions (indirect prompt injection) or targeted misinformation (poisoning). Vendors mitigate with adversarial training, classifiers on untrusted content, restricting which URLs can be fetched, cached/indexed-only search modes, and user confirmations; all of them state the problem is not solved. Vendor-reported attack success rates have dropped to ~1–3% against their own adaptive attackers, while independent benchmarks still show substantial success.

### Cited Findings
- Indirect prompt injection (2023): adversaries plant prompts "into data likely to be retrieved", demonstrated against Bing's GPT-4 Chat, enabling data theft, worming and "information ecosystem contamination". — [Greshake et al., 2023](https://arxiv.org/abs/2302.12173)
- InjecAgent (2024): 1,054 cases; ReAct-prompted GPT-4 vulnerable 24% of the time, nearly doubling with a hacking prompt. — [Zhan et al., 2024](https://arxiv.org/abs/2403.02691)
- AgentDojo (2024): 97 tasks, 629 security cases; dynamic benchmark for attacks/defenses. — [Debenedetti et al., 2024](https://arxiv.org/abs/2406.13352)
- WASP (2025): simple human-written injections deceive top web agents; attacks partially succeed in up to 86% of cases, though agents often fail to complete attacker goals ("security by incompetence"). — [Evtimov et al., 2025](https://arxiv.org/abs/2504.18575)
- Spotlighting (Microsoft, 2024): marking/encoding untrusted input reduces attack success from >50% to <2% on GPT-family models. — [Hines et al., 2024](https://arxiv.org/abs/2403.14720)
- CaMeL (Google DeepMind, 2025): separates control flow (from trusted query) from untrusted data with capabilities; solves 77% of AgentDojo tasks with provable security vs 84% undefended. — [Debenedetti et al., 2025](https://arxiv.org/abs/2503.18813)
- Brave's Comet disclosure (Aug 20, 2025): hidden instructions in a Reddit comment made Perplexity Comet's "summarize this page" fetch the user's email and Gmail OTP and post them back; root cause was sending page content to the LLM without separating it from user instructions; recommended treating page content as untrusted, checking actions against user intent, requiring confirmation, isolating agentic browsing. — [Brave blog, 2025](https://brave.com/blog/comet-prompt-injection/)
- OpenAI deep research (Feb 2025): mitigations include safety training data and a system-level rule that the agent cannot "navigate to or construct arbitrary URLs" (to prevent exfiltration via URL parameters); vendor-reported text-injection attack success fell from 1.5–4% pre-mitigation to 0–0.51% post-mitigation, multimodal from 5–18.5% to 0–2.6%. — [OpenAI Deep Research System Card, 2025](https://cdn.openai.com/deep-research-system-card.pdf)
- Anthropic web fetch only fetches URLs that already appeared in user messages, client tool results or prior search/fetch results (never URLs only in Claude's output), refuses credential-bearing URLs, and warns of exfiltration risk when untrusted input meets sensitive data. — [Anthropic web fetch docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool)
- Anthropic (Nov 24, 2025, updated 2026): RL training against injections in simulated web content, classifiers scanning all untrusted content, red teaming; vendor-reported Best-of-N attacker (100 attempts/environment) success with improved safeguards: Opus 4.5 1.4%, Sonnet 4.5 1.9%, Haiku 4.5 2.4% (model-only: 8.0–13.8%); "No browser agent is immune to prompt injection." — [Anthropic, Mitigating prompt injection in browser use, 2025](https://www.anthropic.com/research/prompt-injection-defenses)
- OpenAI Atlas (Dec 22, 2025, via coverage): RL-trained LLM attacker finds long-horizon injections; adversarially trained agent models; recommends logged-out mode, careful confirmation review, narrow instructions; OpenAI calls deterministic guarantees "challenging" and, per coverage, said prompt injection is "unlikely to ever be fully 'solved'". — [The Decoder, 2025](https://the-decoder.com/openai-admits-prompt-injection-may-never-be-fully-solved-casting-doubt-on-the-agentic-ai-vision/)
- Codex cached search mode exists partly to limit exposure to arbitrary live pages. — [Codex web search docs](https://learn.chatgpt.com/docs/web-search)
- Poisoning without instructions (May 2026): deep-research reports repeatedly draw on the same UGC pages (Reddit, Wikipedia); appending as few as 13 words to one frequently retrieved URL got the text retrieved in 57–76% of runs and cited in 38–51% of reports; poisoning a subreddit achieved 30–53% citation rates at 0.5–4% of retrieved content. — [Zhang, Triedman & Shmatikov, 2026](https://arxiv.org/abs/2605.24245)

### Inferences
- Read-side security is now a design constraint on fetching itself (URL provenance rules, no model-constructed URLs, cached/indexed modes), not only on the model.
- Poisoning research shows the read phase concentrates on a small set of popular pages; a curated lake with provenance reduces this attack surface but inherits it for any ingested UGC.

### Gaps
- Vendor attack-success numbers use their own attackers and are not comparable across vendors; no independent cross-vendor benchmark on current (2026) production browsing agents was found.

## 6. Cost and latency of the read phase (tokens per report, pages read per task)

### Takeaway
Reading dominates agent cost: multi-agent research uses ~15x chat tokens and token volume alone explains ~80% of BrowseComp performance variance (Anthropic); Google prices a Deep Research task at ~80 searches / ~250k input tokens ($1–3) and the Max tier at ~160 searches / ~900k input tokens ($3–7); tasks take 2–4 minutes (Perplexity) to ~20 and up to 60 minutes (Gemini). Context filtering/clearing reduces input tokens by roughly a quarter (dynamic filtering) to 84% (context editing in a 100-turn eval), all vendor-reported.

### Cited Findings
- Anthropic (vendor): agents use ~4x the tokens of chat; multi-agent systems ~15x; on BrowseComp, token usage explains 80% of performance variance (tool calls and model choice bring it to 95%); lead spawns 3–5 subagents in parallel, each using 3+ tools in parallel, cutting research time up to 90%; multi-agent beat single-agent Opus 4 by 90.2% on an internal eval. — [Anthropic multi-agent research system, 2025](https://www.anthropic.com/engineering/multi-agent-research-system)
- Google Gemini Deep Research agent (vendor, preview rates): standard ~80 searches, ~250k input tokens (50–70% cached), ~60k output tokens, $1–3 per task; Max up to ~160 searches, ~900k input tokens, ~80k output, $3–7; most tasks within ~20 minutes, max 60 minutes; tools default to google_search, url_context and code_execution. — [Gemini Deep Research docs](https://aistudio.google.com/docs/deep-research)
- Perplexity Deep Research (vendor, Feb 14, 2025): "dozens of searches" and "hundreds of sources" per query, 2–4 minutes, most under 3. — [Perplexity blog, 2025](https://www.perplexity.ai/hub/blog/introducing-perplexity-deep-research)
- Effective citations per task (independent benchmark, 2025): Gemini-2.5-Pro DR 111.21, OpenAI DR 40.79, Perplexity DR 31.26, GPT-4o-search ~4.8. — [DeepResearch Bench, 2025](https://arxiv.org/abs/2506.11763)
- Pricing primitives: Anthropic web search $10 per 1,000 searches plus tokens; web fetch has no extra charge beyond tokens (10 kB page ≈ 2,500 tokens; 500 kB PDF ≈ 125,000). — [Anthropic web search docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool); [Anthropic web fetch docs](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-fetch-tool); Gemini grounding $14 per 1,000 executed queries after 5,000 free per month. — [Gemini grounding docs](https://aistudio.google.com/docs/google-search); Jina's `s.jina.ai` search charges a fixed ≥10,000 tokens per request because it returns full content of top-5 results. — [Jina Reader page](https://jina.ai/reader/)
- Gemini URL context example: ~27 direct input tokens vs ~10,309 tool-use input tokens for retrieved page content. — [Gemini URL context docs](https://aistudio.google.com/docs/url-context)
- Budgets in open agents: Tongyi DeepResearch evaluation caps at 128 tool invocations and 128K context per task. — [Tongyi DeepResearch, 2025](https://arxiv.org/abs/2510.24701)
- Savings from read-side compression (vendor): dynamic filtering −24% input tokens on average (but price-weighted tokens increased for Opus 4.6); context editing −84% tokens in a 100-turn web-search eval. — [Claude blog, dynamic filtering, 2026](https://claude.com/blog/improved-web-search-with-dynamic-filtering); [Claude blog, context management, 2025](https://claude.com/blog/context-management)
- Independent: ACON reduces peak tokens 26–54%; MEM1 reduces memory 3.7x. — [Kang et al., 2025](https://arxiv.org/abs/2510.00615); [Zhou et al., 2025](https://arxiv.org/abs/2506.15841)
- Fixed-corpus evaluation (BrowseComp-Plus) exists precisely because live web APIs make cost/quality comparisons irreproducible; it ships a curated corpus with human-verified supporting documents and hard negatives. — [Chen et al., BrowseComp-Plus, 2025](https://arxiv.org/abs/2508.06600); BrowseComp itself has 1,266 hard browsing questions. — [Wei et al., BrowseComp, 2025](https://arxiv.org/abs/2504.12516)

### Inferences
- At ~250k–900k input tokens per Gemini report and 15x chat tokens for Anthropic's multi-agent research, most spend is on reading fetched content, so pre-cleaned, pre-chunked, span-addressable content (the user's data lake) mainly saves read-phase tokens and latency, not search cost.
- Reproducible evaluation is moving toward fixed corpora (BrowseComp-Plus), which is effectively a "local data lake" for benchmarking; this supports the user's approach as a complement to, not a replacement for, live web reading.

### Gaps
- OpenAI and Perplexity do not publish tokens or pages read per deep-research task; Anthropic publishes ratios, not absolute counts.
- I found no independent measurement of end-to-end latency breakdown (search vs fetch vs read vs write) for commercial agents.
