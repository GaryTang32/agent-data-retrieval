# LLM-based Information Extraction into Typed Records: Schema-Guided Extraction, Constrained Decoding, and Grounding

Scope: turning text into typed records (entities, relations, events, fields) that can be stored in SQL/graph/key-value stores and queried with exact predicates. Not covered here (other tracks): layout/table parsing, KG construction specifics, query-time semantic operators. Survey anchor for the field: [Xu et al., LLMs for Generative IE: A Survey (FCS 2024)](https://arxiv.org/abs/2312.17617).

Convention: "(author-reported)" = the result comes from the paper that proposes the method/product; "(independent)" = the evaluating party did not build the system that wins. Years in brackets mark classic/foundational work.

## Q1. Generative and instruction-tuned IE models (UIE, InstructUIE, GoLLIE, KnowCoder, Code4UIE, GLiNER/GLiREL, NuExtract, UniversalNER, ChatIE, 2025-2026 successors): how do they work and how do they compare with frontier-LLM prompting?

### Takeaway
Three families now coexist: (a) small span-scoring encoders (GLiNER family) that are cheap, CPU-friendly, emit only spans that exist in the text, and match or beat 7-13B generative IE models on zero-shot NER; (b) instruction/code-tuned generative IE LLMs (UIE → InstructUIE → UniversalNER/GoLLIE/KnowCoder/IEPile/ADELIE → RL-tuned R1-RE/MR-UIE/EAGER) that follow schemas/guidelines and beat untuned prompting; (c) frontier-LLM prompting, which historically lagged fine-tuned models on strict-match benchmarks (2023 evidence) but is the most flexible for arbitrary nested schemas. For a deterministic data lake, the evidence favours a hybrid: encoder or fine-tuned small models for high-volume, well-defined entity/relation types, and frontier LLMs (with schema, grounding and validation) for long-tail nested fields — not frontier prompting alone.

### Cited Findings

**Classic generative unification**
- [2022] UIE casts all IE tasks as text-to-structure generation with a "structured extraction language" (SEL) and a schema-based prompt ("structural schema instructor"), on a pretrained text-to-structure T5 model; SOTA on 4 IE tasks / 13 datasets in supervised, low-resource and few-shot settings (author-reported) — [Lu et al., UIE, ACL 2022](https://arxiv.org/abs/2203.12277)
- InstructUIE (Flan-T5 11B) reformulates 32 IE datasets ("IE INSTRUCTIONS") as instructions; reports gpt-3.5-turbo at only 18.22 F1 on OntoNotes, and InstructUIE comparable to BERT supervised and far above GPT-3.5 zero-shot (author-reported) — [Wang et al., InstructUIE 2023](https://arxiv.org/abs/2304.08085)
- YAYI-UIE adds chat data to IE instruction tuning for Chinese+English; SOTA on Chinese datasets, comparable on English (author-reported) — [Xiao et al., YAYI-UIE 2023](https://arxiv.org/abs/2312.15548)

**Code-style schemas (schema = Python class)**
- CodeIE: recasting NER/RE outputs as code and prompting code LLMs (Codex) outperforms both NL-LLM prompting and fine-tuned moderate-size IE models (e.g., UIE) in few-shot settings on 7 benchmarks (author-reported) — [Li et al., CodeIE, ACL 2023](https://arxiv.org/abs/2305.05711)
- Code4UIE: schemas as Python classes; extraction = generating code that instantiates the classes; retrieval of similar in-context examples; evaluated on 5 tasks / 9 datasets (author-reported) — [Guo et al., Code4UIE 2023](https://arxiv.org/abs/2311.02962)
- GoLLIE fine-tunes Code-LLaMA (7B; 13B/34B for scaling) so that schemas are Python classes whose docstrings carry annotation guidelines and whose comments carry representative candidates; output is code after `result =`, so executing it yields typed instances. Zero-shot average F1 over unseen datasets 55.3 vs 42.3 for the same model trained without guidelines; e.g., CrossNER-AI 59.1 vs prior SOTA InstructUIE 49.0, MIT-Restaurant 43.4 vs 21.0; it is worse than the baseline on E3C and WikiEvents-EE. Ablation: removing label "candidates" drops avg to 49.9 (the largest single loss) (author-reported) — [Sainz et al., GoLLIE, ICLR 2024](https://arxiv.org/abs/2310.03668)
- KnowCoder builds a code-style schema library covering >30,000 knowledge types, does code pretraining on ~1.5B automatically constructed tokens plus instruction tuning; reports +49.8% relative F1 vs LLaMA2 few-shot and up to +12.5% / +21.9% vs SOTA in zero-shot / low-resource (author-reported) — [Li et al., KnowCoder 2024](https://arxiv.org/abs/2403.07969). Multilingual successor KnowCoder-X (Python-class schemas shared across languages, 257k-sample ParallelNER) — [Zuo et al., KnowCoder-X, ACL Findings 2025](https://arxiv.org/abs/2411.04794)

**Distillation / data-centric successors**
- UniversalNER distils ChatGPT into LLaMA-based 7B/13B models via "targeted distillation"; on a 43-dataset, 9-domain NER benchmark it beats ChatGPT by 7-9 absolute F1 on average and beats InstructUIE (author-reported) — [Zhou et al., UniversalNER, ICLR 2024](https://arxiv.org/abs/2308.03279)
- IEPile: ~0.32B-token bilingual instruction corpus from 33 cleaned IE datasets with "schema-based instruction generation"; improves zero-shot generalization (author-reported) — [Gui et al., IEPile, ACL 2024](https://arxiv.org/abs/2402.14710)
- ADELIE: SFT on the IEInstruct corpus then DPO; SOTA among open-source models on held-out IE (author-reported) — [Qi et al., ADELIE, EMNLP 2024](https://arxiv.org/abs/2405.05008)
- B2NERD: resolves inconsistent entity definitions across 54 datasets into a 400+-type universal taxonomy and prunes redundant data, improving open-NER generalization (author-reported) — [Yang et al., B2NERD, COLING 2025](https://arxiv.org/abs/2406.11192)
- MetaIE distils an LLM's "label-to-span" judgments into a small meta-model adaptable to all IE tasks — [Peng et al., MetaIE 2024](https://arxiv.org/abs/2404.00457); Cuckoo reframes next-token prediction as "next tokens extraction" over 102.6M extractive instances converted from LLM pre/post-training data — [Peng et al., Cuckoo 2025](https://arxiv.org/abs/2502.11275)
- RUIE (retrieval of demonstrations with a trained bi-encoder) reports +19.22 F1 average over instruction-tuning methods on 8 held-out datasets (author-reported) — [Liao et al., RUIE, COLING 2025](https://arxiv.org/abs/2409.11673)
- Guideline Learning: automatically synthesizes guidelines from error cases and retrieves them at inference; improves in-context event/relation extraction — [Pang et al., EMNLP 2023](https://arxiv.org/abs/2310.05066)

**RL-tuned successors (2025-2026)**
- R1-RE: RL with verifiable reward, framing RE as guideline-guided reasoning; R1-RE-7B reaches ~70% average out-of-domain accuracy, "on par with" GPT-4o (author-reported; one public dataset Sem-2010 + one private) — [Dai et al., R1-RE 2025](https://arxiv.org/abs/2507.04642)
- MR-UIE: RL + multi-perspective reasoning for UIE; surpasses SOTA on several datasets (author-reported) — [Li et al., MR-UIE 2025](https://arxiv.org/abs/2509.09082)
- EAGER: RL for event extraction with fine-grained verifiable rewards explicitly targeting structural validity, accuracy, groundedness, coverage, over-generation and span precision; outperforms prompting/SFT/prior RL on 7 datasets (author-reported) — [Adjali et al., EAGER, EMNLP Findings 2026](https://arxiv.org/abs/2609.29230)

**Small encoders (GLiNER family)**
- GLiNER: bidirectional encoder (DeBERTa-v3, 50M-300M params) that scores spans against entity-type label embeddings in parallel (no autoregressive decoding). Zero-shot average F1 on 7 out-of-domain sets (CrossNER×5 + MIT Movie/Restaurant): ChatGPT 47.5, InstructUIE 47.2, UniNER-7B 53.7, UniNER-13B 55.6, GoLLIE-7B 58.0, GLiNER-L (0.3B) 60.9. Note: competitor numbers are copied from the respective papers, not re-run — [Zaratiana et al., GLiNER, NAACL 2024](https://aclanthology.org/2024.naacl-long.300.pdf)
- GLiREL: same idea for zero-shot relation classification between multiple entities in one forward pass; SOTA on FewRel and WikiZSL (author-reported) — [Boylan et al., GLiREL 2025](https://arxiv.org/abs/2501.03172)
- GLiNER multi-task (NER, QA, summarization, RE in a small encoder) — [Stepanov & Shtopko 2024](https://arxiv.org/abs/2406.12925); GLiNER2 adds text classification and hierarchical structured data extraction behind a schema interface while staying CPU-efficient — [Zaratiana et al., GLiNER2 2025](https://arxiv.org/abs/2507.18546)
- GLiNER bi-encoder: precomputed label embeddings allow thousands to millions of types; 61.5 micro-F1 zero-shot on CrossNER and up to 130× throughput at 1,024 labels (author-reported) — [Stepanov et al. 2026](https://arxiv.org/abs/2602.18487); GLiNER-Relex: joint NER+RE in one encoder, evaluated on CoNLL04, DocRED, FewRel, CrossRE — [Stepanov et al. 2026](https://arxiv.org/abs/2605.10108)
- Independent deployability study (9 systems, 13M-8B params): a 4B instruct LLM is competitive on accuracy (leads on clean newswire), but GLiNER matches or slightly trails at 1/9-1/24 the size, ms-to-s latency, and **zero malformed output**, while the smallest generative models emit up to **27% invalid output on long inputs**. Crucially, "gold provenance flips the paradigm ranking": LLM-authored silver labels favour generative models; human gold raises every encoder and lowers every generative model — [Chaganti, On-Device NER 2026](https://arxiv.org/abs/2610.00007)

**NuExtract (NuMind)**
- NuExtract 2.0-8B is Qwen2.5-VL-7B fine-tuned (MIT license); the schema is a JSON *template* with typed leaves (`verbatim-string`, `string`, `integer`, `number`, `date-time`, arrays, `enum`, `multi-label`); missing info returns `null` / `[]`; NuMind recommends temperature at or near 0 because e.g. Ollama defaults to 0.7. The benchmark is in-house (~1,000 examples) — [NuExtract-2.0-8B model card](https://huggingface.co/numind/NuExtract-2.0-8B)
- On the third-party LlamaIndex ExtractBench (long enterprise docs), NuExtract3 scored 47.9 value F1 vs 79.8 for Gemini 3.5 Flash and 95.6 for LlamaExtract Agentic Plus (benchmark authored by LlamaIndex) — [Zhang et al., ExtractBench (LlamaIndex) 2026](https://arxiv.org/abs/2607.29677)

**Prompting general LLMs (ChatIE and evaluations)**
- ChatIE turns zero-shot IE into multi-turn QA (first ask which types are present, then fill slots); surpasses some full-shot models on e.g. NYT11-HRL (author-reported) — [Wei et al., ChatIE 2023](https://arxiv.org/abs/2302.10205)
- (Independent, 2023) Across 9 datasets / 4 IE tasks, LLMs "consistently exhibit inferior performance, higher latency, and increased budget requirements compared to fine-tuned SLMs under most settings"; an SLM-filter + LLM-rerank of hard samples gives +2.4 F1 average — [Ma et al., Findings EMNLP 2023](https://arxiv.org/abs/2303.08559)
- (Independent) GPT-4 shows "a visible performance gap" vs SOTA IE methods; analysis of evaluation criteria, robustness, error types — [Han et al. 2023](https://arxiv.org/abs/2305.14450)
- (Independent) ChatGPT is poor in Standard-IE but strong in OpenIE under human evaluation; it is overconfident (low calibration) but mostly faithful to the source text — [Li et al. 2023](https://arxiv.org/abs/2304.11633)
- Counterpoint on evaluation: with human evaluation instead of exact match, few-shot GPT-3 RE is "roughly equivalent to existing fully supervised models"; strict string matching penalizes valid generative outputs — [Wadhwa et al., ACL 2023](https://arxiv.org/abs/2305.05003)
- Zero-shot NER with ChatGPT improves with decomposed per-label QA, syntactic augmentation, and two-stage self-consistency voting — [Xie et al., EMNLP 2023](https://arxiv.org/abs/2310.10035); GPT-NER marks entities inline (`@@Columbus##`) and uses self-verification against over-confident labelling of NULL inputs — [Wang et al., GPT-NER 2023](https://arxiv.org/abs/2304.10428); SumAsk prompting for zero-shot RE — [Li et al., Findings EMNLP 2023](https://arxiv.org/abs/2310.05028)
- Clinical: InstructGPT does well at zero/few-shot clinical span, token-level and relation extraction — [Agrawal et al., EMNLP 2022](https://arxiv.org/abs/2205.12689). Scientific: fine-tuning GPT-3 on ~500 prompt/completion pairs yields JSON records for materials-chemistry NER+RE, including cross-sentence hierarchical records — [Dunn, Dagdelen et al. 2022](https://arxiv.org/abs/2212.05238)
- Robustness: on LLM-generated realistic perturbations (RUIE-Bench) both LLM-based and other UIE models show "significant performance drops" — [Zhu et al. 2025](https://arxiv.org/abs/2503.03201)

### Inferences
- Method-by-method view for a deterministic pipeline:
  - *Encoders (GLiNER/GLiREL/GLiNER2)*: deterministic forward pass (no sampling), outputs are by construction spans of the input (so grounding is free), per-span scores exist, run on CPU; weak on nested multi-field records, long-range document relations and normalization (dates, units, IDs). Best default for high-volume entity tagging.
  - *Instruction/code-tuned IE LLMs (GoLLIE, KnowCoder, UniNER, ADELIE, R1-RE)*: open weights → can be pinned and run with deterministic kernels; code-style schemas give typed outputs that can be executed/validated; but they are trained on academic label sets (CoNLL/ACE-style) and generalize unevenly (GoLLIE loses on E3C/WikiEvents-EE).
  - *Frontier prompting*: best for bespoke nested business schemas and normalization; weaker on strict-span benchmarks (2023 evidence), costliest, and API-side nondeterminism cannot be fully controlled (see Q6).
- Most "beats ChatGPT/SOTA" claims are author-reported and many comparison tables reuse numbers from other papers (explicitly so in GLiNER), so cross-paper rankings at the 1-5 F1 level should not be trusted.
- Gold-label provenance can invert rankings (On-Device NER), so a toolkit should evaluate on human-labelled samples of its own corpora, not LLM-silver labels.

### Gaps
- No independent, re-run head-to-head of GoLLIE/KnowCoder/UniNER/GLiNER2/NuExtract vs 2025-2026 frontier models (GPT-5.x, Claude 4.x, Gemini 3.x) on the classic IE suites was found; 2023 conclusions ("LLMs are not good few-shot extractors") are likely outdated for frontier models but I found no rigorous 2025-2026 replication on CoNLL/ACE/DocRED.
- NuExtract 2.0 scores vs frontier models were not obtainable (only shown as an image on the model card; original blog URL returned 404).

## Q2. Schema-guided / ontology-guided extraction (SPIRES/OntoGPT, LangExtract), document-level and long-context extraction, multi-record extraction and cardinality (truncated lists, duplicates)

### Takeaway
Schema-guided extraction (user-defined JSON Schema / Pydantic / LinkML / Python classes) is the dominant practical pattern, but reliability collapses as schemas get wide and as documents get long: frontier models produce 0% valid output on a 369-field schema, and VLM value-F1 on >50-page documents falls from ~88 to ~28 because whole records are dropped. The winning patterns decompose the problem — chunk + multiple passes + merge (LangExtract), object→field→value staged extraction with validation gates (xmemory, OneKE), recursive per-class prompting with ontology grounding (SPIRES), or agentic/code-based extraction — and they buy accuracy with cost.

### Cited Findings
- SPIRES (OntoGPT) recursively interrogates an LLM per class of a user-defined (LinkML) schema, then grounds each matched value to ontology/vocabulary identifiers; accuracy "comparable to the mid-range of existing Relation Extraction methods" but needs no training data — [Caufield et al., SPIRES, Bioinformatics 2024](https://arxiv.org/abs/2304.02711)
- LangExtract (Google, Apache-2.0): few-shot examples define the schema; controlled generation on supported models (Gemini, OpenAI `output_schema`); every extraction is aligned to source character offsets (`char_interval`, `None` if it cannot be aligned); long documents are handled with chunking (`max_char_buffer`), parallel workers and multiple extraction passes (`extraction_passes=3`) "to improve recall"; README warns the model may copy content from the examples, which the alignment check catches; no benchmark numbers given — [google/langextract](https://github.com/google/langextract)
- OneKE: dockerized multi-agent schema-guided extraction from web pages and PDF books with a "configure knowledge base" for schema configuration and error-case debugging/correction — [Luo et al., OneKE, WWW 2025 demo](https://arxiv.org/abs/2412.20005)
- StructSense: ontology-guided symbolic knowledge + agentic self-evaluative refinement + human-in-the-loop; 91-100% accuracy on schema-based extraction of assessment instruments, 86-93% on paper metadata, 58-75% NER label accuracy (author-reported) — [Chhetri et al. 2025](https://arxiv.org/abs/2507.03674)
- Schema-grounded memory (xmemory): object detection → field detection → field-value extraction with validation gates, local retries and stateful prompt control; "reads become constrained queries over verified records"; 90.42% object-level and 62.67% output accuracy on their extraction benchmark, above tested frontier structured-output baselines (author-reported, vendor) — [Petrov et al. 2026](https://arxiv.org/abs/2604.27906)
- Schema-as-tools: treating schemas as parameterized tools the LLM selects among, for adaptivity across schemas — [Liang et al. 2025](https://arxiv.org/abs/2506.01276)
- Evaporate (data-lake setting): two strategies — LLM extracts values directly from every document vs LLM synthesizes extraction code run over documents. Code is cheap but much less accurate; Evaporate-Code+ generates many candidate functions and ensembles them with weak supervision, reported better than direct extraction while making a sublinear pass (110× fewer LLM tokens averaged over 16 settings of 10k documents) (author-reported) — [Arora et al., Evaporate](https://arxiv.org/abs/2304.09433)
- **Cardinality / list truncation (independent of the model vendors):** ExtractBench (Contextual AI): 35 PDFs, JSON Schemas with 12,867 evaluable fields; schema is an "executable specification" where each field declares its metric (exact match for IDs, tolerance for quantities, semantic equivalence for names; arrays need alignment; omission distinguished from hallucination). Frontier models (GPT-5/5.2, Gemini 3 Flash/Pro, Claude 4.5 Opus/Sonnet) produced valid JSON in only 51% of extractions; best field pass rate 6.9%; credit agreements (13 keys) 56.3% pass vs research papers (16 keys, ~309.5 array items/doc) 20.8%; **0% valid output on the 369-field SEC 10-K/Q schema for all models**; 9 truncated-JSON and 2 context-length failures — [Ferguson et al., ExtractBench 2026](https://arxiv.org/abs/2602.12247)
- ExtractBench (LlamaIndex; 4,869 pages / 370 docs / 67 doc types): commercial VLMs do well on short docs but "often truncate record lists on long ones"; Gemini 3.5 Flash value F1 87.9 on short docs vs 27.9 on >50-page docs; on enormous tables every VLM < 10%; "entire records are dropped rather than misread"; coding agents retain accuracy at higher cost (Codex GPT-5.5: 93.6 F1, 27.8¢/page). The vendor's own LlamaExtract Agentic Plus ranks first (95.6 F1, 8.1¢/page) — a conflict of interest — [Zhang et al., ExtractBench (LlamaIndex) 2026](https://arxiv.org/abs/2607.29677)
- Full-paper sample extraction (polymer nanocomposites): "even advanced LLMs struggle to extract all of the samples from an article"; self-consistency helps — [Khalighinejad et al. 2024](https://arxiv.org/abs/2403.00260)
- StructuredRAG: average 82.55% format success over 24 experiments, range 0-100%; tasks with lists or composite objects are notably harder — [Shorten et al. 2024](https://arxiv.org/abs/2408.11061)
- Long-context positional bias: retrieval of relevant info degrades when it sits in the middle of long contexts — [Liu et al., Lost in the Middle, TACL](https://arxiv.org/abs/2307.03172)
- Document-level RE: LLM methods lag BERT-based DocRE models; attention is dispersed over the many entity pairs with no relation; pre-filtering candidate pairs with a classifier narrows the gap — [Li et al. 2024](https://arxiv.org/abs/2408.13889); AutoRE proposes a Relation-Head-Facts paradigm for end-to-end DocRE — [Xue et al. 2024](https://arxiv.org/abs/2403.14888); vanilla ICL is "infeasible" for DocRE due to many fine-grained relation types and uncontrolled generations, so LLM+NLI is used for data augmentation (DocGNRE) — [Li et al. 2023](https://arxiv.org/abs/2311.07314)
- Training data for long-doc text-to-JSON: STAGE synthesizes reports + JSON schemas from spreadsheets with ground truth validated against the sheet; fine-tuning Qwen3-4B raises exact match 31.37% → 74.27% and value accuracy 45.46% → 90.69% on STAGE-Eval (author-reported) — [Ahn et al., STAGE 2026](https://arxiv.org/abs/2606.20072)
- Archive-scale production: gpt-oss-120B selects among 150 report templates in three constrained-decoding steps, then fills them; 2,186,982 radiology reports processed at 1,258 reports/hour on one GPU; residents left 88.7% of 24,638 fields unchanged; multi-region reports were the main error source — [Puttkammer et al. 2026](https://arxiv.org/abs/2610.04541)

### Inferences
- Multi-record extraction should never be "one call returns the full list" for long inputs: use chunking with overlap + per-chunk extraction + deterministic merge/dedup keyed on normalized identifiers + a completeness check (e.g., count anchors found by regex/encoder vs records emitted). Both ExtractBench papers show recall (dropped records) — not misreading — is the dominant long-document failure.
- Wide schemas should be split into sub-schemas (per object type / per section), mirroring SPIRES' recursion and xmemory's staged write path; ExtractBench's 0%-valid result on 369 fields is a direct argument.
- Code-synthesis extraction (Evaporate) is attractive for determinism: once extraction functions are generated and frozen, re-running them is bit-for-bit reproducible and cheap; LLM calls are needed only to (re)generate functions — but accuracy depends on ensemble/weak supervision.
- Deduplication: none of the reviewed papers report duplicate-record rates explicitly; dedup must be designed in (entity keys, canonical IDs as in SPIRES' ontology grounding).

### Gaps
- No source quantified duplicate-record rates or the effect of chunk size/overlap on cardinality errors with controlled experiments (LangExtract states the knobs but gives no numbers).
- No independent benchmark compares LangExtract, OntoGPT/SPIRES, Instructor-style Pydantic extraction and agentic extractors on the same corpus.

## Q3. Constrained / structured decoding (JSON Schema grammars, Outlines, XGrammar, llguidance, JSONSchemaBench, "Let Me Speak Freely" and rebuttals): effect on validity and accuracy

### Takeaway
Grammar-constrained decoding (GCD) guarantees *syntactic/schema* validity with near-zero overhead in modern engines (XGrammar, llguidance), and on extraction/classification it is neutral-to-positive; it does not guarantee *semantic* correctness and engines differ greatly in which JSON Schema features they actually enforce. The "format tax" on reasoning is real for weaker/open models but is mostly caused by the format-requesting prompt and by forcing answers before reasoning, and is largely recovered by reason-then-format (two-step or draft-conditioned) decoding; recent closed models show little tax.

### Cited Findings
**Mechanisms**
- Outlines: reformulates generation as FSM transitions; precomputes an index over the vocabulary for regexes/CFGs; little per-token overhead — [Willard & Louf 2023](https://arxiv.org/abs/2307.09702)
- SGLang: compressed finite-state machines for faster JSON decoding (multiple tokens per step where the grammar is forced) — [Zheng et al., SGLang 2023](https://arxiv.org/abs/2312.07104)
- XGrammar: splits vocabulary into context-independent tokens (prechecked) and context-dependent tokens (checked at runtime with a persistent stack); up to 100× speedup over prior solutions, "near-zero overhead" end-to-end (author-reported) — [Dong et al., XGrammar, MLSys 2025](https://arxiv.org/abs/2411.15100)
- llguidance: Earley parser over a regex-derivative lexer with a token trie; ~50 µs CPU per token mask for a 128k vocabulary; powers OpenAI Structured Outputs (JSON Schema), integrated into vLLM, SGLang, llama.cpp, Chromium; MIT — [guidance-ai/llguidance](https://github.com/guidance-ai/llguidance)
- OpenAI Structured Outputs: vendor eval reports gpt-4o-2024-08-06 with Structured Outputs at 100% on complex JSON-schema following vs <40% for gpt-4-0613; supports only a subset of JSON Schema (vendor-reported) — [OpenAI, Aug 2024](https://openai.com/index/introducing-structured-outputs-in-the-api/)
- DOMINO: constrained decoders that do not align with sub-word tokenization "significantly impair task accuracy"; subword-aligned constraint enforcement fixes this with ~no overhead — [Beurer-Kellner et al., 2024](https://arxiv.org/abs/2403.06988)
- Grammar-aligned decoding: GCD distorts the LM distribution (grammatical but improbable outputs); ASAp sampling provably matches the LM's conditional distribution given the grammar — [Park et al., NeurIPS 2024](https://arxiv.org/abs/2405.21047); SMC with tractable (tensorized automaton) proposals reduces local-masking bias — [Dang et al., ICML 2026](https://arxiv.org/abs/2606.01926)
- GCD for IE specifically: input-dependent grammars (e.g., only allow entity strings present in the input / KB IDs) make grammar-constrained off-the-shelf LMs beat unconstrained LMs and even task-specific fine-tuned models on closed IE and entity disambiguation — [Geng et al., EMNLP 2023](https://arxiv.org/abs/2305.13971)

**Benchmarks of engines (JSONSchemaBench)**
- 10K real-world JSON schemas + official JSON Schema Test Suite; 6 frameworks. Example empirical coverage (fraction of schemas where valid output is produced): GitHub-Hard — Guidance 0.41, Llamacpp 0.39, XGrammar 0.28, Outlines 0.03, OpenAI 0.09 (OpenAI declares support for only 9%, with 100% compliance when supported); JSONSchemaStore — Guidance 0.30, Llamacpp 0.38, XGrammar 0.33, Outlines 0.09, OpenAI 0.06; Gemini omitted on hard sets (<1% support). XGrammar showed under-constraint failures in 38 test-suite categories (allows invalid outputs) vs 1 for Guidance; Outlines had compile errors in 42 categories and some features (minItems/maxItems/enum) take 40 s-10 min to compile. Grammar compile time: Guidance 0.01 s vs Outlines 8.05 s. Downstream accuracy with Llama-3.1-8B: all constrained variants ≥ unconstrained (GSM8K 80.1 → 81.6-83.8; Last Letters 50.7 → 51.2-54.0) — [Geng et al., JSONSchemaBench 2025](https://arxiv.org/abs/2501.10868). Caveat: authors include Guidance/llguidance developers and Guidance ranks first (not fully independent).

**The accuracy debate**
- "Let Me Speak Freely?": format restrictions degrade reasoning; GPT-3.5-Turbo GSM8K 76.6 (text) vs 49.3 (JSON-mode), Last Letter 56.7 vs 25.2 — partly because JSON-mode outputs put the "answer" key before "reason"; NL-to-Format (answer freely, then convert) ≈ NL; but on classification (DDXPlus) JSON helped (Gemini 1.5 Flash 41.6 → 60.3; Claude 3 Haiku 33.8 → 52.0) — [Tam et al. 2024](https://arxiv.org/abs/2408.02442)
- Rebuttal (.txt, makers of Outlines — interested party): original study used different prompts for structured vs unstructured runs, JSON prompts with no schema, and an LLM "parser"; with matched prompts and schemas, structured ≥ unstructured: GSM8K 0.77 vs 0.78, Last Letter 0.73 vs 0.77, Shuffled Objects 0.41 vs 0.44 — [Kurt, "Say What You Mean" (.txt blog)](https://blog.dottxt.ai/say-what-you-mean.html)
- "The Format Tax" (2026): across 6 open-weight + 4 API models, format requirements (JSON/XML/LaTeX/Markdown) substantially degrade reasoning in open-weight models, but "sampling bias accounts for only a fraction"; "format-requesting instructions alone cause most of the accuracy loss"; decoupling reasoning from formatting (free-form then reformat, or extended thinking) recovers most of it; "most recent closed-weight models show little to no format tax" — [Lee, D'Antoni, Berg-Kirkpatrick 2026](https://arxiv.org/abs/2604.03616)
- Draft-Conditioned Constrained Decoding: unconstrained draft first, then constrained decoding conditioned on it; up to +24 pp strict structured accuracy (GSM8K 1B model: 15.2% → 39.0%) — [Reddy et al. 2026](https://arxiv.org/abs/2603.03305); CRANE: augmenting the grammar to allow reasoning before the constrained answer preserves reasoning — [Banerjee et al., ICML 2025](https://arxiv.org/abs/2502.09061)
- Schema keys are an instruction channel: changing only key wording under constrained decoding substantially changes accuracy (positive and negative, model-dependent) — [Le, AACL 2026](https://arxiv.org/abs/2604.14862)
- Small models (0.6B-4B), 14 tasks, Outlines/XGrammar vs native: CD lifts schema validity from 78.6-92.9% to 100%, rescues type-coercion failures, but instruction-semantic failures remain — "schema conformance is necessary but not sufficient" — [Chavan 2026](https://arxiv.org/abs/2609.23742)
- Frontier APIs' structured-output modes can hurt on large real schemas: in ExtractBench, enabling provider structured output lowered valid outputs from 51% to 37% and all providers rejected the resume schema (0/42) — [Ferguson et al. 2026](https://arxiv.org/abs/2602.12247)
- Alternatives to decode-time constraints: post-hoc structuring with a fine-tuned small model (SLOT: Mistral-7B + CD → near-perfect schema accuracy) — [Wang et al. 2025](https://arxiv.org/abs/2505.04016); RL (GRPO) for strict schema adherence in a 1.5B model — [Agarwal et al. 2025](https://arxiv.org/abs/2502.14905); benchmarks of structured-format generation (StructEval: o1-mini averages 75.58) — [Yang et al. 2025](https://arxiv.org/abs/2505.20139)

### Inferences
- For extraction (as opposed to math reasoning), the evidence (JSONSchemaBench downstream table, Let-Me-Speak-Freely classification results, Geng et al. GCD-for-IE) supports constrained decoding as on-by-default; the main risk is putting decision fields before evidence/reasoning fields. Schema field order should be: evidence quote(s) → optional reasoning → value.
- Use input-dependent constraints where possible (enums from the ontology, regexes for IDs/dates, "verbatim" fields restricted to substrings of the input) — this converts some semantic errors into impossibilities.
- Check JSON Schema feature support per engine before relying on it (JSONSchemaBench shows silent under-constraint in XGrammar and limited subsets in OpenAI/Gemini); always re-validate output with a full JSON Schema validator afterwards.
- For very large schemas, schema decomposition beats a single constrained call (ExtractBench).

### Gaps
- No controlled study found that measures constrained decoding's effect specifically on IE F1 (CoNLL/ACE/DocRED) with 2025-2026 frontier models; evidence is from reasoning tasks, small models, or enterprise PDFs.

## Q4. Grounding and attribution: span-level provenance, quote-then-extract, verification, hallucination rates in extraction; confidence calibration and abstention

### Takeaway
LLM extractions are not guaranteed to be in the document. The robust pattern is "extract value + verbatim evidence span → deterministically align the span to character offsets (exact, then fuzzy) → reject/flag unaligned or unsupported records → optionally verify with a cheap NLI/encoder scorer". Reported effects: up to 85% hallucination reduction (SafePassage), 14.6% of positive extractions removed as unsupported in a 920k-note clinical deployment. LLM self-reported confidence is poorly calibrated; encoder span scores rank well but need temperature scaling; formal abstention guarantees (conformal) are only achievable at loose risk targets.

### Cited Findings
- SafePassage: (1) LLM emits entities plus a supporting "context"; (2) a string-based global aligner (character-level Smith-Waterman; reject below 0.6 matched-chars/alignment-length) locates the context in the document; (3) a scorer checks the context entails the extraction. Reduces hallucinations "by up to 85%" on legal IE (AsyLex refugee decisions). Even the best LLM had 5-10% miss rate on exact string match of its copied context; o4-mini ~5% mistranscriptions, Llama 4 Scout 42%. A DeBERTa NLI scorer fine-tuned on synthetic+~500 human labels (≈2 h annotation) reached P 0.928 / R 0.857 / F1 0.891 vs GPT-4.1 grader F1 0.827, at ~1/2000 the cost per prediction — [Barrow et al., SafePassage 2025](https://arxiv.org/abs/2510.00276)
- LangExtract maps each extraction to exact character intervals and leaves `char_interval=None` when alignment fails, enabling filtering of ungrounded records — [google/langextract](https://github.com/google/langextract); NuExtract templates offer a `verbatim-string` type for values that must appear in the input — [NuExtract-2.0-8B](https://huggingface.co/numind/NuExtract-2.0-8B)
- Quote-then-extract (vendor guidance): for long documents (>20k tokens) "extract word-for-word quotes first", allow "I don't know", require a supporting quote per claim and retract claims without one; best-of-N comparison as a hallucination signal; "they don't eliminate them entirely" — [Anthropic docs, Reduce hallucinations](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations)
- Attribute-first-then-generate: select source segments first, then generate conditioned on them, so the selection doubles as fine-grained attribution — [Slobodkin et al., ACL 2024](https://arxiv.org/abs/2403.17104); ContextCite: post-hoc attribution of a generated statement to context spans via ablation-based surrogate model — [Cohen-Wang et al. 2024](https://arxiv.org/abs/2409.00729); Chain-of-Verification: draft → plan verification questions → answer independently → revise; reduces hallucination on list-style questions — [Dhuliawala et al. 2023](https://arxiv.org/abs/2309.11495)
- Clinical deployment validation (919,783 notes, 11 substance categories): rule-based plausibility filtering + semantic grounding removed 14.59% of LLM-positive extractions as unsupported/irrelevant/implausible; judge-LLM vs experts Gwet's AC1 0.80; primary LLM F1 0.80 (relaxed) — [Mahbub et al. 2026](https://arxiv.org/abs/2604.06028)
- Radiology archive structuring flagged unsupported content in 1.0% (radiography) and 1.5% (CT) of reports — [Puttkammer et al. 2026](https://arxiv.org/abs/2610.04541)
- Systematic-review extraction with ChatGPT-4o: 92.4% correct/satisfactory; 5.2% completely false data, much of it hallucinated plausible values when information was absent from the paper — [Jensen et al., PLOS ONE 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC11706374/)
- Medical IE hallucination mitigation via alternate contrastive decoding (separating identify vs classify sub-task models) — [Xu et al., Findings EMNLP 2024](https://arxiv.org/abs/2410.15702); GPT-NER self-verification against labelling NULL inputs as entities — [Wang et al. 2023](https://arxiv.org/abs/2304.10428); RL rewards that explicitly score groundedness and over-generation — [EAGER 2026](https://arxiv.org/abs/2609.29230)
- Calibration: ChatGPT is overconfident in IE predictions ("low calibration") — [Li et al. 2023](https://arxiv.org/abs/2304.11633). GLiNER per-span confidence ranks correctness well (AUROC 0.76-0.86) but is overconfident (ECE 0.24-0.47), halved by temperature scaling; thresholding gives a small honest F1 gain — [Chaganti 2026](https://arxiv.org/abs/2610.00007)
- Abstention with guarantees: heuristic abstention policies violate user risk targets in 7.5-12.5% of settings; conformal risk control certifies structured outputs only when base risk is near target — at α=0.40, certification for 28% NER / 13% QA / 19% classification inputs; under cross-dataset shift static CRC violated the target in 14 of 16 transfers — [Kotte 2026](https://arxiv.org/abs/2606.29054)
- Absence vs silence: in clinical extraction, most cross-prompt disagreement sat on the "not documented" vs "no" distinction; collapsing to binary dissolved most disagreement — [Murin 2026](https://arxiv.org/abs/2606.05970); ChatGPT-4o two-session agreement fell from 94.1% overall to 77.2% when information was not reported — [Jensen et al. 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC11706374/)
- Grounding metrics in benchmarks: ExtractBench (LlamaIndex) scores word- and page-level grounding F1; best word-level F1 only 46.4 and all general VLMs/coding agents scored 0 (they emit no grounding metadata) — [Zhang et al. 2026](https://arxiv.org/abs/2607.29677)

### Inferences
- For deterministic retrieval with traceability, every stored value should carry (doc_id, char_start, char_end, quote, extractor version). Deterministic string alignment (exact → normalized → Smith-Waterman with threshold) is cheap and reproducible; it should be the gate, with LLM or NLI verification as a second stage only for aligned-but-possibly-unsupported values.
- Derived/normalized values (e.g., "Q3 2025" → 2025-07-01..2025-09-30) cannot be verbatim; store both the verbatim evidence span and the normalized value, and verify the normalization deterministically where possible.
- Schemas should model "not mentioned" explicitly (null + reason enum: not_documented / explicitly_negative / ambiguous); the absence-vs-silence axis is the largest source of disagreement and fabrication.
- LLM verbal confidence should not be used as a gate; use alignment success, cross-run/cross-model agreement, and calibrated small-model scores.

### Gaps
- No large, independent study reports base hallucination (ungrounded-value) rates for 2025-2026 frontier models on general extraction; SafePassage is legal-domain only and reports mistranscription rather than overall ungrounded rates.
- No study found compares quote-then-extract vs extract-then-cite head-to-head on IE accuracy.

## Q5. Benchmarks (CoNLL, ACE05, DocRED, Re-DocRED, SciREX, CrossNER, IEPile, ExtractBench, 2025-2026 structured extraction benchmarks): which results are independent?

### Takeaway
Classic IE benchmarks (CoNLL-03, ACE05, DocRED/Re-DocRED, SciREX, CrossNER) measure sentence/document span-level IE with exact-match F1 and have known annotation problems (DocRED false negatives). 2025-2026 benchmarks shift toward schema-guided, document-to-JSON extraction with per-field metrics, record completeness, grounding and cost (two distinct "ExtractBench"es, JSONSchemaBench, StructEval, STAGE-Eval). Truly independent evaluations are a minority: most model papers are author-reported, comparison tables often reuse others' numbers, and the newest enterprise benchmarks are built by extraction vendors.

### Cited Findings
- [2003] CoNLL-2003 shared task: language-independent NER (PER/LOC/ORG/MISC) — [Tjong Kim Sang & De Meulder](https://arxiv.org/abs/cs/0306050)
- [2006] ACE 2005 multilingual training corpus (entities, relations, events; LDC2006T06) — licensed via LDC, not open — [LDC catalog](https://catalog.ldc.upenn.edu/LDC2006T06)
- [2019] DocRED: document-level RE from Wikipedia/Wikidata requiring multi-sentence reasoning — [Yao et al., ACL 2019](https://arxiv.org/abs/1906.06127). Re-DocRED re-annotates 4,053 documents to fix prevalent false negatives; models trained/evaluated on it gain ~13 F1 — i.e., DocRED's gold under-counts true relations — [Tan et al., EMNLP 2022](https://arxiv.org/abs/2205.12696)
- [2020] SciREX: document-level IE over full scientific papers (salient entities, N-ary relations); large gap to human performance — [Jain et al., ACL 2020](https://arxiv.org/abs/2005.00512)
- [2021] CrossNER: 5 domains with specialized entity types; the standard zero-shot NER suite (with MIT Movie/Restaurant) used by GoLLIE/UniNER/GLiNER — [Liu et al., AAAI 2021](https://arxiv.org/abs/2012.04373)
- IE instruction collections used as training and evaluation: IE INSTRUCTIONS (32 datasets) — [InstructUIE](https://arxiv.org/abs/2304.08085); IEPile (33 datasets, 0.32B tokens) — [Gui et al.](https://arxiv.org/abs/2402.14710); UniversalNER's 43-dataset NER benchmark — [Zhou et al.](https://arxiv.org/abs/2308.03279); B2NERD (54 datasets) — [Yang et al.](https://arxiv.org/abs/2406.11192)
- 2025-2026 structured-extraction benchmarks: ExtractBench (Contextual AI; 35 PDFs, 12,867 fields, per-field metrics) — [Ferguson et al.](https://arxiv.org/abs/2602.12247); ExtractBench (LlamaIndex; 370 docs, value F1 + record completeness + grounding + cost) — [Zhang et al.](https://arxiv.org/abs/2607.29677); JSONSchemaBench (10K schemas, engine coverage/efficiency/quality) — [Geng et al.](https://arxiv.org/abs/2501.10868); StructEval (18 formats, 44 task types) — [Yang et al.](https://arxiv.org/abs/2505.20139); StructuredRAG (6 tasks) — [Shorten et al.](https://arxiv.org/abs/2408.11061); STAGE-Eval (851 source-grounded text-to-JSON examples) — [Ahn et al.](https://arxiv.org/abs/2606.20072); RUIE-Bench (robustness to perturbation) — [Zhu et al.](https://arxiv.org/abs/2503.03201)
- Evaluation-method caveats: exact-match scoring underestimates generative RE; human evaluation puts few-shot GPT-3 near supervised SOTA — [Wadhwa et al.](https://arxiv.org/abs/2305.05003); ChatGPT's IE quality differs strongly between Standard-IE (strict) and OpenIE (human-judged) — [Li et al.](https://arxiv.org/abs/2304.11633); Han et al. analyse "evaluation criteria" as a source of the GPT-4 gap — [Han et al.](https://arxiv.org/abs/2305.14450); ExtractBench uses Gemini 2.5 Flash as an LLM judge for array alignment (0.7 threshold) and single runs — [Ferguson et al.](https://arxiv.org/abs/2602.12247); gold provenance (LLM-silver vs human) flips rankings — [Chaganti](https://arxiv.org/abs/2610.00007)
- Independence audit:
  - Independent of the winning system: Ma et al. 2023 ([link](https://arxiv.org/abs/2303.08559)), Han et al. 2023 ([link](https://arxiv.org/abs/2305.14450)), Li et al. 2023 ([link](https://arxiv.org/abs/2304.11633)), Wadhwa et al. 2023 ([link](https://arxiv.org/abs/2305.05003)), Chaganti 2026 ([link](https://arxiv.org/abs/2610.00007)), Chavan 2026 ([link](https://arxiv.org/abs/2609.23742)), The Format Tax ([link](https://arxiv.org/abs/2604.03616)), Atil et al.   - Interested parties: ExtractBench-LlamaIndex ranks LlamaExtract first ([link](https://arxiv.org/abs/2607.29677)); JSONSchemaBench co-authored by Guidance/llguidance developers and Guidance ranks first ([link](https://arxiv.org/abs/2501.10868)); .txt (Outlines) rebuttal of "Let Me Speak Freely" ([link](https://blog.dottxt.ai/say-what-you-mean.html)); OpenAI's 100% structured-output claim ([link](https://openai.com/index/introducing-structured-outputs-in-the-api/)); NuExtract in-house benchmark ([link](https://huggingface.co/numind/NuExtract-2.0-8B)); xmemory ([link](https://arxiv.org/abs/2604.27906)).

### Inferences
- For the toolkit, classic IE benchmarks are useful only for regression-testing entity/relation taggers; the more relevant evaluation is ExtractBench-style: per-field typed metrics (exact for IDs, tolerance for numbers), array alignment with explicit omission vs hallucination counts, record-completeness on long lists, grounding F1, and cost — all run multiple times to measure variance (neither ExtractBench reports repeated runs).
- Benchmark contamination of CoNLL/ACE/DocRED in frontier-model pretraining is a plausible confound for any 2025-2026 frontier result on them (inference, no direct source found).

### Gaps
- I found no independent, multi-run, leaderboard-style comparison of open-source extraction stacks (GLiNER2, NuExtract, LangExtract+open model, OntoGPT) on a common document-to-JSON benchmark with grounding.
- ACE05 licensing limits open replication; I found no 2025-2026 frontier-model ACE05 event-extraction result from an independent party.

## Q6. Determinism: run-to-run variance, temperature 0, self-consistency/majority voting, ensembling — and their cost

### Takeaway
Temperature 0 is not deterministic in practice: batch-size-dependent GPU kernels make outputs depend on server load, producing up to 15% accuracy swings and many distinct outputs. Bitwise determinism is achievable on self-hosted open models with batch-invariant (or TP-invariant / fixed-shape) kernels at roughly 1.6-2× latency (or less with newer scheduling approaches), but not on closed APIs. Separately, extraction outputs are sensitive to prompt, model and schema choices (model choice reassigned the dominant category on ~half of notes). Self-consistency/voting increases stability and accuracy at N× cost but is itself stochastic; the reproducible design is to make extraction a one-time, versioned, materialized write (snapshot) rather than something re-run at query time.

### Cited Findings
- 5 LLMs configured "deterministically", 8 tasks, 10 runs: accuracy varies up to 15% across runs, best-vs-worst possible gap up to 70%; no model gives repeatable accuracy across all tasks, "much less identical output strings"; proposes TARr@N (raw-output agreement) and TARa@N (parsed-answer agreement) — [Atil et al. 2024](https://arxiv.org/abs/2408.04667)
- Root cause is lack of *batch invariance* (kernel results depend on batch size, which depends on concurrent load), not merely "concurrency + floating point". Qwen3-235B, T=0, 1,000 completions → 80 unique outputs (divergence at token 103); with batch-invariant kernels all 1,000 identical. Cost on Qwen3-8B: 26 s default vLLM vs 55 s naive deterministic vs 42 s with improved attention kernel — [He / Thinking Machines Lab, Sept 2025](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/)
- Changing batch size, GPU count or GPU type under bf16 greedy decoding changes outputs; DeepSeek-R1-Distill-Qwen-7B shows up to 9% accuracy variation and 9,000-token length differences; traced to floating-point non-associativity — [Yuan et al. 2025](https://arxiv.org/abs/2506.09501)
- Nondeterminism perturbs token probabilities most in the 0.1-0.9 range, much less near 0 or 1 — [Fu et al., IEEE TC 2026](https://arxiv.org/abs/2601.06118); "background temperature" formalizes the effective randomness at nominal T=0 and pilots it across major providers — [Messina & Scotta, TMLR 2026](https://arxiv.org/abs/2604.22411)
- Engineering fixes: tree-based TP-invariant kernels give bit-wise identical results across tensor-parallel sizes in vLLM — [Zhang et al. 2025](https://arxiv.org/abs/2511.17826); CoRun (isolated prefill + fixed-shape batched decode) achieves determinism without batch-invariant kernels, with 15-324% higher throughput than batch-invariant approaches (which cost >2× latency and up to 74% throughput) — [Zhao et al. 2026](https://arxiv.org/abs/2608.14376)
- Extraction-specific variance: GPT-4 systematic-review extraction "can differ even when the 'temperature' parameter is set to 0" ("probably not fully replicable"); ~80% accuracy — [Schmidt et al., ALTARS 2024](https://arxiv.org/abs/2405.14445). ChatGPT-4o two sessions agree on 94.1% of 484 data points (AC2 0.93) but only 77.2% when the info is not reported — [Jensen et al., PLOS ONE 2025](https://pmc.ncbi.nlm.nih.gov/articles/PMC11706374/)
- Configuration sensitivity (MIMIC-IV discharge summaries, 17 three-way flags + 47-tag category): cross-prompt Cohen's kappa median 0.69 / 0.68 for two model sizes; changing the model reassigns the dominant admission tag on close to half of notes, changing prompt phrasing on ~1 in 8; larger model puts less mass on catch-all categories (44% → 26%) — [Murin 2026](https://arxiv.org/abs/2606.05970)
- Self-consistency: sample multiple reasoning paths and majority-vote; e.g., +17.9% on GSM8K — [Wang et al., ICLR 2023](https://arxiv.org/abs/2203.11171); Universal Self-Consistency uses the LLM to pick the most consistent free-form answer when votes cannot be counted exactly — [Chen et al. 2023](https://arxiv.org/abs/2311.17311). For IE, two-stage voting (first mentions, then types) improves zero-shot NER — [Xie et al., EMNLP 2023](https://arxiv.org/abs/2310.10035); self-consistency improves full-paper sample extraction — [Khalighinejad et al. 2024](https://arxiv.org/abs/2403.00260); self-consistency used for active selection in guideline learning — [Pang et al. 2023](https://arxiv.org/abs/2310.05066)
- Cheap ensembling alternatives: Evaporate-Code+ ensembles many synthesized extraction functions with weak supervision, cutting LLM tokens 110× vs per-document extraction (author-reported) — [Arora et al.](https://arxiv.org/abs/2304.09433); SLM filter + LLM rerank only for hard samples (+2.4 F1 at "acceptable" cost) — [Ma et al.](https://arxiv.org/abs/2303.08559); small fine-tuned NLI verifier ~2,000× cheaper per prediction than an LLM grader — [Barrow et al.](https://arxiv.org/abs/2510.00276)
- Vendor guidance recommends near-zero temperature for extraction models (NuExtract) — [NuExtract-2.0-8B](https://huggingface.co/numind/NuExtract-2.0-8B); "best-of-N" disagreement as a hallucination signal — [Anthropic docs](https://platform.claude.com/docs/en/test-and-evaluate/strengthen-guardrails/reduce-hallucinations)

### Inferences
- Deterministic *retrieval* does not require deterministic *extraction* if extraction is a versioned ETL step: run once, store records with provenance and (model id, weights hash, prompt/schema hash, decoding params, engine version), and serve all queries from that snapshot. Re-extraction creates a new snapshot; diffs between snapshots are auditable.
- If re-extraction must be reproducible bit-for-bit (e.g., incremental rebuilds), self-host pinned open weights with batch-invariant/fixed-shape inference (vLLM deterministic mode, CoRun-style scheduling) and constrained decoding; closed APIs cannot guarantee this (Atil, Messina & Scotta).
- Use agreement as a signal, not as the mechanism: run k=3-5 samples (or 2 different models) only for fields flagged uncertain (alignment failed, enum ambiguity, absence-vs-silence), majority-vote at the *normalized field value* level, and send disagreements to review. Cost scales ~linearly in k, so selective voting is the economical option.
- Model upgrades are a bigger source of drift than sampling noise (Murin: model change ≫ prompt phrasing), so pin model versions per snapshot and re-validate on a fixed labelled sample before switching.

### Gaps
- No source measured TARa@N-style run-to-run agreement for frontier models on a standard IE benchmark (CoNLL/DocRED) or on nested JSON extraction; extraction-specific variance evidence comes from small clinical/systematic-review studies.
- No published cost-accuracy curve for self-consistency (k) specifically on structured extraction was found.

## Q7 (cross-cutting). Given the above, what is the most effective, reproducible way to turn text into typed records for deterministic agent retrieval?

### Takeaway
Evidence points to a layered write-path: schema-first design → cheap deterministic span extractors where they suffice → LLM extraction with constrained decoding, evidence-first fields and decomposed schemas for the rest → deterministic grounding/alignment and validation gates → selective verification/voting → materialized, versioned records with span provenance. No single model or decoding trick delivers accuracy, completeness and reproducibility on its own.

### Cited Findings
- Reads become exact, constrained queries over verified records when interpretation moves to the write path (object → field → value with validation gates) — [Petrov et al. 2026](https://arxiv.org/abs/2604.27906)
- Encoders give zero malformed output and calibrated-able span scores at a fraction of LLM cost — [Chaganti 2026](https://arxiv.org/abs/2610.00007); [GLiNER](https://aclanthology.org/2024.naacl-long.300.pdf); [GLiNER2](https://arxiv.org/abs/2507.18546)
- Constrained decoding guarantees schema validity (78.6-92.9% → 100% in small models) but not semantics — [Chavan 2026](https://arxiv.org/abs/2609.23742); reason/evidence-before-answer avoids the format tax — [The Format Tax](https://arxiv.org/abs/2604.03616); [DCCD](https://arxiv.org/abs/2603.03305); [Tam et al.](https://arxiv.org/abs/2408.02442)
- Wide schemas and long documents break single-call extraction (0% valid at 369 fields; record lists truncated on long docs) — [Ferguson et al.](https://arxiv.org/abs/2602.12247); [Zhang et al.](https://arxiv.org/abs/2607.29677)
- Character-offset grounding and alignment-based rejection — [LangExtract](https://github.com/google/langextract); [SafePassage](https://arxiv.org/abs/2510.00276)
- Code-synthesized extractors are cheap and re-runnable — [Evaporate](https://arxiv.org/abs/2304.09433)
- Determinism requires pinned, batch-invariant self-hosted inference or snapshotting — [Thinking Machines](https://thinkingmachines.ai/blog/defeating-nondeterminism-in-llm-inference/); [Atil et al.](https://arxiv.org/abs/2408.04667)

### Inferences
- Recommended stack (synthesis, not from a single source):
  1. Schema registry (JSON Schema / Pydantic / LinkML) with typed fields, enums bound to ontology IDs, explicit null-reason enums, and per-field scoring metrics (ExtractBench-style).
  2. Tier-1 extractors: GLiNER2/GLiREL or regex/rule extractors for high-volume types (deterministic, span-native).
  3. Tier-2 LLM extraction for nested/business fields: per-chunk, per-sub-schema calls; constrained decoding via XGrammar/llguidance on self-hosted pinned models (or provider structured outputs if the schema subset is supported); field order evidence → value; multiple passes for recall; deterministic merge/dedup on canonical keys.
  4. Grounding gate: exact/fuzzy alignment of evidence quotes to char offsets; reject or quarantine unaligned values; small NLI verifier for support.
  5. Selective redundancy: second model or k-sample voting only on flagged fields; disagreements to human review.
  6. Materialize records with provenance and full version metadata into SQL/graph; queries never call the LLM, so retrieval is deterministic for a snapshot.
- Main open risk: recall on long multi-record documents; it should be monitored with completeness checks rather than assumed.

### Gaps
- No end-to-end study was found that measures the combined effect of this layered design vs single-call frontier extraction on the same corpus, including cost and determinism metrics.
